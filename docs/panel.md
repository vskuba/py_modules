# Скелет панели (`panel_/`)

> Вход, права, люди и токены — одинаковые у всех панелей. Что считать правом и
> где держать учётки, решает проект; скелет задаёт интерфейс и правила.

## 0. Граница: механизм здесь, каталог там

Панели трёх проектов делали одно и то же тремя способами. У двух совпадало почти
файл в файл — `users.py` байт в байт, — и обе умели ровно `is_admin`. У третьего
был полноценный RBAC: права строками, роли в таблице, политика полей. Взяли
**богатый** вариант и развели его надвое.

| | Где | Почему |
|---|---|---|
| проверка прав, правила про людей, точки `/api/users` | слой | у всех одинаковы |
| **какие права бывают** (`workflow:view`, `profile:edit`) | проект | предметное знание, `tool_rules.md` §1 |
| **что входит в роль** | проект | его дело, кому что |
| **где лежат учётки и роли** | проект | у одного столбец, у другого таблица |

⚠⚠ Каталог прав в слой не уезжает **ни при каких условиях**: `workflow:*`,
`agent:*`, `profile:*` — это имена чужих предметных областей, и модуль с ними
перестаёт быть переносимым. Но и обратное неверно: оставить каждому свою
проверку прав значит получить то, что было, — у одного права, у двух других
`is_admin` и больше ничего.

| Файл | Что |
|------|-----|
| `panel_access.py` | **договор доступа**: какие права есть, что входит в роль, политика полей |
| `panel_store.py` | **договор хранения**: где лежат учётки, роли и токены |
| `panel_auth.py` | вход сессией или токеном, зависимости роутов |
| `panel_user.py` | правила заведения, правки и посева первых двух |
| `panel_auth_api.py` | точки `/auth`: вход, выход, «кто я» |
| `panel_user_api.py` | точки `/api/users` |
| `panel_setting_api.py` | точки `/api/setting` + часовой пояс панели |
| `panel_backup_api.py` | точки `/api/backup`: снимок всей базы |
| `panel_seed_api.py` | точки `/api/seed`: выбранные таблицы поверх живой базы |
| `panel_static.py` | раздача `/static` с обязательной перепроверкой у сервера |
| `panel_file.py` | общее у двух последних: каталог в `data/`, проверка имени, список |

## 1. ⚠⚠ Право, а не имя роли

Точка объявляет, **что нужно уметь**, а не **кем быть**:

```python
@router.delete('/{id}')
async def drop(id: int, user = Depends(panel_auth_need('workflow:delete'))):
```

Сравнение `role == 'admin'` отсекает любую другую полноправную роль: учётка QA
получала 403, имея на бумаге все права. Поэтому **полнота роли — это совпадение
её набора прав с каталогом**, а не имя.

`panel_auth_admin_required` остаётся для того, чему права не подобрать: seed,
бэкапы, веб-морда к базе. Это не предметная операция, и заводить под неё
`install:backup` значило бы называть правом вопрос «полноправный ли ты».

## 2. Договор доступа — `PanelAccess`

Три вопроса, на которые проект обязан ответить:

```python
class OurAccess(PanelAccess):
    def permissions_all(self):        return frozenset(Permission)
    def permissions_of(self, role):   return ROLE_PERMISSIONS.get(role, DEFAULT)
    def roles_all(self):              return None   # роли заводятся на ходу

panel_access_use(OurAccess())
```

⚠ **Ответы должны быть дешёвыми.** `permissions_of` зовётся на каждый запрос, а
страница опрашивает ручки пачками. Раскладку ролей держат в памяти и обновляют
по своему поводу. Методы потому синхронные: асинхронная подпись приглашала бы
сходить в базу прямо здесь.

⚠ `roles_all()` отдаёт `None`, если роли заводятся на ходу. Закрытый список —
защита от опечатки (`admn` завела бы учётку, которая не может ничего, а
выглядела бы рабочей); отказываясь от него, проект берёт проверку на себя.

⚠ Незнакомая роль — **не ошибка**, а обычный исход: роль могли завести и не
прописать ей прав. Отвечать на такую надо наименьшим набором.

⚠⚠ Не подключили договор вовсе — скелет работает в режиме «права не заведены»:
полный набор у всех. Это умолчание, а не дыра: панель без каталога ведёт себя
как панель без прав, то есть как до их появления. Дырой был бы обратный выбор —
пустой набор запер бы администратора снаружи собственной установки.

## 3. Договор хранения — `PanelUserStore`

Где лежат учётки, роли и токены — вопрос логики проекта. Интерфейс один.

Умолчание `PanelUserStoreColumn` покрывает простой случай: роль строкой в
`user.role`. Проекту с такой схемой писать не надо ничего.

```sql
user              id, username, password_hash, role, created_at
user_access_token id, user_id, token, note, created_at  -- FK, ON DELETE CASCADE
```

⚠⚠ **`token` обязан вмещать 43 знака** (`VARCHAR(64)` с запасом). Токен выдаёт
`auth_token_new()` — `secrets.token_urlsafe(32)`, то есть 43 знака, а не 36 как
у uuid4. Столбец уже 43-х ломается **молча**: MySQL в нестрогом режиме обрежет,
ручка вернёт полное значение, в базе ляжет обрезанное, и выданный токен не
сработает ни разу. Строки об этом не будет нигде — человек получит 401 и пойдёт
искать ошибку в заголовках. Поймано на живой установке, где столбец остался
`char(36)` с времён uuid4.

⚠ `note` тоже обязателен: без него список действующих ключей выглядит как «три
токена по шесть знаков», и отозвать чужой, не отозвав свой, нельзя.

Проект с ролями в таблице реализует свой:

```python
class RoleTableStore(PanelUserStoreColumn):
    async def get(self, user_id):
        # ... LEFT JOIN role r ON r.id = u.role_id, отдать r.name как `role`
    async def create(self, username, password_hash, role):
        # ... перевести имя роли обратно в role_id

panel_store_use(RoleTableStore())
```

⚠⚠ **Почему договор на методы, а не на подменяемые запросы.** Первым заходом
хранилище подменялось строками SQL. Так выражается **чтение**, но не запись:
проекту с `role_id` нужно не только достать имя роли через `JOIN`, но и
перевести имя обратно в номер при заведении. Половина договора вышла бы
выразимой, половина нет — и второй проект всё равно писал бы своё.

⚠ Каждый метод отдаёт `role` **именем**, а не номером: правами ведает договор
доступа, а он знает роли по именам.

### ⚠⚠ Столбцы проекта — через `extra`, и только по списку

У проекта в таблице людей бывает своё: почта, язык, связи с узлами. Скелет про
них не знает и знать не должен, но и терять их нельзя — иначе страница,
сохранившая человека, стирала бы ему половину карточки.

Поэтому у `create`/`update` есть довод `extra`, а роутер берёт его из тела
запроса **по закрытому списку имён**:

```python
panel_user_api_router(extra_fields=('email', 'node_ids'))
```

Список, а не сквозной проброс: пройди тело насквозь, и страница дописала бы
любой столбец таблицы — включая тот, которым роль задаётся в обход проверки
роли. Что делать с `extra`, решает хранилище: умолчание не делает ничего, потому
что у простой схемы таких столбцов нет.

⚠ `ON DELETE CASCADE` на токенах обязателен: выданный скрипту ключ не должен
пережить человека, которому принадлежал.

## 4. ⚠ Политика полей

Роль может видеть сущность, но не все её поля. Механизм в договоре доступа,
данные — у проекта:

```python
def fields_allowed(self, entity, action, role):
    if self.is_full(role):   return PANEL_ACCESS_ALL_FIELDS
    return POLICY.get(entity, {}).get(action, {}).get(role, ...)
```

⚠ Лишнее поле при записи **отбрасывается молча**, а не отвечает отказом: форма
шлёт себя целиком, и человек, которому поле показали серым, не виноват, что оно
уехало. Отказ на каждое такое поле сделал бы страницу неработающей.

⚠ `PANEL_ACCESS_ALL_FIELDS` — отдельное значение, а не полный список имён:
состав полей меняется вместе со схемой, и «все» обязано значить «все нынешние».

## 5. Подключение

```python
panel_access_use(OurAccess())          # какие права и роли
panel_store_use(OurStore())            # где лежат люди  (можно опустить)

app.include_router(panel_auth_api_router())
app.include_router(panel_user_api_router(view='user:view', manage='user:update'))

await panel_user_seed_admin()
await panel_user_seed_operator()
```

⚠ Роутер отдаётся **функцией**: будь он переменной модуля, два приложения в
одном процессе (а так живут тесты) получили бы один объект с уже навешенными
роутами.

⚠ Имена прав у роутера — доводами, а не зашиты: скелет не вправе придумывать
имена в чужом каталоге. Опустили — точки открыты полноправному, то есть ведут
себя как до появления прав.

## 6. ⚠ Посев: два условия, и они разные

| Кого | Когда заводится | Почему так |
|------|-----------------|------------|
| `ADMIN_USERNAME` | таблица **пуста** | «первый пользователь»: пустая таблица и есть признак свежей установки, а на живой заводить второго админа переменной окружения нельзя |
| `OPERATOR_USERNAME` | нет такого **логина** | вторая роль обычно появляется позже панели, и условие «таблица пуста» не дало бы завести его никогда |

⚠ Ни один не «создать или обновить»: правка пароля в `.env` молча меняла бы его
у живой учётки, а забытый в образце `change-me` возвращался бы после каждого
перезапуска.

## 7. ⚠ Запреты домена закрывают безвыходные состояния

Каждый закрывает состояние, из которого **нет выхода через панель**:

- **роль себе** — понизив себя, администратор теряет доступ к этой самой
  странице, и вернуть роль ему некому;
- **удалить себя** — человек остаётся без учётки в середине сеанса;
- **последний полноправный** — панель осталась бы без хозяина.

⚠⚠ Последний считается **по набору прав**, а не по имени роли, и запросом это не
сделать: полнота — свойство каталога, а не столбца. Поэтому роли перебираются в
памяти; учёток у панели единицы, а зовётся проверка только на правке роли и
удалении.

Третий запрет сегодня недостижим: единственный путь к нему — правка самого себя,
а она отсечена раньше. Оставлен страховкой: правила «про себя» ещё будут
меняться.

## 8. ⚠ Мелочи, которые стоили бы дорого

- **Роль из куки, а не из базы.** Зависимость висит на каждой точке, а страница
  опрашивает их пачками каждые пятнадцать секунд. Плата: смена роли доезжает
  после перелогина, но не позже. У токена роль всегда свежая — он читается на
  каждый запрос.
- **Роль «непонятно что» = пустая.** Не `admin` и не `operator`: у пустой нет
  прав ни по какому каталогу, то есть неизвестный получает наименьшее.
- **Хеш сравнивается всегда**, даже когда логина нет: быстрый отказ выдавал бы,
  какие логины существуют.
- **403, а не 404** на нехватку права: страница есть, человек видит её у
  коллеги. «Нельзя» понятнее, чем «нет такой».
- **Токен виден один раз** — в ответ на выдачу. В списке только хвост в шесть
  знаков: отличить свой ключ от чужого хватает, воспользоваться — нет.
- **`panel_auth_need` требует все перечисленные права**, а не любое из них:
  точка, которой хватает одного из двух, обычно на самом деле две точки.


## 9. ⚠⚠ Бэкап и seed — разные вещи, и путать их дорого

| | Бэкап | Seed |
|---|---|---|
| что | **вся** база | **выбранные** таблицы |
| как ложится | полная **перезапись** | `INSERT IGNORE` поверх живой |
| зачем | авария | перенос заведённого руками |

Поэтому и страницы разные, и роутеры разные, хотя работа с файлами у них одна —
она и вынесена в `panel_file.py`.

⚠ Проверка имени файла живёт **там же, одной копией**, и это не экономия строк:
имя приходит из запроса и уходит в путь файловой системы. Две копии проверки
разойдутся в тот день, когда одну поправят, а пропущенный `../` там — чтение
чужого файла.

⚠ Единственное предметное знание у seed — `runtime_tables`: какие таблицы копит
сама работа установки, а не человек. Приходит доводом: скелет не вправе гадать,
что у проекта рабочее.

⚠ У бэкапа **последний файл удалить нельзя**. «Почистил старьё» и «остался без
единой копии» выглядят одинаково ровно до того дня, когда копия понадобится. У
seed такого запрета нет: это выгрузка, а не единственная копия данных.


## 10. ⚠ Вход: три точки, и копий у них быть не должно

`/auth/login`, `/auth/logout`, `/auth/me` — пятьдесят строк, которые у трёх
панелей были написаны трижды. Третья копия к этому моменту растеряла половину
правил: свой запрос вместо `panel_auth_user_check`, своё правило про первого
пользователя (оно уже есть в хранилище) и **мгновенный отказ на неизвестном
логине** — то есть логины можно перебирать по времени ответа.

⚠⚠ Хеш сравнивается **всегда**, даже когда логина в базе нет. Это не
перестраховка: без него «нет такого пользователя» отвечает заметно быстрее, чем
«неверный пароль», и перебор имён становится возможен без единой попытки
подобрать пароль.

⚠ Имя `/auth` закреплено: на него смотрит проба живости сессии в обвязке сюиты
(`tests_panel.md`) и клиент панели для разовых проверок.

⚠ Проекту, который пишет вход в свою ленту событий, довод `on_login` — скелет
про ленты не знает.


## 11. ⚠ Статика: раздача общая, файлы — проекта

`panel_static_files(path)` вместо своего подкласса `StaticFiles`. Он был написан
в трёх проектах трижды, под тремя именами, и ставил один и тот же заголовок.

⚠⚠ `Cache-Control: no-cache` обязателен. Starlette отдаёт `ETag` и
`Last-Modified`, но **не** `Cache-Control`, а без него браузер кэширует
эвристически — по возрасту файла. Страница грузит новый HTML со старым
ES-модулем и падает «не экспортирует timeFull», хотя на сервере экспорт есть.
Модули браузер вдобавок держит в памяти вкладки: обычное обновление не помогает.

`no-cache` — «перепроверить перед использованием», а не «не кэшировать»: почти
всегда приходит 304 без тела.

⚠⚠ **Сами файлы CSS и JS в `py_modules` не уезжают** — он submodule под скрипты
Python, разметки в нём нет ни одного файла. Общая статика живёт в своём
репозитории (`dashboard`), который проект подключает рядом:

```
<проект>/
  py_modules/   ← скрипты Python
  dashboard/    ← статика, шаблоны, каркас
```

Здесь — только обвязка: `panel_static_files(own, shared='dashboard')` ищет файл
**сперва у проекта, потом в общем**.

⚠⚠ Порядок каталогов — договор: свой первым. Это единственный способ отойти от
общего вида, не ломая остальных. Живой пример — `common.css`: он совпадает у двух
панелей и лежит в общем, а у третьей свой, и она видит свой.

⚠ Поиск по двум каталогам, а не второй путь `/static/shared`: второй путь
означал бы правку каждой страницы, подключающей эти файлы, — `notification.js`
зовут 35 страниц в одном только проекте.

⚠ Что переезжает в `dashboard`: файл, который **уже совпадает** по контрольной
сумме у двух проектов и дальше должен меняться у обоих сразу. Сейчас это 347
строк из ~106 000 всего фронта — правила и замер в его `README.md`.

### ⚠⚠ Метка версии считается по тем же каталогам

`panel_static_url('js/x.js', own, shared)` даёт `/static/js/x.js?v=1756800000` —
время правки файла. Без метки `no-cache` не спасает: ES-модуль, **уже
загруженный во вкладку**, не перезапрашивается вовсе, страница берёт его из
памяти, и обычное обновление не помогает. Так и было — новый HTML со старым
модулем и «не экспортирует timeFull» при живом экспорте.

Порядок каталогов здесь обязан совпадать с порядком у раздачи. Разойдись они —
метка считалась бы по одному файлу, а отдавался бы другой; у общего файла метки
не было бы вовсе, и модуль из `dashboard` застревал бы в кэше вкладки навсегда.
Поймано сюитой сразу после переноса статики в submodule, а не на проде.
