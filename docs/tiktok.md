# tiktok_ — TikTok без входа

Три вещи, которые TikTok отдаёт анониму, и больше ничего: жива ли ручка,
что в карточке профиля, кого находит поиск по имени/городу.

## 1. Каналы (замерено живьём, 2026-10)

* **oembed** (`/oembed?url=…/@ручка`) — работает с хоста без браузера: `200`
  с `author_name` — профиль жив, `400` — ручки нет; пачка гипотез проверяется
  за секунды, это `tiktok_exists`;
* **страница профиля** — только через браузер-контейнер; с адресов, которые
  TikTok знает, прямой `/@ручка` ловит слайдер-капчу — переживает её тот,
  кто пришёл из `search/user?q=`, поэтому `tiktok_profile` при пустом
  прямом заходе повторяет его через поиск (`_search_hit`);
* **поиск пользователей** (`/search/user?q=`) — дорисовывается на глазу,
  ждать надо признаком (`Followers`), а не паузой; карточки отдают ссылки
  **без href** (клик вешается на обработчик) — читают текст страницы, где
  строка кандидата выглядит как `![Avatar for ручка]`, имя, ручка, счётчик.

Счётчики страница пишет слитно (`148Following`) — шаблоны `\s*`, не `\s+`.
Выдача поиска шумная и короткая (6–12 кандидатов, без прокрутки): близко
сидящие по буквам имена всплывают выше точного совпадения — это список
кандидатов, а не вердикт.

## 2. API (транспорт — `browser_http`, адрес контейнера из `BROWSER_URL`)

| Функция | Что делает |
|---------|-----------|
| `tiktok_exists(handles)` | `{ручка: True/False}` через oembed, без браузера |
| `tiktok_search(query, proxy, browser)` | кандидаты `[{handle, name, followers, likes}]` |
| `tiktok_profile(handle, proxy, browser)` | карточка `{name, bio, followers, following, videos}`; `videos=0` — «has not published» |

`proxy` — когда адрес хоста уже спалится; `browser` — адрес контейнера, когда
`.env` не наш (с хоста это проброшенный порт, а не докерное имя).

## 3. CLI

```bash
python -m tiktok_.tiktok_ exists a quad77 handle_x
python -m tiktok_.tiktok_ search "Михайло Черновцы" --browser http://127.0.0.1:8014
python -m tiktok_.tiktok_ profile webtechnics24
```

## 4. Грабли

* `search/user` по точной ручке может её **не показать** (ранжирование), а
  прямой goto — показать; молчаливый `found: False` после «ручка жива по
  oembed» значит капчу, а не смерть профиля — смотреть `exists`;
* капча живёт на адресе: смена прокси (`proxy` у функций) снимает её чаще,
  чем повторный заход с тем же адресом;
* `videos` — не Likes: на профиле без роликов пишется `0Likes` и
  «has not published any videos»; шаблон по `videos` сработал бы на
  заголовке таба, поэтому ноль ищется по тексту публикации.
