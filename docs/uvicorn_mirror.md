# Копия страницы панели как полноценный исток: тело — своё, всё прочее — прокси

> `uvicorn_mirror('/admin/photo/girls')` — contextmanager: снимает страницу свежей,
> отдаёт её по её же пути со своего эфемерного порта, а `/static/` и `/api/`
> проксирует на панель вошедшим клиентом. URL копии суют `web_probe`/`web_shot`/
> `web_drive` как обычную страницу. Инструмент — `py_modules/uvicorn_/uvicorn_mirror.py`,
> CLI: `python -m uvicorn_.uvicorn_mirror СТРАНИЦА [--probe 'JS с return']`.

## 1. Зачем не `capture` + руки

`uvicorn_page_capture` переписывает корневые ссылки на адрес панели и кладёт
HTML в temp: годится мерить геометрию одного куска, но страница на такой копии
живёт неполно — её собственные `fetch` уезжают в чужой исток и глохнут без куки.
Здесь наоборот: тело отдаётся по **своему** пути, копией правит сам прокси —
`{{ base }}` и относительные ссылки внутри копии продолжают указывать туда же,
куда указывали, и руками не нужно ни symlink'ов `static`, ни sed-ов pathname.

## ⚠⚠ Кадр страницы за входом — одной командой

```bash
python -m uvicorn_.uvicorn_mirror /admin/orders --shot /tmp/кадр.png \
    --js 'document.querySelector("[data-tab=\"work\"]").click();'
```

Иначе кадр не снять: `web_shot` по адресу панели получит login-стену, а
скрипт на питоне прячет саму работу — по его команде не видно, снимали кадр
или нет. Это важно и человеку, и заставе вёрстки
(`claude_gate_design_review_live`), которая держит ход, пока кадра не видит.

⚠ `--js` обязателен для страниц с вкладками: вкладка берётся из
`localStorage`, а у свежего Chrome он пуст — кадр придёт с умолчательной, а не
с той, которую правили. Поймано живьём: правил «Заказы», снимал «Настройки».

⚠ Ответ `--js` печатается рядом с путём кадра: его `return` — это числа из
DOM, ради которых зонд и писали. Без этого кадр приходится снимать дважды:
один раз ради картинки, другой ради чисел.

⚠ Ошибки консоли печатаются там же. Кадр показывает, что человек
увидел; консоль — что при этом сломалось молча. Половина поломок страницы не
даёт ни того, ни другого по отдельности.

## 2. Порядок

Снимок тела и кука входа — одним заходом (`uvicorn_panel_client`); сервер —
`ThreadingTCPServer` на эфемерном порте в daemon-потоке; выход из контекстного
менеджера гасит его и закрывает клиента. Тело живёт в памяти и снимается
свежим при каждом входе: копия из /tmp, пережившая правку шаблона, врёт незаметно.

## Грабли

- **панель отвечает своей страницей только вошедшему**: запрос без куки увидел
  бы login-стену — поэтому прокси несёт куку панели, а не изобретает вход.
- **проксирует все методы**: страница не только читает, загрузка материалов
  POST-ом; страница без POST врёт про половину кнопок.
