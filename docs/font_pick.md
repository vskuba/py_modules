# font_pick — шрифт, которым можно написать вот этот текст

Подписать картинку нечем: Pillow рисует только тем шрифтом, который ему дали, а
встроенный (`ImageFont.load_default`) знает латиницу и больше ничего. Русская
подпись выходит рядом пустых прямоугольников — и заметно это не в коде, не в
логе и не в тесте, а на готовом кадре, когда он уже уехал человеку.

```python
from font_.font_pick import font_pick, font_covers

font = font_pick(28, 'Шаг 7')
text = 'Шаг 7' if font_covers(font, 'Шаг 7') else 'Step 7'
draw.text((x, y), text, font=font, fill='white', anchor='mm')
```

Два вопроса — две функции: `font_pick` отвечает «чем рисовать», `font_covers` —
«выйдет ли читаемо». Второй нужен потому, что первый **всегда** возвращает
шрифт: отказ рисовать кадр хуже подписи латиницей.

## ⚠⚠ Покрытие проверяется растром, а не таблицей cmap

Соседний `font_coverage` отвечает на тот же вопрос точнее, но ему нужен путь к
файлу и `fontTools` — а у встроенного шрифта Pillow файла нет вовсе. Здесь
сравнивается отрисовка: символ, которого в шрифте нет, рисуется тем же
«.notdef», что и заведомо отсутствующий знак из приватной области (U+E000).

Приём работает для любого шрифта и не тянет зависимостей сверх Pillow. Замер на
DejaVu: маска «Ш» — 600 байт, «а» — 255, образец «.notdef» — 425, совпадений
нет. У встроенного «Ш» и «а» совпадают с образцом байт в байт, «7» — нет.

⚠ `bytes(font.getmask(ch))`, а не `.tobytes()`: `getmask` отдаёт `ImagingCore`,
и такого метода у него нет — зато есть буферный протокол. Ошибка тихая, её
проглатывает `except` и отвечает «не покрывает» на **любом** шрифте: подпись
молча исчезает со всех кадров.

## ⚠ Список путей, а не `fc-list`

`fontconfig` есть не везде: в `python:*-slim`, на котором стоит половина
контейнеров, нет ни его, ни шрифтов вообще. Вызов внешней команды дал бы отказ
там, где нужен ответ «ничего нет», — и стоил бы процесса на каждую подпись.

Порядок `FONT_PICK_PATHS` — порядок предпочтения: DejaVu первым, у него самое
широкое покрытие из тех, что ставят пакетами. Не нашлось ни одного известного —
обходятся системные каталоги, но не больше `FONT_PICK_SCAN_MAX` файлов: на
машине с офисным пакетом шрифтов тысячи, и перебор всех ради трёх слов это
секунды на каждый кадр.

Замер: первый вызов 100 мс (чтение файла), следующие десять — 2 мс. Кэш не
нужен.

## Шрифта нет в образе — и это обычный случай

`python:*-slim` приезжает без единого шрифта. Проекту, который подписывает
картинки, нужна строка в dockerfile:

```dockerfile
RUN apt-get update && apt-get install -y --no-install-recommends \
    fonts-dejavu-core \
    && rm -rf /var/lib/apt/lists/*
```

Полтора мегабайта. Без неё `font_pick` честно вернёт встроенный шрифт, а
`font_covers` — `False`, и зовущий сам решит: писать латиницей или не писать
вовсе.

## Грабли

1. **Рисовать, не спросив `font_covers`** — пустые прямоугольники вместо
   подписи, видно только на готовой картинке
2. **`.tobytes()` у маски** — `AttributeError` внутри `try`, и подпись молча
   пропадает везде
3. **Надежда на `fc-list`** — в slim-образе его нет
4. **Обход всех шрифтов системы** — секунды на кадр там, где нужны
   миллисекунды
