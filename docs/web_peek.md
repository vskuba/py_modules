# Сырой ответ живой страницы без браузера: статус, тело, маркеры

> Когда нужен факт «что сервер реально прислал», а не что нарисовал Chrome:
> доехал ли шаблон, какой JSON, под каким заголовком кука, есть ли в странице
> её кусок. `web_peek(url)` — один запрос без браузера: статус, заголовки, тело,
> разобранный JSON; `web_peek_markers(url, [...])` — тот же grep по ответу, с
> номерами строк. Chrome-зонды (`web_probe`) для этого тяжеловаты. Инструмент —
> `py_modules/web_/web_peek.py`, CLI: `python -m web_.web_peek URL --markers a,b`.

## 1. Граница с семейством `web_`

Здесь **нет браузера вообще**: сырой HTTP-ответ, каким его увидел бы `curl -i`.
Геометрию и состояние отрисованной страницы числами считают `web_probe` и
компания (см. `web_shot.md`) — там Chrome поднимается, рендерит, гаснет.
Страница, живущая дольше запроса (вход по форме, наблюдатель DOM, сценарий по
шагам) — `browser_`. Между ними — этот модуль: проверить, что сервер ответил,
до того как спорить, как это нарисовалось.

## 2. Тело как есть и разобранный JSON тоже

Ответ отдаётся и текстом, и объектом (если это JSON): двери панелей отвечают
JSON'ом, проверять поле поля дешевле, чем искать его подстрокой. Маркеры
ищутся построчно и называют номер строки — «кусок шаблона виден на такой-то
строке», тем же языком, каким человек сделал бы `grep -n`.

## Грабли

- **без куки страница отвечает то, что видит неавторизованный**: маркеры
  админки над закрытой дверью дадут пустой поиск; для авторизованного ответа
  есть `uvicorn_panel_client` (см. `uvicorn_panel.md`), а не этот модуль.
- **`json` — это `None`, когда тело не JSON**, а не ошибка: текст под этим же
  ключом `'text'` живёт целиком, решение о разборе — не здесь.
