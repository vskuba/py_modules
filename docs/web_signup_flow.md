# Чужая площадка: стена, регистрация, подтверждение, вход — поток и грабли

> Целый путь до чужого комментария/аккаунта, разобранный по шагам: разведка
> страницы → вердикт о стене → форма регистрации → письмо-подтверждение → вход
> → проверка публикации → реестр. Инструменты: `web_signup.py`, `web_wall.py`,
> `web_ledger.py` (новый), `web_login.py`, `mail_box.py`, `mail_wait.py`
> (новый), `web_peek.py`, `web_shot.py`. Документ про **порядок и отказы**,
> контракты функций — в докстрингах.

## 1. Карта: что откуда зовётся

| Шаг | Чем | Вердикт/выход |
|-----|-----|---------------|
| Разведка адреса | `web_wall_probe`, `web_signup_form` | пускает / стена / форма |
| Стена | `web_wall_scan` (классы и действия — §3) | `human` / `wait` / `change_exit` |
| Регистрация | `web_signup_try` | `done`/`mail`/`wall`/`duplicate`/`denied`/`limit`/`fields`/`busy` |
| Письмо | `mail_box_new`, `mail_wait_letter`, `mail_wait_follow` | ссылка проведена / `button` / стена |
| Вход | `web_login_try`, `web_login_sweep` | `success` / `miss` / `lock` |
| Проверка публикации | `web_peek_markers` (без куки), `web_shot` (кадр) | строка видна анониму / нет |
| Память | `web_ledger_put` / `web_ledger_get` | лицо ключа в jsonl |
| Темп пачки | `function_pace_run` | чекпоинт + ожидание 429 |

## 2. Поток целиком

```
web_wall_probe(страница)          ← пускают? иначе §3 и стоп
web_signup_form(регистрация)      ← поля, csrf, honeypot; форма вообще есть?
mail_box_new()                   ← ящик под регистрацию
web_signup_try(url, person, ledger=реестр)
   'fields'    → не хватает данных личности — дополнить person, не долбить
   'duplicate' → аккаунт уже есть — дальше по §5, не заводить второй
   'busy'      → домен в реестре — один аккаунт на площадку (§4)
   'wall'      → §3, стоп до человека
   'mail'      → mail_wait_letter → mail_wait_follow (одна попытка!)
   'done'      → к проверке
web_login_try(...)                ← сессия; 'lock' — сменить выход, не пароль
web_peek_markers(публичная страница, маркеры) ← опубликовал ≠ создал (§6)
web_ledger_put(реестр, домен, {...})          ← лицо аккаунта/публикации
```

## 3. Стена: класс, действие, что делать

| `wall` | `action` | что это и что делать |
|--------|----------|----------------------|
| `captcha` | `human` | recaptcha/hCaptcha/Turnstile — автоматизма нет, нужен человек; солверы не в правилах проекта |
| `challenge` | `human` | JS-челлендж Cloudflare — голое HTTP не пройдёт, решение за живой средой |
| `phone` | `human` | верификация номером — SIM не наш ресурс |
| `identity` | `human` | паспорт/РНОКПП/Diia — для аккаунта это **финальная** стена, новый аноним её не обойдёт |
| `blocked` | `human` | бан аккаунта/адреса — разбираться руками, новые попытки только хуже |
| `limit` | `wait` | 429/Retry-After — окно пережидает `function_pace_run`, не повтор назло |
| `lock` | `change_exit` | замок антибрутфорса: пара НЕ проверена, нужен другой IP, а не другой пароль |

Никогда не путать: `lock` это про выход, `wall` это про правила площадки,
`denied` (см. `web_signup`/`web_login`) это про пару/данные.

## 4. Одна площадка — один аккаунт

Анонимные аккаунты с одного отпечатка (IP, canvas, аналитика страницы) палит
вся сеть аккаунтов разом — площадки сравнивают именно это. Поэтому:

* `web_signup_try(..., ledger=...)` **до** попытки читает реестр и возвращает
  `busy`, если у домена уже стоит строка `kind='account'`;
* после успеха (`done`/`mail`) зующий пишет лицо:
  `web_ledger_put(реестр, 'площадка.ком', {'kind':'account','login':...,'box':...})`;
* `force=True` существует для осознанного второго аккаунта (другой человек за
  той же площадкой) — не для «первый как будто не прижился».

## 5. Письмо и магическая ссылка

* Ссылка подтверждения **одноразовая**: один `mail_wait_follow`, повтор
  означает «ссылка не найдена», хотя впервые всё прошло. Второй заход — через
  «отправить письмо ещё раз» на площадке, не повторным GET.
* Сканеры почты кликают ссылки сами, до нас: письмо в ящике может прийти уже
  сожжённым. Признак — отказ на первом же ходу; лечится перевыпуском.
* «Verify in original tab»: часть площадок по ссылке лишь показывает кнопку —
  вердикт `button` честный, ссылкой подтверждение не взять, нужен клик.
* `links[]` из `mail_box_letters` бывают пусты (introText не всё тело) — за
  полным телом `mail_wait_letter` ходит в сырую запись письма сам.

## 6. Проверка публикации: «опубликовал ≠ создал»

Ответ 201/PENDING значит только «принято». Факт — это строка, видимая
**анониму**: `web_peek_markers(публичная_страница, маркеры)` без куки + кадр
`web_shot` как доказательство; статус модерации — сторожем позже. Каждая
публикация — своей строкой в `web_ledger` (ключ `площадка#дело`), иначе
следующий круг не отличит «уже висит» от «надо пробовать».

## 7. Выход и темп

* Весь круг — **одним клиентом на одном выходе**: GET формы и POST, ссылка
  письма — тот же proxy; csrf-пре-сессии и токены привязывают к IP.
  `http_pool_client(proxy=...)` — общий транспорт; такой клиент не закрывать
  руками после `async with` уже сделано.
* Пачка постов — через `function_pace_run`: окно и 429 пережидает по
  Retry-After; руками долбить после лимита нельзя — окно только удлиняется.

## Грабли

1. **CSRF из чужого похода.** Токен формы живёт в сессии на IP: GET формы и
   POST разными выходами — отказ с валидным токеном. Весь круг — один
   `http_pool_client(proxy=...)`.
2. **Капча внутри 200 OK.** Статус не говорит ничего — вердикт только по
   телу (`web_wall_scan`), и наоборот: страница-глушка лимита полна слов про
   капчу, поэтому 429/Retry-After разбираются **до** содержимого.
3. **Cloudflare без challenge-страницы.** Бывает пустой ответ с заголовком
   `cf-mitigated: challenge` — `web_wall_scan` смотрит и заголовки.
4. **`type="tel"` — ещё не стена.** В форме доставки живого магазина телефон
   обычное поле; телефоном вердикт становится только в паре со словом
   подтверждения рядом.
5. **Honeypot.** Скрытое поле `website/url/company` — ловушка: заполненный
  honeypot помечает бота без отказа на экране; `web_signup` их не трогает,
   свой разбор форм обязан тоже.
6. **Дубликат — не отказ и не успех.** «Такой email уже есть» после таймаута
   прошлой попытки означает, что та попытка **увенчалась**; идти надо во вход,
   а не заводить второй аккаунт.
7. **Челлендж, который не виден в curl.** Капча/челлендж, вставляемые JS после
   загрузки, голому GET не покажутся вовсе; для JS-рендеренных площадок в
   `web_wall_scan` подается outerHTML из браузера.
8. **Возраст и репутация аккаунта.** Площадки скрывают пороги (аккаунту
   N дней, K правок до публикации); вердикт «пустой пост» при 200 — это
   модерация/порог, а не стена: см. §6, не долбить формой.
9. **Одноразовость ссылки письма.** Повторный GET = отказ; перевыпуск —
   просьбой на площадке. Сканер почты мог сжечь ссылку до нас (§5).
10. **Верификация личности — финальная.** Стена `identity` для заведённого
    аккаунта не обходится вторым аккаунтом: палит по отпечатку, уводит в
    `blocked` всю площадку (§4).
