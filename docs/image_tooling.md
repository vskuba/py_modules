# Тон картинок: чем мерить яркость фона и чем ровнять пачку по эталону

> Яркость подложки картинок мерится модой цвета в окне (`image_measure`) и
> подгоняется кусочно-линейными уровнями к эталону (`image_match`).
> Инструмент — `py_modules/image_` (ядро, Pillow), CLI: `python -m image_.image_`.
> Всё про измеренные числа и грабли замера; правки пикселей ради пикселей тут нет.

## 1. Замер: фон — это мода, а не среднее

`image_measure(path, box)` возвращает моду цвета (самую частную краску),
её яркость Rec.601 и среднюю по окну. Порядок чисел такой, потому что:

- **Среднее по кадру врёт.** Белые карточки и тёмный текст тянут среднее в
  стороны от подложки; на пачке страниц со скруглёнными карточками разница
  среднего больше, чем сам сдвиг фона.
- **Мода ищет подложку честно:** её в кадре больше всего. Но окно замера
  долями кадра (`box=(x0, y0, x1, y1)`) обязана лежать на чистом фоне:
  мода, снятая по всему кадру страницы с заголовком, иногда собирает цвет
  текста-тени; полоска у верхнего края правой половины экрана
  (`(0.55, 0.015, 0.95, 0.06)`) заведомо без букв.

Две грабли из живого прогона, обе молчаливые:

1. **Моду искать по всему диапазону 0–255.** Ограничение «ищем светлую
   подложку, floor 128» пропустило фон с настоящей модой 108: тёмный кадр
   съехался к 186 вместо 212, потому что LUT строился от выдуманной точки.
2. **Снимки сравнивать только внутри одного устройства и версии Android:**
   панели разные, одна и та же страница на телефоне и эмуляторе лежит на
   кадре разной высоты (`mobile_emulator.md`, §3).

`image_measure` дополнительно возвращает `spread` — размах p95−p5 яркости в
окне: на чистом фоне он единицы, большой размах означает, что окно захватило
посторонний объект. С `top=N` (флаг `--top`) приходит список из N самых
частых красок с числами — по нему видно, что в окне второй цветовой кластер,
которого мода не показывает.

## 2. Правка: уровни с якорями, а не «прибавить яркости»

`image_match(path, target)` строит кусочно-линейную кривую с тремя якорями:
`0 → 0`, `фон → цель`, `255 → 255`. Чёрный закреплён — текст не сливается с
фоном и контраст «тёмное по светлому» сохраняется; белый закреплён — света
не клиппуются. Это единственная правка, которая делает картинку «такой же
яркой», не делая её другой по цвету; `brightness`/`gamma` сдвигают всё,
включая текст.

Грабли:

1. **`Image.point` на RGB требует ровно 768 записей** — 256, повторённые
   трижды; на 256 Pillow бросает `wrong number of lut entries`.
2. **JPEG по умолчанию пишется с качеством 75** — цельноэкранная графика
   вокруг текста покрывается муаром. В `image_match` стоит `IMAGE_JPEG_QUALITY = 95`.
3. **Прозрачность сохраняется, но не всякая.** Уровни накладываются только на
   RGB-каналы, альфа RGBA-файла уходит в результат нетронутой (у проверенного
   прогона альфа совпадает побайтно). Но у JPEG альфы нет физически: сохранение
   в `.jpg` её выбрасывает — это ограничение формата, а не баг инструмента;
   индексируемые картинки с прозрачностью (`P` + `tRNS`) сплющиваются в RGB.

## 3. Идемпотентность: править всегда от оригинала

Профиль уровней, применённый второй раз, складывается с первым: «ещё чуть
ярче» превращается в выбитую подложку. `image_match(..., backup='каталог')`
запоминает первый встреченный файл нетронутым и правит всегда от него:
повторный прогон повторяет первый, а не накручивает. Прогон по уже
исправленным файлам без `backup` — верный способ всё испортить; на это
указывает и поле `changed: False` (уже в допуске ±1).

## 4. Аудит: репрезентативно ли окно замера

`image_audit(path)` проверяет фон кадра до того, как по нему что-то подгоняют:
девять зон сетки 3×3, четыре узкие полоски по кромкам (2% кадра, с отступом,
чтобы не захватить скруглённые углы) и вердикт — группы яркости по всем
областям (кластеры с разницей до `IMAGE_AUDIT_FLAG`). Кластеров больше одного —
предупреждение: фон не единый, и окно замера надо брать внутри той области,
под которую подгоняешь, а не «сверху у края».

Классический промах, который это ловит: фон страницы ярче фона карточки,
замер «у верхнего края» возвращает яркость страницы, и карточка подгоняется
под чужой тон — на экране появляется светлое пятно с видимым краем.
Медиана по зонам тут наврёт: в кадре с двумя фонами она примет один из них
и будет выглядеть правдоподобно, поэтому вердикт — именно группировка.

Тонкие полоски по кромкам — не для красоты: светлая полоса в 4% по верху
картинки в зону-треть не попадает вовсе, её замечает только кромка.

## 5. Шов: видно ли заплатку краем на живом экране

`image_seam(path, pos)` смотрит профиль яркости через предполагаемую границу:
медиана яркости прямоугольных срезов по пикселю, `span` клеток с каждой
стороны. Вердикт решает ступенька яркости вблизи самой границы
(±`IMAGE_SEAM_WINDOW`), разница медиан половинок — `delta`. Ступеньку ищут
только у границы, потому что буквы на заплатке и вокруг неё тоже делают
большие ступени, но швом не являются; они остаются в `profile_max` и
`profile` для отладки.

Полосу (`at`) выбирают там, где нет глифов, и проверку делают несколько раз
на разных `at` — настоящая ступень не уходит, куда её ни перенеси, а текстовая
замерает на месте. Координаты берут из того же снимка экрана; если граница —
край DOM-элемента, экранные прямоугольники даёт `adb_cdp_element_rect`
(`mobile_control.md`, §8).

## CLI

```bash
python -m image_.image_ measure page.png --box 0.55,0.015,0.95,0.06
python -m image_.image_ measure page.png --top 5
python -m image_.image_ audit card.png
python -m image_.image_ seam shot.png --pos 362 --at 690
python -m image_.image_ seam shot.png --pos 655 --at 232 --axis y
python -m image_.image_ match a.png b.jpg --target ref.jpg --backup orig/ --box ...
```

`--target` — файл эталона (берётся яркость его фона) или число 0–255;
`--out` — каталог, иначе поверх; вывод построчный: `было → стало (цель,
записано|уже в допуске) → файл`.
