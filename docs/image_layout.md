# Геометрия кадра: где фон, где граница контента, где точки, вырез скруглённого прямоугольника

> Фон «сквозь» контент достраивается по боковым полоскам (`image_layout_bgfield`),
> граница контентного блока ищется по самому крутому перепаду от этого фона
> (`image_layout_edge`), строка точек-индикаторов — по максимуму отклонения
> колонки (`image_layout_dots`), стекло карточки вырезается SDF-альфой в RGBA
> (`image_layout_alpha`, `image_layout_cutout`).
> Инструмент — `py_modules/image_` (модуль `image_layout`), CLI:
> `python -m image_.image_layout`. Про тон и швы — соседний `image_tooling.md`.

## 1. Поле фона: что было бы за картинкой, если бы картинки не было

`image_layout_bgfield(src)` возвращает float32-массив той же формы, что кадр:
«какого цвета здесь был бы фон». Строится из того, что контент не закрыл:
медианы боковых полосок (по 4% ширины у краёв) интерполируются горизонтально,
затем поле притягивается к медианам верхней и нижней зон (полоса под
статус-баром, полоса над панелью вкладок) — без этой коррекции горизонтальная
интерполяция расходится с реальным фоном у краёв кадра.

Зачем: экран приложения наполовину закрыт карточкой, а тон подложки CSS
обязан совпадать с картинкой (`image_tooling.md`, тональный контракт) —
замерять его приходится там, где его не видно. На карусели из десяти кадров
поле + маска карточки дают дельту, приводящую фоны всех кадров к фону
эталонного, не трогая стекло.

- **Окна зон — всегда конкретные пиксели кадра, не доли «на глаз».** Умолчания
  в константах — просто типичный мобильный кадр; перед доверием проверьте
  точками: CLI печатает поле в произвольных `--xy`, сверяется с чистыми
  местами кадра (там |кадр − поле| обязан быть единицы).

## 2. Граница контента: максимум градиента, не порог

`image_layout_edge(src, band, search)` по отклику |кадр − поле| отдаёт
`rise_at`/`fall_at` — строки (или колонки), где контент начинается и
кончается. Граница — строка **нового уровня**: отклик прыгнул между i и i+1,
значит 325, а не 324.

- **Порог врёт в большую сторону.** Обход «первая строка, где отклик > N»
  соскальзывает на яркую мелочь ниже границы: у стекла карточки настоящий
  край 1616, а пороговый обход уехал в 1713 — на строку светлых точек под
  карточкой. Крутизна перепада остаётся на контенте.
- **Сглаживание сдвигает границу на полокна.** Скользящее среднее профиля
  перед дифференцированием утащило край стекла с 325 на 309; по умолчанию
  сглаживание выключено, шум давит медиана поперёк полосы `band`.
- **`band` берётся над безглифной зоной.** Медиана поперёк полосы не спасает от
  строк текста, идущих через всю полосу; на кадре всегда есть вертикальная
  щель между карточкой и краем — полосуют ею (в примерах `(700, 940)`).
- **`search` обязателен, когда переходов несколько.** Фото внутри карточки
  даёт перепад и 34 ступени — круче границы стекла (16–17); глобальный argmax
  находит фотографию. Ищут окно вокруг ожидаемой границы: `search=(200, 450)`
  для верха, `(1450, 1750)` для низа — на трёх разных слайдах это стабильно
  325/1616.

## 3. Точки-индикаторы: пик отклонения, не яркость

`image_layout_dots(src, band)` по полосе строки точек отдаёт отрезки
`{center, width, peak}` и активный слот. Для колонки — **максимум**
|кадр − поле| по полосе.

- **Усреднение по полосе размывает точку.** Точка тонкая (~20 px в кадре
  2400), полоса 60 px: средняя яркость колонок почти не растёт, пять из шести
  точек терялись. Максимум ловит все шесть (шаг между центрами 44 px,
  ровно карусельный).
- **Активный слот по яркости не читается.** Медианная яркость всех шести
  точек различается на 1–2 ступени — argmax по ней выдавал случайный слот.
  Пик отклонения от поля разводит надёжно: активная 22–30, неактивная 10–16,
  вдвое. Проверено на десяти кадрах оригинала — слоты сошлись с
  просмотренным монтажом.

## 4. Вырез: скруглённая альфа поверх живого фона

`image_layout_alpha(h, w, rect, radius, feather)` — маска скруглённого
прямоугольника (знаковое расстояние до него: `d = min(max(qx, qy), 0) +
hypot(max(qx,0), max(qy,0)) − r`), `image_layout_cutout(src, out, rect,
radius)` применяет её и пишет RGBA-файл. Применение: страница рисует живой
фон (CSS-градиент с анимацией), картинка слоем несёт только стекло карточки.

- **`feather` обязателен, JPEG сдвигает край на ±1 px.** Резкая маска на
  живом фоне под вырезом даёт белёсую нитку по периметру; 8 px перехода
  прячут её на глаз полностью.
- **`zero_hidden` — это размер файла.** Под полной прозрачностью лежат
  пиксели градиента, которые кодеку незачем беречь: те же слайды 1080×1986
  — PNG 2.8 МБ против WebP q90 ~170 КБ с бит-в-бит совпадающей альфой.
  Обнуление RGB под альфой само по себе снимает PNG до 1.2 МБ — мало, формат
  решает больше.
- **Радиус мерить дугой, не «полоской у угла».** Попытка оценить скругление
  горизонтальным срезом у угла дала ложный «радиуса нет»; SDF с
  прикинутым радиусом сверяется визуально на монтаже (`image_frames_grid`).

## CLI

```bash
python -m image_.image_layout bgfield slide.png --xy 540,900 --xy 80,1700
python -m image_.image_layout edge slide.png --band 700,940 --search 200,450
python -m image_.image_layout dots shot.png --band 1740,1800
python -m image_.image_layout cutout slide.png --rect 86,325,992,1616 \
    --radius 48 --out card.webp
```
