# Клиент запущенной панели: вошёл, проверил, перелогинился сам

> Проверка поднятой панели руками стоит трёх повторяющихся шагов: войти
> (JSON-телом — форма даёт 422), не перепутать домен куки, перелогиниться после
> рестарта. `uvicorn_panel_client()` делает это за вызывающего: адрес из
> `BASE_URL` или `compose ps`, вход под учёткой из `.env`, автоперелогин на 401.
> Инструмент — `py_modules/uvicorn_/uvicorn_panel.py`,
> CLI: `python -m uvicorn_.uvicorn_panel GET /api/...`.

## 1. Адрес панели берут из факта, а не из головы

`uvicorn_panel_base()` сначала зовёт `BASE_URL` (проект сам знает, как его
панель видна снаружи), иначе смотрит `docker compose ps` в **основной выкладке**
(compose помнит проект от каталога, из которого его поднимали — в worktree без
этого «service is not running») и берёт опубликованный порт сервиса с `uvicorn`
в имени. Адрес всегда `127.0.0.1:<порт>`: куку ставят на тот же хост, с которым
просят панель, иначе домен куки и адрес запроса расходятся и запрос приходит
без неё — молчаливая 401 вместо ответа.

## 2. Клиент: вошёл один раз, не вспоминаешь про куку

`await uvicorn_panel_client()` — готовый к запросу `httpx.AsyncClient`: куки
правильные, учётка из `.env` (`ADMIN_USERNAME`/`ADMIN_PASSWORD`), 401 чинится
сам — один перелогин и повтор запроса внутри `request()`. Рука, пишущая
проверку, не должна помнить про вход: вход — часть клиента, а не теста.

⚠ Клиент сидит на общем транспорте (`http_pool`) и **его не закрывают**:
`async with` закрыл бы транспорт — а с ним и чужие вызовы.

## 3. Точка состояния: `web_state` — ручка + поля → значение

Когда вопрос звучит «что отвечает ручка» и не требует ни браузера, ни
асинхронии, клиент раскладывать незачем: `web_state(url, params=…, method=…)`
(файл `web_/web_state.py`) — тот же вошедший клиент, но точкой: вошёл под
учёткой из `.env`, снял конверт `{'result': …}`, отдал содержимое; ошибки —
словами, как ответила панель. Отличие от § 2: `uvicorn_panel_client()` —
готовый клиент для **серии** запросов с перелогиним, `web_state` — один
вопрос одним вызовом, без `await` снаружи.

```bash
python -m web_.web_state '<адрес ручки>' --params '<поле>=<значение>'
```

## Грабли

- **`/auth/login` не берёт form'у** — JSON-объект, на форме 422; проверять
  лучше на живом теле, а не на своей заглушке.
- **кука умирает с процессом**: после рестарта старый клиент ждёт 401 на каждом
  запросе; автоперелогин в клиенте — ровно про это, руками про это забывают.
- **`localhost` ≠ `127.0.0.1`** для cookie-джара: домен куки сверяют с адресом
  запроса — в этом модуле это один и тот же `base_url`, руками это разъезжается.
