# dsh API — метод хоста harness'а из-за его пределов

> Хост DeepSeek Harness слушает петлю и с 0.1.5 пускает в `/api/*` **только
> по cookie** — петля больше не достаточная защита. В самом проекте клиент
> уже есть, но он привязан к окружению проекта; наружу всегда нужны были
> только два вопроса: «жив ли хост» и «позвать метод». `dsh_/dsh_api.py` —
> эти два вопроса без окружения проекта: cookie печётся из секрета на диске,
> конверт собирается сам.

## 1. Жив ли хост — без секрета вовсе

```python
from dsh_.dsh_api import dsh_api_alive

dsh_api_alive()                          # True — любой ответ HTTP, даже 401
dsh_api_alive(base='127.0.0.1:8890')
```

Смысл вопроса ровно в «процесс жив, порт слушает», поэтому спрашивается
открытый корень: мёртвый хост и живой-но-без-секрета — разные ответы, и
сторожу путать их нельзя.

## 2. Метод — конвертом

```python
from dsh_.dsh_api import dsh_api_call

sessions = dsh_api_call('session/list', {'_request': {}})
```

`POST http://<base>/api/<область>/<метод>`, тело — конверт
`client-request` с `rpcId`, ответ разворачивается: ветка `ok` →
`result.value` как есть, ветка ошибки → `DshApiError` с кодом и сообщением
хоста. Методы без параметров требуют пустого `args` — без конверта хост
отвечает `gateway/arguments-invalid`.

## 3. Ручка плагина — GET без конверта

```python
from dsh_.dsh_api import dsh_api_get

dsh_api_get('bell.state', query='session=...')     # {'ringing': True}
```

Маршруты плагинов хоста отдают обычный JSON, конверта не наращиваем: что
вернула ручка, то и приходит.

```bash
PYTHONPATH=. python -m dsh_.dsh_api alive
PYTHONPATH=. python -m dsh_.dsh_api call session/list --args '{"_request":{}}'
# get — только ручки без параметров; query (как session= у bell.state) — из python
```

## Грабли

1. **Имя поля аргументов — часть дескриптора метода, и у многих оно с
   подчёркиванием**: `session/list` просит `_request`, а не `request`.
   Угадывать нечем — но ошибка `gateway/arguments-invalid` **перечисляет
   поля дескриптора** («missing `_request`; unexpected `request`»): читать
   её текст, а не гадать словарь.
2. **Cookie привязана к авторитету** (`host:port`): одна на 8790 не подойдёт
   хосту на 8890, поэтому адрес — единственный параметр и печатаем пропуск
   на каждый запрос (один sha256 + один hmac — дешевле следить за протуханием).
3. **Секрет — из `<DSH_HOME>/.credentials.yaml`** (переменная `DSH_HOME`
   перебивает путь), запись `client-connection/browser-session`. Сам
   секрет, значения ключей рядом с ним и адреса с `?token=` **никуда не
   печатаются**: сообщение об ошибке называет путь, но не содержимое.
4. **401 — текстом, не JSON**, и значит ровно одно: нечем подписать
   (секрет другой — хост поднимался не этим пользователем) либо пропуск
   истёк; это не «метод не найден».
5. **GET-ручки плагинов — не конверт**: у них свой ответ (и свои
   обязательные параметры — `bell.state` без `session` отвечает 400);
   `dsh_api_call` на них не катится, для них `dsh_api_get`.
