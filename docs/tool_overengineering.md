# Tool overengineering — обвязка, пережившая свою причину

> `tool_/tool_overengineering.py`: разбирает `.py` деревом и ищет точные приметы
> переусложнения, которое оставили правки: обёртки-переименования, опции без
> пользователя, абстракции над одним случаем, класс ради одного вызова.

    PYTHONPATH=py_modules python -m tool_.tool_overengineering src           # legacy-каталог целиком
    PYTHONPATH=py_modules python -m tool_.tool_overengineering a.py b.py     # файлы партии
    PYTHONPATH=py_modules python -m tool_.tool_overengineering src --root .  # где искать наследников

Код возврата — число находок (0 — чисто). Правило, которое он сторожит, — `code_rules.md` §4.5.

## 1. Зачем

Новый код редко пишут «на вырост» — переусложнённым его делают **правки**. Было три
реализации, две сняли, а абстракция осталась; второй режим больше никто не включает, а
параметр и ветка под него живут; функцию переименовали, а старое имя оставили обёрткой.
Каждый такой след выглядит частью устройства, и читатель строит на нём рассуждение.

Поэтому инструмент смотрит **файл целиком, а не дифф**, и годится двумя способами:
аудитом legacy-каталога и пунктом 8 заставы ревизии (`claude_gate_code_review`), которая
зовёт его по файлам партии правок.

## 2. Приметы

| kind | что найдено |
|------|-------------|
| `passthrough` | функция только передаёт свои параметры другой, по порядку и без своего значения |
| `fixed_param` | у **приватной** функции параметр с умолчанием, а вызовы в файле его не меняют — или все передают один литерал |
| `single_impl` | абстрактный класс (ABC / Protocol / методы из `...` и `raise NotImplementedError`) с ≤1 наследником под корнем |
| `class_as_function` | класс без баз из `__init__` и одного метода |

Замер на всём `py_modules`: 28 кандидатов за 1,5 с.

## 3. ⚠⚠ Что намеренно **не** находка

Каждое исключение — ложная находка с первого прогона по слою:

* **dunder-методы** (`__aexit__` → вложенный объект) — протокол, а не второе имя;
* **публичная функция, отдающая работу своей приватной** — дверь модуля по §4.3;
* **умолчание `None`** (`_cli(argv=None)`) — точка подмены для тестов, а тесты в другом
  файле, и «вызовы в файле» их не видят;
* **«все передают одно» по переменной** (`_face(det_size)` трижды) — одно имя, разные
  значения; судится только литерал;
* **класс из одних `pass`** — намеренный null-object (тихий логгер), а не абстракция.

## 4. ⚠⚠ Публичные параметры не судятся

`fixed_param` смотрит только приватные функции: их вызывающие живут в том же файле, и
вывод точный. Публичную функцию общего слоя зовут проекты — «здесь никто не передаёт»
не значит ничего (та же причина, что у `tool_dead --private`).

## 5. Грабли

1. **Наследники ищутся текстом** (`class X(...Base...)`) по корню: регистрация через
   реестр, `type()` или конфиг обманет поиск. В общем слое абстракцию наследуют
   проекты — «ни одного наследника» там значит «ни одного здесь».
2. **Судейское не считается**: «лишний слой», «флаг, который нигде не меняется»,
   fallback для снятого режима — без контекста ложных находок больше, чем верных, а
   ложное «упрости» выполняют. Эту половину пункт 8 заставы задаёт словами.
3. **Только `.py`**: для PHP/JS приметы те же (§4.5), смотрит тот, кто правил.
4. Оставляешь находку намеренно (чужой формат, известный второй случай) — причина в
   докстринг, иначе следующий ревизор её снимет.
