# Tool Typo — следы неудачной правки в прозе, перед коммитом

> Ошибка в докстринге живёт дольше ошибки в коде: код падает, а текст молча врёт
> читателю и портит корпус поиска (`tool_find.md`). Проверка стоит секунду и идёт
> **до** `git commit`, вместе с остальными машинными проверками.

## 1. Как звать

```bash
PYTHONPATH=. python -m tool_.tool_typo             # перед коммитом; вывод обязан быть чистым
PYTHONPATH=. python -m tool_.tool_typo --kind mixed
PYTHONPATH=. python -m tool_.tool_typo --prose     # всю прозу — на вычитку модели
PYTHONPATH=. python -m tool_.tool_typo --cyrillic  # кириллица в именах функций и ключах словарей
```

Чистый вывод выглядит так:

```
механических следов правки нет (орфографию это не проверяет — см. --prose)
```

## 2. Что ловится и что нет

| Проверка | Пример | Надёжность |
|----------|--------|------------|
| `mixed` — буквы из двух алфавитов в слове | `косину` + латинская `c` | высокая |
| `mixed` — слипшиеся при вставке слова | `вcwd`, `иTokenizer` | высокая |
| `doubled` — слово повторено подряд | `слово слово` | высокая |
| орфография, согласование, смысл | «полевом пояснем» | **не ловится** |

Последняя строка — не недоработка, а граница. Русского словаря в системе нет, и
**чистый вывод означает «механических следов нет», а не «текст без ошибок»**.

## 3. Почему нет проверки «по похожести»

Первая версия искала одинокие формы, до которых один шаг правки от частого слова. Она
дала 1932 кандидата на 508 записей — и провалила главный тест:

| Пара | Похожесть | Что это на самом деле |
|------|-----------|----------------------|
| `сериалу` ↔ `сериал` | 0.92 | законные формы |
| `сохранять` ↔ `сохранить` | 0.89 | законные формы |
| `пояснем` ↔ `пояснение` | 0.75 | **настоящая опечатка** |

У флективного языка законные формы похожи **сильнее**, чем опечатка на верное слово:
эвристика ранжирует наоборот и тонет в шуме. Проверка убрана целиком, а не смягчена
порогом — порога, разделяющего эти два случая, не существует.

## 4. Вычитка по-настоящему

`--prose` отдаёт всю прозу репозитория строками `файл:строка<TAB>текст` — готовыми к
отправке модели:

```bash
PYTHONPATH=. python -m tool_.tool_typo --prose | head -400 \
  | gx10 -s 'корректор: только орфография и согласование, термины и код не трогай' \
         'найди ошибки, формат ответа: файл:строка|слово|как правильно'
```

⚠ Объём — около 13 тысяч строк (1.6 МБ). Целиком в промпт не влезет: режьте на части
или сужайте корнем через `tool_typo_prose(root=...)`.

## 5. Имена и ключи — не опечатка, а правило (`--cyrillic`)

Здесь инструмент уже не про прозу, а про код: `*.py` разбирается синтаксическим
деревом, и показываются имена функций и ключи словарей на кириллице — то, чего
правило `code_rules.md` §1.2 не терпит. В отличие от grep-шаблонов, дерево не
гадает по раскладке и ловит и смешанные имена (`test_metadata_строкой`).

⚠ Дереву не видно классы, переменные, SQL и разметку — для них остаются grep-шаблоны
§1.2. Инструмент не заменяет их, а закрывает верхнюю половину той же приёмки.

## Грабли

1. **Подмена буквы глазами не видна.** `косинуc` с латинской `c` читается как `косинус`
   и переживает любую вычитку человеком — ровно поэтому проверка машинная.
2. **Чистый вывод ≠ текст без ошибок.** Орфографию инструмент не проверяет; «полевом
   пояснем» он пропустит и должен пропустить.
3. **Английское слово с русским окончанием — приём репозитория**, а не ошибка: `JOINы`,
   `switchать` отфильтрованы. Новый такой оборот в выдаче означает, что он не подошёл
   под шаблон, — проверьте, а не правьте вслепую.
4. **Код в обратных кавычках вырезается.** Опечатка внутри `` `имя_функции` `` не
   ловится: там своя орфография, и её проверяет импорт, а не корректор.
