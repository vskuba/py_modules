# Mobile hardware — железо читают с устройства, а не помнят наизусть

> Разрешение, плотность, версия Android и «где тут край экрана» — факты конкретного
> устройства и машины, а память агента и заметки прошлой сессии устаревают молча.
> Перед расчётом координат паспорт снимают командами из раздела 1; этот файл — про то,
> **как факты получать и как не ошибиться их использованием**. Чем смотреть (`adb_`,
> `ai_vision`) — `mobile_device.md`; как нажимать (`adb_ui`, `adb_input`) — `mobile_control.md`.

## 1. Паспорт: снять один раз за сессию

```bash
python -m adb_.adb_ info       # модель, Android, разрешение, плотность — разом, с живого устройства
```

Или `adb_device_info()` из кода (`mobile_device.md`). Без py_modules — голом adb,
там же проверка связи (`adb devices -l`): `getprop ro.product.model`,
`getprop ro.build.version.release`, `wm size`, `wm density`.

| Факт | Команда | Зачем |
|------|---------|-------|
| Разрешение | `wm size` | от него считают доли экрана в жестах |
| Плотность | `wm density` | перевод dp ↔ px, оценка мишеней (раздел 3) |
| Версия Android | `getprop ro.build.version.release` | поведение системных диалогов и прав различается |

Перевод величин: `px = dp × density / 160`. На `density 480` палечная мишень 48 dp —
это 144 px; на другом телефоне те же 48 dp — другие пиксели, зашитое число из прошлой
сессии означает чужой экран.

`wm size` при включённом масштабировании отдаёт две строки — действует **последняя
названная** (`Override`), физическая её только описывает.

## 2. Экран: координаты с глаз не брать

Снимок устройства просматривают через инструмент, который **дожимает кадр** (увидеть
1080×2400 целиком — значит увидеть его в уменьшенном масштабе). Координата, снятая
глазом с просмотренной картинки, — из другой системы:

```text
❌  «кнопка примерно на (540, 1900)» — по просмотренному изображению
✅  координаты из `bounds` дампа (`adb_ui`) либо честный пересчёт по масштабу
```

Пересчитывать допустимо только масштаб, известный точно (размеры исходного кадра и
полученного), а не «на глаз похоже». Надёжнее — не считать вовсе: точку нажатия по
надписи отдаёт `adb_ui_find`, а для того, чего в дереве нет (картинка без подписи),
есть вырезка в исходных пикселях — `adb_crop` с обратным пересчётом через
`adb_crop_point` (`mobile_steps.md`). Пиксельные замеры (границы пилюль и полос)
делают по **файлу в родном разрешении** библиотекой, а не по просмотренной картинке.

## 3. Ввод: мишень, край, жест

- **Мишень.** Прикинуть размер цели до тапа: 48 dp в пикселях этого телефона
  (раздел 1). Точка в 10 px от края элемента — промах, внешне неотличимый от
  попадания; проверкой служит сравнение экранов до и после (`adb_state_diff`).
- **Край.** Жест, начатый вплотную к верхней или нижней границе экрана, забирает
  система: вместо expected — шторка уведомлений или панель навигации. Отступ обязателен.
- **Свайп ≠ тап.** Длинный свайп по карусели перелистывает карточку, по краю —
  переключает вкладку. Жест «прокрутить список» в области, где живёт карусель,
  уводит на чужой экран; прокрутку задают внутри списка и коротко.

## 4. Системные перехватчики: они молча ломают сценарий

| Перехватчик | Симптом | Что делать |
|-------------|---------|------------|
| Шторка уведомлений | тап в верхнюю полосу открыл не элемент, а шторку | закрыть (`KEYCODE_BACK`), тапить ниже; отступ — раздел 3 |
| Блокировка / погасший экран | `mCurrentFocus` пуст | разбудить (`adb_input_wake`), разблокировать |
| Сон во время долгой работы | дампы и тапы «не слышны», экран погас | `adb shell svc power stayon true` на время сессии, по окончании — `false` |
| Диалог «Открыть с помощью» | внешняя ссылка увела из приложения в системный выбор | это не ошибка приложения; закрыть («Скасувати»), ссылку считать dead-end'ом сценария |
| Клавиатура | поле видно, тап по нему не срабатывает — под палью клавиатура | свернуть (`KEYCODE_BACK` один раз закрывает клавиатуру, не экран) |
| Биометрия / системный диалог поверх | фокус чужой, тапы уходят в диалог | `adb_app_current` называет владельца фокуса — верить ему, не скриншоту |

## 5. Дерево интерфейса: не у каждого приложения отдаётся

`uiautomator`/`adb_ui` видит дерево приложений на WebView и нативных — на Flutter в
release-сборке дерево пустое, и это не поломка adb. Пустой дамп при живом экране —
признак switchать на зрение (`adb_screen_describe`, `vision_llm.md`), а не копать
глубже дамп. Dart VM Service в release недоступен — «включить semantics» из кода
приложения нельзя.

## 6. Тулчейн сборки: факты с машины, привычки — в проект

Пути SDK, версии JDK и node — принадлежность машины, между проектами они общие, но
всё равно читаются, а не вспоминаются:

```bash
java -version && node -v && cordova -v 2>/dev/null
echo "${ANDROID_HOME:-не задан}"      # путь SDK: читать из окружения, не помнить
```

Проектные особенности (какой JDK требует конкретная обёртка, куда кладётся артефакт)
в проектной документации; здесь — только способ получить факты.

## Чек-лист «новый телефон или новая сессия»

1. `adb devices -l` — связь и серийник.
2. `wm size` + `wm density` — разрешение и плотность этой сессии.
3. `svc power stayon true` — на время длинной работы.
4. Координаты — только из дампа (`adb_ui`), не с просмотренной картинки.
5. После каждого действия — сравнение состояния (`adb_state_diff`, `mobile_control.md`).

## Грабли

1. **«Координаты с глаз» мимо на 100–200 px** — просмотренный снимок дожат, глаз
   меряет уменьшенную копию; тапы падают в промежутки между строками, а дамп при этом
   выглядит «тем же экраном». Координаты — из `bounds`, замеры — по файлу в родном
   разрешении.
2. **Зашитые числа чужого экрана** — «кроп сверху 110 px» с одного телефона
   обесценивается на другом; перед раскроем `wm size`, а числа — в проект, не в общее.
3. **`Override size` выше `Physical`** — кто взял первую строку `wm size`, считает
   от неработающего разрешения; действует последняя названная.
4. **Шторка вместо кнопки** — верхняя полоса экрана принадлежит системе; тап в неё
   не доходит до приложения, а промах выглядит как «кнопка не нажимается».
5. **Свайп-карусель** — длинный свайп по области карточки перелистывает её или
   уходит во вкладку; «прокрутка» теряется, состояние меняется не то, что ждали.
6. **Пустой дамп у живого экрана** — Flutter release без semantics; копать дамп
   бесполезно, нужен vision.
