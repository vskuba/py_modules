# Person UA — украинские имя и фамилия, какими их пишут в заказах

> Списки, собранные из чужих источников, именами заполнены наполовину: ники
> (`A.V.PRTT`), инициалы (`S·Z`), чужие алфавиты, просто `@`. В заказе на
> украинский магазин такого не бывает, а чинить это чисткой нечем: фамилии в
> источнике чаще всего нет вовсе.

## 1. Зачем

Модуль отвечает ровно на вопрос «как зовут»: имя и фамилия, согласованные по
роду, из справочника живых украинских имён. Телефон, адрес и прочее он не
трогает — соседние данные остаются теми, что были.

Так устроен и `email_make.md`: не «склеить строку», а «выглядеть как настоящее».
Разница в цене ошибки — список, который выдаёт себя, бесполезен целиком.

## 2. Как звать

```bash
PYTHONPATH=py_modules python3 -m person_.person_ua 10 --gender f --seed 7
```

| Функция | Контракт |
|---------|----------|
| `person_ua_name(gender='', rand=None) -> dict` | `{'first', 'last', 'gender'}`; пустой `gender` — монетка |
| `person_ua_surname_female(last) -> str` | женская форма фамилии; несклоняемая — как есть |

```python
from person_.person_ua import person_ua_name

person = person_ua_name()          # {'first': 'Олена', 'last': 'Левицька', 'gender': 'f'}
```

## 3. ⚠⚠ Род согласуется, иначе выдаёт себя сразу

«Олена Чорний» — не описка генератора, а **признак** генератора: человек так не
представляется, и одной такой строки хватает, чтобы список перестали считать
настоящим.

Имена разделены по роду, фамилия с родовой формой получает её:

| Окончание | Мужская | Женская |
|-----------|---------|---------|
| `-цький` | Левицький | Левицька |
| `-ський` | Вишневський | Вишневська |
| `-ий` | Чорний | Чорна |
| `-ій` | Крайній | Крайня |

⚠ Фамилии на `-енко`, `-ук`, `-чук`, `-ко` по роду **не меняются вовсе** —
«Коваленко» и «Ковальчук» одинаковы у мужчины и женщины. Это свойство языка, а
не упрощение модуля: приписать им женское окончание значит сделать ту же ошибку
с другой стороны.

⚠ Порядок правил в `PERSON_UA_FEMALE_RULES` значим: длинные окончания идут
раньше коротких. Иначе `-цький` поймается правилом `-ий` и даст «Левицьа».

## 4. ⚠ Род возвращается третьим полем

Не для красоты: по нему зовущий решает, как обратиться в письме и какое
окончание поставить в своей форме. Выводить род обратно из готового имени
значило бы завести второй справочник имён — и разойтись с первым.

## 5. Почему `rand` — довод, а не глобальный `random`

Разнообразие проверяют счётом: «на двухстах именах вышло столько-то разных».
Такой проверке нужен повторяемый источник случайности, иначе тест то проходит,
то нет. Передал `random.Random(42)` — получил тот же набор; не передал — обычный
случай. Правило общее с `email_` (`email_make.md`, §5).

## 6. Чего здесь нет

**Отчества.** В интернет-заказе его не спрашивают: форма площадки просит имя и
фамилию, и третье поле выдало бы заполнение не того бланка.

**Других языков.** Модуль назван `person_ua` именно поэтому: справочник имён —
это знание о стране, и прятать его за «универсальным» именем значит обещать то,
чего нет. Понадобится соседняя страна — рядом ляжет `person_pl.py`, а не
параметр `locale` у этого.

**Связи с телефоном и почтой.** Имя не знает, чьё оно: номер приходит из своего
источника, адрес почты строит `email_make` из этого имени. Каждый отвечает за
своё, и подменить можно любой из трёх по отдельности.
