# Backup Rules — seed и бэкап

> Два разных механизма с разными задачами: **seed** переносит архитектурные данные между
> инсталляциями, **бэкап** восстанавливает базу после сбоя. Путать их дорого.

## Разница

| | Seed | Backup |
|--|------|--------|
| Содержимое | выбранные таблицы (архитектура) | вся БД |
| Формат | текстовый SQL | сжатый дамп |
| Назначение | первичный запуск свежей БД, перенос настроек | полное восстановление |
| Применение | `INSERT IGNORE` — безопасно повторно | полная перезапись |
| Автоприменение | да, при старте на пустой БД | нет, только вручную |
| В репозитории | да (это часть конфигурации проекта) | нет |

## Seed: экспорт архитектурных данных

### Формат файла

```sql
-- Seed SQL
-- Generated: <timestamp>
-- Tables: <list>

SET NAMES utf8mb4;
SET FOREIGN_KEY_CHECKS = 0;

-- TABLE: <table>
INSERT IGNORE INTO `<table>` (`id`, ...) VALUES
  (1, ...),
  (2, ...);

SET FOREIGN_KEY_CHECKS = 1;
```

- `INSERT IGNORE` — повторное применение не трогает существующие строки
- `FOREIGN_KEY_CHECKS = 0` вокруг вставок — снимает зависимость от порядка таблиц
- значения экранируются библиотечной функцией драйвера, не самописной
- несколько файлов хранятся по дате в имени → можно откатиться на предыдущую версию

### Какие таблицы включать

**Включать** — то, что заполняется руками и является частью архитектуры: ноды, роли,
права, пользователи, настройки, конфигурации агентов и workflow, справочники.

**Не включать:**

- то, что **синхронизируется автоматически** при каждом старте (реестр инструментов)
- то, что **создаётся динамически** в рантайме
- **runtime и логи**: сессии, трейсы, журналы запросов, очереди, планы

Правило: если строку создаёт код, а не человек, — она не в seed.

### Автоприменение при старте

1. взять самый свежий seed-файл
2. проверить признак «база свежая» — например, `COUNT(*)` по опорной таблице равен нулю
3. пусто → применить; не пусто → пропустить

Проверка обязательна: без неё каждый рестарт молча дописывает данные.

### Парсинг SQL

Разбивать файл на стейтменты **нельзя простым `split(';')`** — точка с запятой
встречается внутри строковых литералов. Нужен сплиттер, знающий про кавычки и
экранирование.

## Backup: полный дамп

### Создание

Приоритетный путь — штатная утилита дампа БД:

```
<dump-tool> --single-transaction --routines --triggers --default-character-set=utf8mb4 <db>
# stdout → gzip(compresslevel=6) → <backup_dir>/backup_<timestamp>.sql.gz
```

**Пароль передаётся через переменную окружения, не в командной строке** — аргументы
видны в списке процессов всем.

Fallback на языковой драйвер (по таблице: DDL + все строки) допустим, когда утилиты нет
в образе, но он менее надёжен: не переносит триггеры и процедуры. Об этом ограничении
надо знать до, а не после аварии.

### Восстановление

Распаковать поток → подать на stdin клиенту БД с явной кодировкой. Требует наличия
клиента в образе — если его нет, create работает, а restore нет, и обнаруживается это в
худший момент. **Проверять restore заранее.**

### Таймауты и хранение

- таймаут на создание меньше, чем на восстановление (восстановление всегда дольше)
- каталог бэкапов — на постоянном томе, а не внутри слоя контейнера
- сортировка списка по имени работает как сортировка по дате, если timestamp в имени

## Безопасность

1. **Имя файла из запроса — валидировать всегда:** запретить `/` и `..` (path traversal),
   разрешить только ожидаемое расширение.
2. **Удаление последнего бэкапа блокировать** на уровне UI и API — иначе «почистил
   список» означает «остался без бэкапа».
3. **Права на восстановление** — отдельное право, а не то же, что на просмотр списка:
   restore перезаписывает всю базу.
4. **Бэкап содержит все данные пользователей.** Скачанный файл — та же чувствительность,
   что и сама база: не в общие каталоги, не в чаты, не в репозиторий.

## Грабли

1. **Seed применился повторно** — забыли проверку «база свежая»
2. **`split(';')`** — файл рвётся посреди значения с точкой с запятой
3. **Нет клиента БД в образе** — restore недоступен, выясняется при аварии
4. **Пароль в аргументах команды** — виден в `ps`
5. **Автогенерируемые таблицы попали в seed** — конфликтуют с синхронизацией при старте
