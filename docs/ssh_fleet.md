# SSH Fleet — несколько машин разом и файл на цель

> `ssh_x` умеет говорить с одной машиной, а спрашиваем мы ферму: «все живы?»,
> «где крутится этот контейнер?», «положи конфиг на оба узла». Насадить цикл
> по `ssh_x` можно и руками, но последовательный обход четырёх узлов мёртвого
> роется в таймаутах по очереди, а перенос файла каждый раз сочиняется заново
> — и каждый раз без `--chmod`, отчего файл живёт чужими правами.

## 1. Флот: одна команда всем целям, параллельно

```python
from ssh_.ssh_fleet import ssh_fleet_run

r = ssh_fleet_run(['узел-1', 'узел-2'], 'uptime -p', timeout=25.0)
# {'узел-1': {'code': 0, 'output': 'up 3 weeks...', 'error': ''},
#  'узел-2': {'code': -1, 'output': '', 'error': 'ssh: ...'}}
```

Ключ ответа — **строка цели ровно как передали**; узел, до которого не
доехались, не выбрасывается из словаря, а приезжает записью `code: -1`:
флот отвечает ведомостью, а не исключением — иначе одна мёртвая машина
съедает ответы живых. Потолок параллельности — `SSH_FLEET_PARALLEL` (8):
больше — уже похоже на флуд sshd.

Значения в скрипт — так же, как `ssh_x`: аргументы через `args=`, скрипт
уходит по stdin, кавычки целы.

```bash
PYTHONPATH=. python -m ssh_.ssh_fleet узел-1 узел-2 'uptime -p'   # цели — повторяемые
# позиционные; вывод JSON; код возврата — число узлов, ответивших не нулём
```

## 2. Файл на цель: `ssh_put` с правами в один поход

```python
from ssh_.ssh_put import ssh_put

ssh_put('local/unit.service', 'узел-2', '/tmp/unit.service', mode='644')
```

Идёт `rsync -a --`, где нет `rsync` — `scp`; форма цели ровно `ssh_x`
(`[флаг...] пользователь@хост`), один хост на вызов. `mode` — октальные
цифры: при `rsync` живёт в `--chmod`, при `scp` досказывается отдельным
походцем `chmod`. Ответ — та же форма `{'code', 'output', 'error'}`, что у
всего ssh-слоя; таймаут — `code: -1`, не исключение.

⚠️ `dest` на чужую машину — просто строка для удаленной шелла: путь с
пробелами без кавычек разъедется. Экранировать самому, а лучше не селить
пробелы там, где их не просят.

## Грабли

1. **Одна мёртвая цель — не исключение, а запись** с `code: -1`: флот
   обязан ответить про каждую, молчание про узел хуже вранья про узел.
2. **Ключ словаря — строка цели как передали**: `'user@host'` и `'alias'`
   для одного узла — два ключа, и сверка «все ли ответили» по имени
   разъедется со списком целей.
3. **`ssh_put` не катит каталоги рекурсивно назло `rsync -a`** — на это
   не накладываем табу: каталог на цель это тоже `rsync`, но сверка
   содержимого уже задача покрупнее. Пока — файлы.
4. **Права между переносом и `chmod`**: при fallback на `scp` файл короткое
   время живёт своими (маска umask). Для публичного `/tmp`-файла это
   секунды, для секрета — причина не тащить секрет через `scp` вовсе.
5. **`ssh_x` — транспорт флота**, и его молчание на предупреждениях
   (`Warning: Permanently added`) распространяется сюда же: первая встреча
   с новым узлом не спросит подтверждения — известность ключа решает
   `ssh_config`, а не этот слой.
