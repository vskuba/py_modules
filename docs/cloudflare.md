# Cloudflare — виджет Turnstile на живой странице

> Вызов Cloudflare устроен так, что его провал не видно: страница не падает,
> консоль молчит, спиннер просто возвращается к чекбоксу. Отсюда весь модуль:
> виджет нужно **найти сквозь тень**, нажать **по-настоящему**, а провал
> **объяснить по сети**, потому что на странице объяснения нет.
>
> Модуль — `cloudflare_` (`py_modules/cloudflare_`). Страницу, прокси и
> отпечаток даёт вызывающий: функции берут готовую `page` из `browser_`
> (сессия, сценарий) или заводят свою в CLI.

## 1. Порядок вызовов

```
watch = cloudflare_watch(page)        # до goto: раунды вызова идут первыми
... открыть страницу, дождаться модалки или формы ...
box   = await cloudflare_widget_box(page)   # есть ли виджет и где
await cloudflare_widget_click(page)         # мышь по центру чекбокса
tok   = await cloudflare_token_wait(page)   # непустой ответ или пусто
watch['stop']()
cloudflare_challenge_diagnose(watch['events'], tok)
```

`verdict` у разбора пять: `passed` (токен есть), `pat-missing` (браузеру
нечем платить токен приватности), `scored` (отклонён по очкам репутации —
вопрос к адресу выхода), `silent` (вызов до страницы не доехал вовсе),
`unknown` (раунды есть, признака нет).

## 2. Грабли, в которые уже наступали

**Виджет живёт в чужом iframe, часто в теневом узле.**
`document.querySelectorAll('iframe')` его не находит, `.click()` по элементу
остаётся синтетическим событием, и managed-раунд кончается спиннером без
ответа. Поиск через тень — `CLOUDFLARE_WIDGET_JS`, нажатие — `mouse.click`
в центр rect'а.

**Токен ≠ успех.** Поле `cf-turnstile-response` появляется на странице и до
прохождения вызова, с пустым или вчерашним значением. Годится только
непустое **после клика** — потому `cloudflare_token_wait` и ждёт длину, а не
существование поля.

**Сеть честнее страницы.** Раунд вызова — это `/fo/`, `/pat/`, `/i/`; ни
одного из них на странице не видно. 401 на `/pat/` без последующего выпуска
токена — браузеру нечем доказать приватность (Private State Token: в Chromium
без приватных песочниц API нет), и маскировка отпечатка здесь не помогает
**ни в какой мере**: та же страница в брендированном браузере без аттестации
проваливается одинаково. 204 на `/i/` — норма, телеметрия дошла; правилом
провала её не считаем.

**Молчание — это тоже вердикт.** Ни одного ответа вызова (`silent`) означает,
что страница даже не спросила защиту: модалка не открылась, скрипт вызова
заблокирован CSP — искать надо до виджета, а не в нём.

## 3. Границы

Определение состояния по тексту (`cloudflare_widget_state`) — подсказка
человеку, не решение: спиннер и галочка-картинка текста не имеют,
окончательный ответ — токен плюс разбор сети. Сам вызов модуль не проходит и
не обходит: он находит, нажимает и объясняет. Что делать с вердиктом — сменить
адрес выхода (`scored`) или браузер с аттестацией (`pat-missing`) — решает
вызывающий.
