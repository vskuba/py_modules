# Дек целиком: каждый слайд в кадре, в кадре ничего не отрезано

> Семь слайдов глазами — это «первый выглядит нормально». Таблица на втором
> длиннее вьюпорта на восемьдесят пикселей без единой ошибки в консоли, а
> кнопка «дальше» после правки молчит семь раз подряд. `web_deck_check` проходит
> весь дек сам: навигация, геометрия, кадр — на слайд, и говорит, где именно
> подуть. Инструмент — `py_modules/web_/web_deck.py`, CLI:
> `python -m web_.web_deck файл.html`.

## 1. Сейчас

```bash
PYTHONPATH=. python -m web_.web_deck .claude/docs/shop_network_map.html
#   слайд 1: ок виден=1
#   слайд 2: 🔴 виден=2 вылезает на 180px вниз, 0px вбок
#   …
#   7 слайд(ов), кадры: /tmp/deck_…
```

rc — число проблемных слайдов (0 — дек принят), кадры PNG — по слайду на каждый,
в каталоге, путь в выводе. Вьюпорт по умолчанию 1280×720 (`--size`), без кадров
— `--no-shots` (тогда быстрее).

## 2. О чём строка слайда

* `виден=N` — какой слайд действительно открылся после навигации; не тот номер —
  навигация сломана (клик-ветка) или дек ходит по хэшу (ветка не он).
* `вылезает на Npx вниз` — нижняя отрисованная кромка листьев против вьюпорта.
* `бок дока раздут, рисунка там нет` — `scrollHeight` больше кадра, а рисовать
  там нечего: фантомный бокс (пережиток `svg height:auto`), не дефект вёрстки.

## Грабли

1. **навигация ищем по двум конвенциям**: глобальная `show(k)`, иначе клики по
   `<body>`. Дек с хэш-навигацией попадёт в клик-ветку и покажет не тот слайд —
   правка на его же стороне: дать деку `show(k)` или править вызов.
2. **вердикт по нижней кромке листьев, не по документу**: пустые боксы раздувают
   `scrollHeight` на сотни px, не добавляя в кадр ни пикселя; по документу
   такие слайды вечно «лезут». `phantom` различает честно.
3. **консоль и сети — не сюда**: их к `web_drive`; здесь геометрия и кадр,
   «визуально чисто» по-прежнему решает человек (или `image_*`-сравнение).
