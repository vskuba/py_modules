# SVG в растр точного размера: суперсэмплинг вместо «как получится»

> Векторную иконку (Android `drawable/*.xml`, логотип из макета) надо иногда
> получить картинкой: PNG заданного размера с прозрачным фоном. Браузерного
> рендера под рукой нет, а «открыл в ImageMagick и сохранил» даёт зубчатые
> скошенные края на диагоналях. `image_svg_render` рендерит с трёхкратным
> превышением и ужимает LANCZOS-ом — сглаживание считается на большом растре.
> Инструмент — `py_modules/image_` (модуль `image_svg`), CLI:
> `python -m image_.image_svg`. Замерить результат — `image_scan.md`.

## 1. Почему суперсэмплинг, а не один проход

ImageMagick растеризует SVG сам (свой рендерер, без librsvg — его может не
быть), и на целевом размере кривые получаются ступеньками: фильтр сглаживания
там уже не при чём, геометрия успела окраситься в пиксельную сетку. Рендер в
`size × supersample` (по умолчанию ×3) с последующей ужимкой LANCZOS-ом
считает контур на втрое более плотной сетке — край выходит как из браузера.
Цена — временный растр во временном каталоге; удаляется в любом исходе.

## 2. Размер и viewBox

Функция `image_svg_render(svg, out='', size=512, supersample=3)` принимает путь
к `.svg` или саму разметку строкой; `size` — сторона или пара `(w, h)`.
Исходные `width`/`height` снимаются, канвас выставляется в `size ×
supersample`, альфа сохраняется (PNG RGBA, фон прозрачный).

Масштаб содержимого берётся из `viewBox`. Если его нет, но есть числовые
`width`/`height` — `viewBox="0 0 W H"` синтезируется из них. Нет ни того, ни
другого — `ValueError`: масштабировать содержимое нечем, молча рисовать «как
повезёт» хуже честной ошибки.

## 3. `magick` или `convert` — и как не перепутать

Ищется `magick` (v7), потом `convert` (v6). Коварство в том, что `convert` в
Linux — ещё и утилита конвертации файловой системы из util-linux: она есть
почти везде и умеет совсем другое. Поэтому кандидат проверяется вызовом
`-version` по слову `ImageMagick`; не нашли настоящий — `FileNotFoundError` с
текстом, что ставить.

## CLI

```bash
python -m image_.image_svg icon.svg                    # png рядом с исходником, 512
python -m image_.image_svg logo.svg -o /tmp/logo.png --size 1024
python -m image_.image_svg glyph.svg --size 64 --supersample 6
```

## Грабли

1. **Маленький растр даёт «лишние» пиксели по краю фигуры** — ореол
   сглаживания и ringing фильтра добавляют 1–2 px почти невидимых пикселей;
   `image_scan_bbox` на растре 64 px насчитает габарит больше геометрического
   (на 1024 сходится в сотые). Мерить геометрию — на ≥256 и строгим тоном с
   малым `tol`.
2. **Фон прозрачный — это проверка, а не презумпция** — после рендера стоит
   взглянуть, что угол кадра имеет альфу 0: залил рендерер серый фон вместо
   none — значит флаг `-background none` куда-то пропал (в своём коде мимо
   модуля про него забывают первым).
3. **Сложные градиенты и фильтры — как дорисует рендерер** — внутренний
   рендерер ImageMagick не поддерживает половину SVG 2; итоговая истина —
   растр, его и сверяют (`image_scan_bbox`, `image_`-сравнение), а не
   ожидание «как в браузере».
4. **`convert` без слова ImageMagick в версии — не ImageMagick** — util-linux
   утилита отвечает на тот же вызов; проверка модуля сделана, но при ручной
   отладке команды в оболочке это первый кандидат на «команда есть, а
   делает чушь».
