# Page slice — страница списка одним ответом

> Арифметика страниц выглядит на три строки и пишется заново в каждом списке. К
> моменту появления этого модуля она лежала **в шести местах трёх проектов** —
> покупатели, отпечатки, сессии, блоки, намерения, журнал, — и везде чуть
> по-разному.

## 1. Как звать

```python
from page_.page_slice import page_answer, page_slice

bounds = page_slice(page, per_page)          # offset, limit, подрезанный page
rows = await db.fetch(..., bounds['limit'], bounds['offset'])
return page_answer(rows, total, bounds['page'], bounds['per_page'], live=9)
```

| Функция | Контракт |
|---------|----------|
| `page_slice(page, per_page, total=None)` | `{page, per_page, offset, limit, pages}` |
| `page_count(total, per_page)` | сколько страниц; пустой список — одна |
| `page_answer(rows, total, page, per_page, **extra)` | конверт для общего пейджера |

## 2. ⚠⚠ Беда не в объёме, а в краях

Страница меньше единицы, нулевой `per_page`, пустой список, номер больше, чем
страниц, `?page=abc` из адресной строки. Каждая копия ошибается в своём крае, и
ошибка видна не сразу — список просто показывает не то.

| Край | Ответ |
|------|-------|
| пустой список | **одна** страница, не ноль: она существует, просто пуста |
| `page` больше, чем есть | подрезается последней, а не отказ |
| `page=abc`, `per_page=''` | первая страница, умолчание |
| `per_page=100000` | потолок `PAGE_SLICE_PER_PAGE_MAX` |

⚠ Номер подрезается, а не отвергается: человек нажал «вперёд», список за это
время ужался — отказ показал бы пустой экран вместо списка, который никуда не
делся.

⚠ Деление вверх целыми (`-(-a // b)`), а не `math.ceil`: тот переводит в float,
и на миллионах строк последняя страница терялась бы на погрешности.

## 3. Конверт одной формы

`page_answer` собирает то, что ждёт общий пейджер панели
(`dashboard/js/pager.js`): `rows`, `total`, `page`, `pages`, `per_page`,
`shown`. Своя форма у каждого списка означала бы свой пейджер у каждой
страницы — ровно то, от чего уходим.

⚠⚠ `total` в конверте — это **то, по чему считаются страницы**. У списка с
фильтром это найденное, а не вся база; размер базы едет своим полем (`whole` у
покупателей). Положи туда базу — и «вперёд» уводила бы на страницы, которых в
отборе нет.

⚠ `shown` — длина `rows`, а не `per_page`: на последней странице их меньше, и
подпись «показано 50 из 137» на семи строках была бы ложью.
