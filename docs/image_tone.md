# Image Tone — построчный оттенок кадра: профиль и вердикт «полоса»

> Тон плывёт по кадру ступенькой или плавно? `image_tone_rows` считает по
> каждой строке медиану разности каналов по ярким пикселям, `image_tone_band`
> отвечает одним числом: где ступенька и какая. Моды и средние по окну полосу
> мажут — здесь профиль построчный.

## 1. Интерфейс

```python
image_tone_rows(path, rect=None, chan='g-b', min_luma=150, step=7)
# -> {'file', 'chan', 'rect', 'rows': [(y, медиана | None)], 'count'}

image_tone_band(path, rect=None, chan='g-b', min_luma=150, step=7, min_jump=6)
# -> {'band': bool, 'band_y': первая строка нового тона, 'jump': со знаком,
#     'before', 'after', 'max_jump'}
```

`chan` — разность каналов: `g-b` (жёлтизна/синьва), `r-b`, `r-g`. В медиану
строки входят только пиксели с `min(r,g,b) >= min_luma` — текст, тени и
обводки не сдвигают тон фона; строка без ярких пикселей даёт `None`.

```bash
python -m image_.image_tone band slide.webp --rect 120,1550,970,1616 --min-luma 90
python -m image_.image_tone rows a.webp --rect 120,1620,970,1980   # профиль для сверки
```

## 2. Полоса — это ступенька; дрейф меряют профилем

`band` находит максимальный скачок между соседними строками и молчит на
медленном дрейфе — так и задумано: градиент обоев нормален. Жёлтая заплатка,
легшая на одно место, даёт ступеньку и зовётся полосой. Если же тон уползает
постепенно (профиль идёт −9, −5, +5, +15), вердикт «ровно» честный, а мерить
надо **уровень** профиля и сравнивать кадры между собой: два вызова `rows`
на одном окне у «до» и «после» (или у двух слайдов одной пачки) читаются
строка в строку.

## Грабли

1. **Скриншот с телефона темнее того же кадра, запечённого в webp** —
   сравнивать абсолютный RGB бессмысленно, сравнивают разность каналов
   (`g-b`) и её профиль: на тоне это почти не сказывается, на яркости — на
   десятки единиц.
2. **Прозрачность печётся чёрным** — `convert('RGB')` гасит альфу в ноль: у
   слайдов с прозрачным подложием за карточкой за карточку не лезть,
   измерять только внутри карточки (или по снимку экрана, где живой фон).
3. **min_luma=150 не видит полупрозрачное стекло** — тёмные области карточки
   порог отбраивает целиком, строки дают `None`; для стеклянных зон порог
   опускают (на стекле той же пачки рабочий порядок — 90).
4. **Однострочный `band` не чинит то, что лечит `rows`** — ступеньки нет,
   есть дрейф; не опускать `min_jump` до шума, а сверять профили двух кадров.
