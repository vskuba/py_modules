# Image Glass — стеклянная плитка: прозрачный webp с полупрозрачной пластиной

> Карточка должна быть полупрозрачным стеклом поверх живых обоев, а не
> непрозрачной заплаткой? `image_glass_plate` печёт RGBA-подложку: вне
> скругления — ноль альфы, внутри — заливка с альфой, по контуру — тёмная
> кромка; `image_glass_bake` кладёт сверху глифы из дампа и сохраняет
> lossless-webp. Цвет заливки берут не на глаз, а стеклянным контрактом из
> `image_tone.md`.

## 1. Интерфейс

```python
image_glass_rounded_mask(size, rects, radius, ss=4)      # -> (h, w) float 0..1, край мягкий
image_glass_rim_mask(size, rects, radius, rim_w=2, ss=4) # -> кольцо: внешняя маска минус внутренняя
image_glass_plate(size, rects, fill, radius=0, rim=None, rim_w=2, ss=4)   # -> PIL RGBA
image_glass_bake(src, out, rects, fill, radius=0, rim=None, rim_w=2, ink=True,
                 ink_offset=10, ink_slope=30.0, crop=None, ss=4)
# -> {'out', 'size', 'bytes', 'alpha_share', 'rects'}
```

Плиты `rects` — прямоугольники холста пикселями, холл берётся с размера
источника. Заливка и кромка — `(r, g, b, a)` с альфой 0..255 **как она
хранится в webp** (не процент). Кромка `rim=None` — без неё; рабочая
настройка стекла пачки — `rim=(0, 0, 0, 12)` шириной 2 px: живая карточка
закончена тёмным чётким обводом, светлая рамка подделывает оригинал.

```bash
python -m image_.image_glass dump.png tile.webp \
    --rects 86,325,992,960\;86,982,992,1616 --fill 190,218,190,69 \
    --radius 40 --rim 0,0,0,12 --crop 0,91,1080,2077
python -m image_.image_glass dump.png plain.webp --rects 0,0,100,50 --fill 190,218,190,69 --no-ink
```

## 2. Куда это в работе

Стеклянная карточка в клоне интерфейсов: пиксельная картинка поверх живого
фона не умеет следовать обоям — на светлой фазе обоев заплатка белее окружения,
на тёмной чёрнее, и глаз видит квадрат. Правильный ответ — RGBA: плита с
альфой, WebView сам подмешает обои.

Цвет и альфу не подбирают на глаз — решают стеклом из тонового контракта
(`image_tone.md`, § «одной строкой»): меряют живой дельтой
`image_tone_row_delta` оригинала, решают `image_tone_glass_solve(bg, delta,
alpha)` — он отдаёт fill; после сборки сверяют живым снимком клона
`image_tone_glass_verify`. Альфу берут ту, что держит форму глифов: чем
меньше альфа, тем сильнее почернение «дотягивает» полупрозрачность, и
компромисс проверяют на кромке текста.

Слой глифов (`ink=True`) поднимает из источника всё, что темнее фона плиты:
медиана яркости поля принимается за «стекло», `ink_offset` — с какого
почернения у глифа появляется альфа, `ink_slope` — при каком он непрозрачен.
Фон карточки (ровно медиана) даёт альфу ноль и не портит пластину; поэтому
окна полей для замеров и медиана глифов смотрят в один и тот же дамп.

## Грабли

1. **Потерочный WebP на малой альфе рисует тёмную бахрому по скруглению** —
   сохраняем всегда `lossless=True, exact=True` (встроено в `bake`); с q90
   край стекла лесенкой из чёрных точек, и «почини альфу» тут не поможет —
   теряется интерполяция цветов под прозрачностью.
2. **RGB под альфой=0 — чёрный после композита** — `alpha_composite` гасит
   цвет там, где оба слоя прозрачны; браузер, толкующий файлы как
   premultiplied, покажет тёмную дымку вокруг всей плиты. `bake` и `plate`
   перекрашивают пустоту под цвет заливки (`_fill_under_alpha`).
3. **Жёсткая маска по скруглению читается лесенкой** — Pillow рисует радиус
   дугой без полутонов, а на 25%-альфе каждая ступень видна; маска рисуется
   ×4 и ужимается BOX — край становится мягким на 4–5 px, как в оригинале.
4. **`img.alpha_composite(over)` без присваивания портит базу** — метод
   меняет приёмник и возвращает `None`; compose — модульная функция
   `Image.alpha_composite(base, over)`, и только её результат идёт дальше.
5. **Без ink фон дампа печётся «стеклом с текстом-призраком»** — глифы
   дампа сами по себе имеют альфу заливки и проступают серым; слой `ink`
   поднимает их до непрозрачности. Чистый же фон плиты (медиана) подняться
   не должен — поэтому порог считается от медианы поля, а не от константы.
