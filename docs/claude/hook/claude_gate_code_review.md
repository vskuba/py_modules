# Застава ревизии кода после правки — код нарезан по трём файлам, сверь с правилами

> Правила, которые она сторожит, — `docs/code_rules.md`: тот же функционал не живёт в
> двух файлах, DDD / SOLID / GRASP и имена по правилу префикса, латиница в идентификаторах,
> приватные ниже публичных, мёртвый код удалён, документация актуальна. Пока правка лежит
> в одном файле, её видно глазами вместе с правкой; на трёх файлах изменение перестаёт
> читаться как целое — и ровно на этом размере «гляну потом» не наступает никогда.

## 1. Точка `PostToolUse`: правку не отменить

`PreToolUse` на `Write`/`Edit`/`NotebookEdit` занят заставой
`claude_gate_tool_exists_check`, поэтому эта стоит **после** записи. Отсюда два правила,
которых нет у застав отмены:

* замечание приходит агенту как ответ на **успешный** вызов — в тексте прямо сказано
  «правку не отменять, она удалась, её надо посмотреть»;
* зовётся застава на **каждую** правку, десятки раз за сессию; порог и память устроены
  так, чтобы из десятка вызовов голос прозвучал один раз на партию правок.

Сорванная правка сюда не приходит вовсе: `Edit`, не нашедший строку, уходит в
`PostToolUseFailure`. То есть партия считается по состоявшимся записям, а не по попыткам.

```json
"PostToolUse": [{"matcher": "Write|Edit|MultiEdit|NotebookEdit",
  "hooks": [{"type": "command",
    "command": "/usr/bin/python3 /home/vasyl/PycharmProjects/py_modules/claude_/hook/gate/claude_gate_code_review.py",
    "timeout": 60}]}]
```

⚠ Соседство с `claude_gate_tool_exists_check` — не дубль, а два разных вопроса: та
отменяет **первое** прикосновение к файлу, пока не показано, чем это уже делают; эта
смотрит на **итог** партии, когда файлы уже написаны. На одном ходе работают обе.

## 2. Партия = три файла, о которых ещё не говорили

Счёт идёт по **файлам, а не по нажатиям**: десять правок в одном файле — одна правка
глазами, три файла — уже изменение. Застава собирает файлы кода от начала транскрипта
(`claude_hook_tool_calls` поверх хвоста `.jsonl`), плюсует файл текущего вызова — до
строк транскрипта он ещё не доехал — и вычитает файлы, о которых уже говорила. Не
набралось трёх — молчит; набралось — спрашивает и дописывает партию в память под id
сессии, чтобы следующий вызов спрашивал о новых файлах, а не пережёвывал эту.

    CLAUDE_GATE_CODE_REVIEW_SEEN → ~/.cache/claude_gate_code_review_seen.json
    {сессия: {'asks': N, 'seen': [файлы партии], 'at': epoch}}        # живёт сутки

Три вопроса на сутки (`CLAUDE_GATE_CODE_REVIEW_ASKS`), дальше — тишина. Без вычитания
застава кричала бы на каждую правку после третьей; с одним лишь счётчиком придирок
молчала бы до конца суток после первого вопроса.

⚠ Транскрипт читается хвостом (`…_ROWS = 800` записей), поэтому **состав партии держится
в памяти, а не выводится из окна**: в долгой сессии первые файлы вываливаются из хвоста,
и без `seen` застава пересчитывала бы их заново на каждом вызове.

⚠ Файлы, не попавшие в код (`.md`, `.json`, `.html`), в партию не входят намеренно:
правка текста и правка страницы — не правка функционала, у них свои заставы
(`claude_gate_tool_exists_check`, `claude_gate_design_review_live`). `.ipynb` — код:
блокнот правят `NotebookEdit`, и разъезжается он по файлам не лучше модуля.

## 3. Что застава считает сама

Два пункта из семи имеют машинную формулировку — застава считает их **до** того, как
открыть рот, и кладёт находки в текст: `tool_typo_cyrillic` (§1.2, кириллица в именах и
ключах) и `function_order` (§3, порядок определений) по `.py`-файлам партии. Цена — один
`ast` на файл; без них агент тратит круг на то, что уже посчитано.

⚠ Кириллицу судит `tool_typo_cyrillic`, а не `variable_cyrillic`: первому видно **само
имя** функции или ключ словаря, второй смотрит имена внутри тела — файл с
`def ai_лицо()` и латиничным телом прошёл бы мимо.

Находки `.js`, `.php` и прочего не-`.py` деревом не видны — там остаются grep-шаблоны
§1.2, их застава называет словами.

## 4. Чего застава не решает

Размазан ли функционал, на месте ли предметная область, жив ли оставленный правкой код,
не обещает ли док удалённого — застава **не судит**: контекста правки у неё нет, а ложный
вердикт «размазано» стоит дороже молчания. Она перечисляет файлы и проверки
(`tool_.tool_impact`, `tool_.tool_find`, `tool_.tool_import`, `tool_.tool_dead`,
`commit_.commit_scope`); смотрит тот, кто правил.

### ⚠⚠ Орфография (пункт 7) названа командой, хотя машинная

`dictionary_spell_check_ru` ловит опечатки ровно в том слое, который правят эти же
вызовы, — в докстрингах и комментариях. Считать его здесь всё равно нельзя, и причин
две:

1. **Он работает по корпусу, а не по файлу.** Опечатку от термина отличает замена,
   частотная в репозитории; на одном файле частот нет, и проверка не ошибается, а
   **молчит**. Звать её «по файлам партии», как `tool_typo_cyrillic`, бессмысленно по
   устройству.
2. **Полный прогон — 5,7 с** против долей секунды у `ast`-проверок, а застава
   срабатывает на каждой партии правок.

Поэтому пункт стоит в одном ряду с судейскими: команда названа, смотрит тот, кто правил.
Своё слово ремесла, которого нет в словаре, кладут в `.spell-allow` корня — иначе оно
будет всплывать находкой у каждого.

## Грабли

1. **Своя поломка и неразобранный ввод отпускают вызов** (договор — `claude_hook.md`):
   на `PostToolUse` держать нечего, инструмент уже отработал
2. **Незаписанная память = повтор вопроса.** Сбой записи глотается (`claude_gate.md`), и
   в среде с недоступной на запись `~/.cache` застава держит каждую новую партию заново.
   Там, где память живая, вопрос звучит один раз на партию
3. **Точка `PostToolUse` зовётся на каждую правку** — порог по файлам, а не по вызовам,
   иначе голос звучал бы на каждом нажатии
4. **Клапан на один вызов**: `CLAUDE_GATE_CODE_REVIEW_PASS=1`, без правки конфига
5. **Правка в `py_modules` без хода указателя submodule рассинхронит живые сессии с
   сюитой** — застава исполняется по пути из `~/.claude/settings.json`
