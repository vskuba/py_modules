# Заставы — что стоит на пути агента

> Застава не просит помнить правило, она встаёт на пути: запись, правка, выкладка, конец
> хода — и молчит, пока есть на что придираться. Здесь договор, политика и четыре
> заставы целиком; проверки, на которые они зовут (`tool_instead`, `deploy_precheck`,
> `frontend_check_rules`), описаны у своих модулей.

| Файл | О чём |
|------|-------|
| `claude_hook.md` | договор хука: stdin JSON, решение кодом возврата, разбор ввода и хвост транскрипта — одним модулем на все заставы |
| `claude_gate.md` | политика прерывания: клапан, бюджет придирок, память на сутки |
| `claude_gate_tool_exists_check.md` | застава записи кода: покажи, чем это уже делают, и отмени одну попытку |
| `claude_gate_deploy.md` | застава выкладки: узнай команду выкладки по тексту и не пусти с находками «стоп» |
| `claude_gate_design_review_live.md` | застава конца хода: правка вёрстки без снятого кадра — гипотеза, а не работа |
| `claude_gate_code_review.md` | застава после правки: код нарезан по трём файлам — сверь затронутое с `code_rules.md`, правку не отменяя |

## Как вешаются

Заставы вписаны в `~/.claude/settings.json` — он глобальный, поэтому работают во всех
проектах сразу. В `command` путь пишется полным, а `python` — **системным**: хук
запускается вне проекта, и `.venv` конкретного проекта ему недоступен.

## В DSH те же заставы

Код, написанный в DSH, проходит тот же путь только если смонтирован мост
`@deepseek-ai/dsh-hooks-claude-code`: он читает `~/.claude/settings.json` и зовёт те же
команды на швах перехвата харнеса. Два шага: пакет —
`dsh plugin --profile web add @deepseek-ai/dsh-hooks-claude-code`, строка в
`~/.dsh/profiles/web/cordis.patch.yml` — **списком `insert:`**, а не голой `- id:`
(грабля 6 в `claude_hook.md`), с `configPath: ~/.claude/settings.json`. Видно ли мост в
профиле — `dsh --profile web --dump-config | grep hooks-claude-code`.

⚠⚠ Без моста в DSH не работает **ни одна** застава: настройки Claude Code харнес не
читает вовсе, и молчание выглядит как «придираться не к чему». Та же тишина стоит за
ногой `- id:` без `insert:` — профиль её молча теряет.

⚠ Мост читает `settings.json` **один раз — когда применяется профиль**: правка настроек
(новый матчер, новая застава) живёт в DSH, только когда профиль применится заново — после
правки `cordis.patch.yml` или рестарта харнеса. В Claude Code та же правка действует со
следующего хода.

⚠ `PostToolUseFailure` мост не поддерживает, `tool_response` приходит сплюснутым в
текст, а `transcript_path` — пустой: заставы, которым нужен разбор хода, читают журнал
DSH сами (`claude_hook.md`, §5). Матчеры в `settings.json` от этого перечисляют имена
инструментов в обоих регистрах.

## ⚠⚠ Застава исполняется из той выкачки, чей путь прописан в settings.json

…а сюита проекта проверяет копию подмодуля на закреплённом коммите. Правка заставы
без хода указателя значит, что живые сессии уже работают по-новому, а тесты проверяют
старое: двигайте указатель вместе с правкой.
