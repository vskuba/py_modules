# Застава выкладки — не пусти команду выкладки с непройденными проверками

> События `pre_deploy` в Claude Code нет: выкладка для хуков — обычный запуск `Bash`,
> ничем не отличимый от `ls`. Застава стоит на каждом `Bash`, смотрит **текст команды**
> и просыпается только на приметах выкладки; проверки гоняет `deploy_precheck` (см.
> `docs/deploy_precheck.md`).

## 1. Порядок, а не список функций

Застава отвечает за секунды — иначе её снимут вместе с пользой: она не гоняет сюиту,
не смотрит прод, не ходит в базу.

    команда без приметы выкладки → выход мгновенный, молча
    выкладка, проверки чисты       → код 0, агент ничего не заметил
    выкладка, есть находка «стоп» → код 2, команда не запускается, отчёт в stderr

## 2. Приметы ищутся только в позиции команды

Список примет короткий (`--marks` печатает их), но ошибка в нём либо глушит заставу,
либо мешает каждой второй команде. Примета шире нужного — застава лезет в каждую
вторую команду; уже нужного — выкладка уходит непроверенной.

⚠ Без привязки к позиции (`CLAUDE_GATE_DEPLOY_HEAD`: начало строки или после
разделителя команд) застава ловила сама себя: `echo "…git push…"` — это `echo`, а не
выкладка, и первая же проверка заставы оказалась заблокирована собственной приметой.

⚠ Сюда попадает только то, после чего код оказывается **на проде**. Коммита здесь нет:
он ничего не выкладывает, а застава на каждом коммите — это застава, которую снимут
к обеду. Отправка в удалённый репозиторий — есть: у этих проектов `py_modules`
подмодулем, и порядок отправок значим (сперва общий слой, потом проект).

## 3. Проверяется репозиторий, в котором команда вправду выполнится

Хук получает `cwd` сессии; переход `cd`/`-C` в подмодуль перед отправкой читается из
самой команды (берётся **последняя** смена каталога), и корень git ищется `rev-parse`,
а не поиском `.git` вверх по дереву: у подмодуля `.git` — файл со ссылкой, и наивный
поиск отдал бы родителя. Иначе первая же отправка общего слоя встала бы из-за долга
чужого репозитория.

## 4. Памяти о придирках нет — намеренно

Выкладку повторяют до успеха, и «второй раз пропускаем» означало бы «выложить
непроверенным со второй попытки». Здесь работает только клапан
`CLAUDE_GATE_DEPLOY_PASS=1` (см. `claude_gate.md`).

## Грабли

1. **Код `2`, не `1`**: единица для хука значит «сам хук сломался», и вызов при ней
   проходит — замечание до агента не дойдёт
2. **`--marks` — не украшение, а часть устройства**: список проверяют руками тем же
   способом, которым он устроен, потому что обе ошибки в нём невидимы

## Чем проверить

```bash
python3 py_modules/claude_/hook/gate/claude_gate_deploy.py --marks   # список примет
echo '{"tool_name":"Bash","tool_input":{"command":"git push"}}' \
  | python3 py_modules/claude_/hook/gate/claude_gate_deploy.py       # выход 0 или 2
python -m pytest tests/test_claude_gate_deploy.py
```
