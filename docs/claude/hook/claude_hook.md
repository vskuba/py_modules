# Claude Hook — договор хука Claude Code одним местом на все заставы

> Хук получает на stdin JSON с именем инструмента и его доводами, а отвечает кодом
> возврата. Договор короткий, но в нём три места, где легко навредить, и все три
> одинаковы у любой заставы — поэтому они здесь, а не в каждой заставе отдельно.

## 1. Как устроен ответ

| Код | Значение |
|-----|----------|
| `0` | пропускает: вызов идёт, агент ничего не заметил |
| `2` | отменяет вызов, `stderr` уходит агенту замечанием |

⚠ Не `1`: единица для хука значит «сам хук сломался», и вызов при ней проходит —
замечание до агента не дойдёт вовсе.

⚠ На `PostToolUse` двойка **ничего не отменяет** — инструмент уже отработал, и `stderr`
приходит агенту замечанием к состоявшемуся вызову. Проверяющему это меняет одну формулировку:
не «не пущу», а «правку не отменять, её надо посмотреть»; так делает
`claude_gate_code_review`.

Функция проверки получает разобранный ввод и возвращает **текст замечания**; пустая
строка значит «пропустить». Ни кодов возврата, ни `stderr`, ни разбора JSON она не
касается — этим занят этот модуль целиком.

## 2. Три места, где застава обязана пропускать

    сломанный ввод   → пропустить, а не упасть
    своя ошибка      → пропустить, а не запретить всё
    не тот инструмент→ выйти мгновенно

Сломанный хук, запрещающий всё, останавливает работу целиком и необъяснимо для
человека; непроверенная запись — беда меньшая, и её видно. По той же причине ввод,
который не разобрался, — не «подозрительный вызов», а сломанная труба: пропускается
молча. Исключение внутри проверки превращается в строку в `stderr` и код `0` —
текст при этом печатается: молчащая сломанная застава хуже видимой.

## 3. Точка `Stop`: инструмента нет, а договор тот же

Застава на закрытии хода приходит без `tool_name` и `tool_input`: отменять нечего,
под вопросом сам конец хода. Для неё `claude_hook_stop_run(look)`.

⚠ `Stop` зовётся на **каждый** конец хода, а возвращённый ход идёт с той же заставой
заново — она зовёт саму себя. Ввод несёт `stop_hook_active: true` на возвращённых
ходах; политику придирок читает застава по своей метке, а не по флагу: флаг значит
лишь «ход уже возвращали», а предел — сколько раз мы успели спросить.

## 4. Транскрипт — только хвост

Заставе на `Stop` смотреть нечего, кроме транскрипта: `claude_hook_transcript_rows`
читает последние килобайты `.jsonl` и отдаёт разобранные строки от старых к новым.
Живые транскрипты наработаны до 154 МБ: прочитанный целиком, один такой встанет на
десятки секунд на каждом конце хода. Окно меряется **байтами**, а не строками: строка
с выводом инструмента весит мегабайты. Обрезанную слева строку модуль отбрасывает
молча — это не поломка файла.

Поверх строк — `claude_hook_tool_calls(rows)`: вызовы инструментов из этих записей,
`{'name', 'input', 'at'}`, в порядке хода. Обход `message.content[]` с отбором `tool_use`
— единственная работа, которую две заставы (`claude_gate_design_review_live`,
`claude_gate_code_review`) делали порознь, и третьей разбор добавлять уже незачем.

⚠ Отметка `at` — строка `timestamp` из записи, а не число: порядок оставляет судить
заставе, ей известно, что именно она сравнивает (у вёрстки — «правка после кадра»).

## 5. Харнесов два: Claude Code и DeepSeek Harness

Заставы пишутся один раз и работают в двух харнесах. Разницу между ними модуль
закрывает собой — застава не знает, где она оказалась:

- **имена инструментов**: DSH пишет их строчными (`edit`, `bash`), Claude Code — с
  заглавной. Сравнение через `claude_hook_is_tool(name, tools)` — без учёта регистра;
  `claude_hook_wanted` опирается на неё, поэтому `settings.json`-матчер обязан
  перечислять обе формы (матчер смотрит пословно, регистра не знает).
- **журнал**: `transcript_path` мост DSH заполняет пустой строкой — пути на шве
  персистентности не видны, а журнал сжат. Файл находится по `session_id`:
  `~/.dsh/sessions/<slug>/session-<uuid>/session.v*.jsonl.zstd`; отдаёт его
  `claude_hook_journal_path(data)` — готовый путь Claude Code или найденный журнал DSH.
- **форма записей**: в журнале DSH вызов — строка `{'type': 'tool/call', 'data': {...}}`
  с `name` и `arguments` (аргументы — JSON строкой). `claude_hook_tool_calls(rows)`
  разбирает обе формы, застава видит тот же `{'name', 'input', 'at'}`.
- **хвост сжатого журнала** читается `zstd -dc | tail -c`: разжимать журнал целиком
  на каждом вызове — то же расточительство, что читать транскрипт без окна.

⚠ Журнала нет, `zstd` в машине нет, `session_id` не найден — пустой список, застава
молчит. Молчание здесь нарочное: сломанная заставка обязана пропускать, а не держать
(`docs/claude/hook/claude_gate.md`).

## Грабли

1. **Клапан заставы — не аргумент, а окружение процесса**: `CLAUDE_GATE_*_PASS`
   проверяется в момент вызова; выставленный в общей оболочке, он снимает заставу со
   всего, что в ней запускается
2. **`limit` ноль или меньше отдаёт пустой список**, а не «все»: отрицательный срез в
   Python отдал бы весь хвост, и застава разобрала бы мегабайты вместо ничего
3. **Пустое имя инструмента — не наш случай**: так выглядит неразобранный ввод, и
   решение о пропуске принимает обвязка, а не проверка
4. **`session_id` в DSH — это уже имя каталога**: харнес называет сессию
   `session-<uuid>` и тем же id подписывает её. Искать каталог по `session-{id}` —
   получить `session-session-<uuid>` и молчать вместо работы; ищутся обе формы
5. **Матчер `settings.json` — не Python**: мост сравнивает список имён пословно и без
   регистра; строчное `edit` из DSH не попадёт в группу, пока в списке нет и строчной
   формы
