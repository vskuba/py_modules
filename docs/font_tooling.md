# Шрифты — чем смотреть, чем сверять, чем проверять покрытие

> Шрифт смотрят структурно (`font_info`: формат, upem, глифы, имена) и
> пиксельно (`font_text_diff`: одна строка двумя шрифтами). На вопрос «это
> тот же шрифт?» отвечают `font_compare` — контуры, нормированные по
> unitsPerEm, потому что подмножества перекодируются и масштабируются.
> Инструмент — `py_modules/font_`, CLI: `python -m font_.font_`.

## 1. Анатомия: паспорт через `font_info`

`font_info(path)` даёт: формат (`CFF` — PostScript-контуры, `TrueType` —
glyf), `upem` (единиц на em: 512, 1000, 2048 — все честные), число глифов,
`ascender`/`descender` из hhea, имена, признак подмножества (префикс
`ABCDEF+`), число cmap-символов.

Порядок вопросов к незнакомому файлу:

1. **Имя, а не файл** — файловое имя ничего не значит, доверять полям
   `family`/`postscript` из таблицы имён.
2. **Формат и upem** — определяют, каким способом его можно сверять (§2).
3. **Покрытие** — `font_coverage(path, текст)` для всего текста, который
   шрифт должен обслужить; для многоязычных строк — построчно.

## 2. «Это тот же шрифт?»: три проверки по возрастанию стоимости

1. **`font_compare` — контуры.** Набор глифов (без `.notdef`) и совпадение
   контуров общих глифов, нормированных по upem каждого. Держит главный
   случай: подмножество вложенное движком печати, где контуры те же, но
   переписаны (CFF→glyf) и домножены вместе со сменой upem. Поле `formats`
   предупреждает: у разных форматов кривые описаны разными командами
   (квадратичные против кубических) — тогда контурное сравнение не читается.
2. **`font_text_diff` — растр.** Одна строка, нарисованная обоими шрифтами
   по общей базовой линии (`anchor="ls"`), и статистика разницы. Доли
   процента — округление растеризатора; проценты — формы разошлись.
3. **`font_render_text` + глаз** — рядом положить PNG, смотреть кернинг и
   конкретные глифы.

## 3. Чек-лист сверки шрифта с мастером

1. `font_info` обоих: формат, upem, имена — расхождения запомнить.
2. `font_coverage` мастер-файлом по всему целевому тексту.
3. `font_compare(мастер, кандидат)` — `only_a/only_b` (не тот набор?),
   `outlines_differ` (те ли контуры).
4. Форматы разные или кандидат — подмножество из PDF: `font_text_diff`
   длинной мнемонической строкой, `out-dir` для глазной проверки.
5. Порог: `pct_pixels.pct` < ~2 — один рисунок; выше — смотреть diff.png.

## Грабли

1. **Подмножество в PDF — не мастер**: движок печати перекодирует CFF в glyf
   и меняет upem (512 → 2048, координаты ×4). Сравнение таблиц/глифов
   исходных файлов с вложенным subset лжёт — только нормированные контуры
   или растр (`font_compare` это и делает).
2. **Метрики между upem несопоставимы** — ascender 514 при upem 512 и 2004
   при 2048 — один и тот же шрифт; делить на upem до сравнения.
3. **Формат решает язык контуров**: glyf — квадратичные кривые, CFF —
   кубические; между форматами посимвольное сравнение команд бессмысленно,
   спорит растр.
4. **Растровое сравнение без общей базовой линии** даёт разницу метрик
   вместо разницы рисунка — рисовать `anchor="ls"` и холст фиксированного
   размера.
5. **Имя файла врёт** — «card.ttf» оказался чужим именем официального
   шрифта; вывод по `postscript`/`family` и контурам, не по имени.
6. **Число глифов ≠ покрытие**: у сабсета глифы могут быть, а cmap — нет
   (и наоборот); проверять `font_coverage` именно по целевому тексту.
