# http_card — карточка «запрос → ответ» картинкой, с метками по JSON-пути

> HTTP request response card для тикета или отчёта: метод, адрес, заголовки,
> тела запроса и ответа в один кадр, на полях — красные рамки с подписями. Кадр
> собирает headless Chromium (`http_shot`-раскладка), секреты вычищаются до
> записи файла, метки ищутся по JSON-пути, а не «третья строка слева».

## 1. Вызовы

| Вызов | Для чего |
|-------|----------|
| `http_card_render(spec, out, ...)` | spec-файл целиком → PNG; вернёт `{'out', 'marks'}` с флагом `found` на каждую метку |
| `http_card_html(spec, mask=())` | только HTML карточки — без браузера, тот, что увидит печать; на нём и строятся тесты |
| `http_card_mask(value, mask=())` | замазать структуру данных по тем же правилам, не собирая карточку |

```python
http_card_render(json.load(open('card.json')), 'card.png', forbid=['values.txt'])
```

CLI — `python -m http_.http_card --spec card.json --out card.png [--forbid secrets.txt]`;
метка, не нашедшая адресата, — код возврата 2: картинка нарисована, но врать в
ней нечего, рамку ставить не на что.

## 2. Что маскируется

Карточка попадает в публичный тикет, поэтому секрет затирается везде, где он
может лежать, а не только в теле:

- **имена ключей** — `authorization`, `x-api-key`, `api_key`, `api_token`,
  `apikey`, `secret`, `encryption_key`, `password`, `token`, `signature`,
  `cvv`/`cvc` — без учёта регистра и раскладки (`API_KEY` = `api-key`), на любой
  глубине → `••••••`; список = `HTTP_SHOT_MASK` + `DATA_MASK_SECRET_KEYS` + пара
  коротких имён из конфигов stage-контуров;
- **query и URL целиком** — `?signature=…` в адресной строке и `signature=`
  внутри строки `continue_request.uri` замазываются по имени параметра:
  подписанный callback-урл в кадре — это готовая подделка уведомления;
- **номер карты** — `••••••••••••4242`: маскируется всё, кроме last4;
- **`--forbid`** — последние значения из настроек: если хоть одно осталось в
  собранном HTML, PNG не пишется вообще.

## 3. Метки ищутся по пути, а не по порядку

`{"path": "$.fiat_data.amount"}` или `{"path": "response.$.description"}`.
Путь разбивается на шаги (`items[2].id` — три шага), каждая строка pretty-JSON
помнит свой кортеж шагов, якорь `data-m="N"` надевается на строку-владелицу —
после чего `bounding_box()` из Playwright даёт рамке координаты. DOM-порядок в
этом участвует ровно как порядок обхода: прошлая реализация сшивала метки со
строками по индексу, и первая же пара одинаковых полей (`amount` в запросе и в
ответе) сдвигала все рамки на карточке. Отсюда же sides: `request.` /
`response.` уточняют сторону, голый `$.x` ищется сначала в ответе.

## 4. Грабли

- ⚠ `found: false` у метки — не тишина: правь путь или сторона, иначе кадр
  вводит в заблуждение (метка названа, рамки нет).
- ⚠ Маска смотрит на имена, `--forbid` — на значения; это два независимых
  сторожа, `forbid` подменяет собой отсутствие нужного имени в списке.
- ⚠ Фигурные скобки пути — JSONPath-подобный минимум (`шаг`, `[индекс]`),
  фильтры и `..` не обещаны.
- ⚠ Две метки на соседних строках длинного тела: `image_arrow` ищет плашку
  справа на высоте строки (право-первым), иначе scoring увёл бы обе вниз кадра
  и стрелки пересеклись бы через весь JSON — метка должна оставаться у своей
  строки.
