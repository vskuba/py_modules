# Frontend Rules — серверный рендеринг админки

> Страницы собираются шаблонизатором на сервере, JS — обычные файлы без сборки,
> зависимости лежат локально. Никакого бандлера, никакого CDN.

## 1. Почему без сборки

Админка — не продукт, а инструмент. Отсутствие шага сборки означает: правка шаблона
видна после `F5`, и нет пайплайна, который может сломаться отдельно от приложения.

Практическое следствие, которое надо помнить всегда:

| Что изменил | Нужен ли рестарт приложения |
|-------------|----------------------------|
| шаблон (`.html`) | нет |
| статика (`.js`, `.css`) | нет, но нужен сброс кэша браузера |
| серверный код | **да** |

«Поправил, не применилось» — почти всегда забытый рестарт.

## 2. Структура страницы

- **базовый шаблон** с блоками (`title`, `content`, `styles`, `scripts`) — страница
  наследует его и не дублирует обвязку
- **роуты HTML** отдельно от роутов JSON (см. `api_rules.md`)
- страница не содержит бизнес-логики: она грузит данные из API и рисует

## 3. Регистрация в меню

Если навигация строится из карты «URL → раздел», то **страница, которой нет в карте,
выпадает из меню или попадает не в тот раздел**. Это не автоматика: добавил страницу —
допиши её в карту. Пункт в чек-листе ниже существует именно из-за этих грабель.

## 4. Стили

Общей библиотеки классов может не быть — тогда стили пишутся **в самой странице**, и это
осознанный выбор, а не недоделка: страницы независимы, правка одной не ломает другие.
Цена — дублирование.

Правила, если библиотеки нет:

- не заводить «почти общий» класс в одной странице, надеясь на переиспользование
- общими делать только те примитивы, которые реально нужны везде (лейаут, таблица, форма),
  и тогда — явным общим файлом, а не копированием
- в проектной документации зафиксировать, какой из двух подходов принят

## 5. Зависимости — локально, без CDN

Библиотеки складываются в статику репозитория. Причины: работа без интернета, отсутствие
внешней точки отказа, отсутствие утечки факта посещения админки третьей стороне,
воспроизводимость версии.

## 6. Общие JS-модули

Повторяющееся поведение (загрузка конфига, форматирование времени, обёртка над fetch,
тосты, подтверждения) — в общие модули, а не копипастой в каждую страницу.

**Инициализация обязательна.** Типичная ловушка: модуль форматирования времени требует
явной инициализации (загрузить таймзону), и **без неё молча показывает UTC**. Ошибки нет,
цифры есть, они неверные. Такие модули документируются с обязательным вызовом
инициализации, а страница без него считается сломанной.

## 7. Чек-лист новой страницы

1. Шаблон наследует базовый; свои стили и скрипты — в соответствующих блоках.
2. HTML-роут добавлен в модуль страниц с проверкой прав.
3. **URL добавлен в карту меню** (иначе страницы не будет в навигации).
4. Данные берутся из существующих API; новые эндпоинты — по `api_rules.md`.
5. Вызваны инициализации общих модулей (таймзона, конфиг).
6. Проверено под ограниченной ролью: элементы, требующие прав, скрыты **и** запрещены
   на сервере (скрыть кнопку — не защита).

## Грабли

1. **Забыт рестарт после правки серверного кода** — «изменения не применились»
2. **Страница не в карте меню** — недоступна из навигации
3. **Не вызвана инициализация таймзоны** — время в UTC без единой ошибки в консоли
4. **Кэш браузера** — старая версия JS, отладка несуществующего бага
5. **Права проверены только в UI** — endpoint остался открытым
6. **Библиотека с CDN** — админка не работает без интернета и зависит от чужого хоста
