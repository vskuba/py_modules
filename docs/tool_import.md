# Tool import — импорты, которые никто в файле не читает

> `tool_/tool_import.py`: файл целиком на AST — имя каждого импорта и вопрос,
> встретилось ли оно ещё хоть раз в этом же файле. Не определения (за них
> `tool_dead`), а провода: обещания зависимостей, которые никто не потянул.

    PYTHONPATH=py_modules python -m tool_.tool_import src
    PYTHONPATH=py_modules python -m tool_.tool_import . ; echo $?   # сторож

Код возврата — число кандидатов.

## 1. Зачем

Мёртвый импорт врал читателю дважды за одну сессию: `import random` в файле,
где долю обращения убрал жребий у соседа, и `site_setting` в модуле, который
перестал читать настройки после переезда доли в шаг `dice`. Оба нашли руками
и случайно, попутно с другой работой; линтеров в рабочих образах нет.

Отличие от `tool_dead` принципиальное, и merging их портит оба: тот судит
определения **по всему репозиторию** (у имени столько зовущих, сколько оно
запомнило адресов), а импорт проверяется **внутри своего файла** — он не
определение, а обязательство перед этим же файлом. У вердиктов разные
основания и разная цена ложного срабатывания.

## 2. Устройство

Порядок одного файла: разобрать дерево → собрать прочитанные имена → выписать
импорты → оставить те, чьего имени в прочитанных нет.

Прочитанным считается:

- любое вхождение `ast.Name` — `json.dumps` читает `json`, декоратор читает
  декорируемое, строка ф-строки читает имена внутри `{}`;
- имя в `__all__` — реэкспорт как осознанное использование;
- обе ветки `try: import x / except ImportError: x = None` — имя встречается,
  живы обе, нет — мертвы обе; судится именно имя, а не строка импорта.

Сознательно вне суда:

| Что | Почему |
|-----|--------|
| `__init__.py` | реэкспорт — идиома пакета, читает другой файл |
| `from __future__` | обязано молчать, имени не даёт |
| `import *` | имен не называет, судить нечего |
| `# noqa` на строке импорта | штатная лазейка для импорта ради побочного эффекта |

## Грабли

⚠ **Имя, собранное строкой, невидимо**: `getattr(mod, 'x')`,
`importlib.import_module`, реестры каркасов. Отчёт — список кандидатов:
решает человек или сторож сюиты, а не этот модуль; для известных мест —
`# noqa`.

⚠ **Суд — файл целиком**, имя из другого файла здесь не нужен вовсе: импорт,
нужный только соседнему модулю по `from модуль import имя`, законно мёртв у
нас и живёт в том соседнем — звать его должен `tool_dead`, не этот.

⚠ **`skip` в `file_walk` заменяет штатный список, а не дополняет**: первая
версия передала свои три имени и сорок секунд изучала `site-packages` вместо
дерева проекта. К `FILE_WALK_SKIP` дописываем, не перезаписываем.

⚠ **Синтаксическая ошибка в файле — пропуск молча**: инструмент вспомогательный
и падать из-за чужой недописанной правки не должен; битый файл не увидит никто,
но и отчёт не потеряется стопкой исключений.
