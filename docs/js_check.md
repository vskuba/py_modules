# JS цел как браузерный модуль: парсинг ESM, адрес поломки, граф импортов

> Страница мертва, `node --check` молчит, стек пуст — потому что CommonJS-парсер
> node не видит поломку, которая браузеру (ESM) видна, а у непарсящегося модуля
> стека нет вовсе. `js_check(файл)` парсит код ровно так, как его парсит браузер,
> и отдаёт адрес с куском исходника плюс граф импортов. Инструмент —
> `py_modules/js_/js_check.py`, CLI: `python -m js_.js_check файл.js страница.html`.

## 1. Почему не `file_check` и не `node --check` руками

`file_check` отвечает на вопрос про байты (пустышка, огрызок, голова), здесь
вопрос про код: распарсится ли. Ровно тот случай: в многострочную одинарную
строку шаблона доехала переносимая строка — `.js` как `.js` node читает CJS-парсером и
молчит, а браузер на ESM-парсере умирает с «Invalid or unexpected token» ещё до
исполнения — стек пуст, искать негде. Тело блока пишется во временный `.mjs` с
отступом строк до места в шаблоне — номер строки из node выходит родным.

## 2. Граф вместо угадывания

`imported_by` — куда смотрят импорты файла; у страницы — из её же инлайн-модуля.
Кавычки и обёртки в шаблонах любые: `{{ static_url('js/…') }}` — тоже импорт.

## Грабли

1. **node — системная зависимость**: нет бинаря — `FileNotFoundError`, а не
   молчаливый пропуск (как ffmpeg в `adb_rec`).
2. **`.js` ≠ модуль для node**: проверка всегда через копию `.mjs`; проверить
   «как есть» — значит проверить не то, что читает браузер.
3. **классический `<script>` без `type=module` — не модуль**: он не в графе, и
   это не поломка, это разметка такая.


## ⚠⚠ Модуль страницы с общей статикой: `js_static_run`

Страницы подключают общие модули абсолютным путём — `/static/js/notification.js`.
Браузеру этого хватает: раздача панели ищет файл в двух каталогах (своём и общем
submodule `dashboard`), и путь разрешается в URL.

А node ходит по **файловой системе** и про `/static/` не знает: берёт его за
абсолютный путь от корня диска и отвечает `ERR_MODULE_NOT_FOUND`. Тест падает,
хотя в браузере модуль работает — проверено в обе стороны.

```python
from js_.js_static import js_static_run

done = js_static_run(script, roots=[own_public, 'dashboard'])
assert done.returncode == 0, done.stderr
```

⚠ Каталоги **в порядке поиска**: свой проекта, затем общий — тот же порядок, что
у раздачи. Разойдись они, тест проверял бы не тот файл, который отдаёт сервер.

⚠⚠ Хук ставится через `node:module`.`register`, а не `--import`: тот исполняет
файл в том же потоке, и перехват резолва из него **не действует** — отказ
выглядит точно так же, как без хука вовсе.

⚠ Три способа было, два плохи: симлинки общих файлов — лишняя сущность в git и
нет их на Windows; относительные пути node понимает, но тогда файл обязан лежать
на диске проекта, то есть общего submodule не бывает.
