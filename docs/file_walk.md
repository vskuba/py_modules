# File Walk — обход дерева без служебных веток

> Обойти репозиторий за исходниками нужно многим инструментам сразу, и все писали это
> одинаково: `rglob('*')` со списком служебных папок в фильтре **после** обхода. Фильтр
> после обхода не экономит ничего — дерево `.venv` перебирается целиком и выбрасывается.
> `file_walk` обрезает ветку **на входе** в каталог: те же файлы, в сотни раз дешевле.

## 1. Зачем это отдельная функция

Копий было четыре — `tool_catalog`, `tool_typo` (три обхода), `tool_impact`, `page_wire`, —
и каждая несла свой список служебных папок. Расходятся такие списки молча: инструмент,
не знающий про `.mypy_cache`, однажды начинает читать чужой кеш и сообщать о находках
в нём.

Цифры этого репозитория (204 своих `*.py`, `.venv` на 65 тысяч файлов):

| Как искали | Путей перебрано | Время |
|------------|-----------------|-------|
| `rglob('*.py')` + фильтр после | 22 237 | 0.310 с |
| `rglob('*')` + фильтр после (так искал `tool_impact`) | 78 722 | ~0.9 с |
| `file_walk` с обрезкой веток | 204 | 0.001 с |

Отсюда `tool_find` 0.60 → 0.30 с, `tool_typo` 0.81 → 0.52 с, `tool_impact` 0.79 → 0.28 с.
Цифры — с холодным стартом интерпретатора; сам обход быстрее в ~43 раза.

## 2. Как звать

```python
from file_.file_walk import file_walk

file_walk('.', ('.py',))                  # исходники репозитория
file_walk(root, ('.py', '.md'))           # код и проза разом
file_walk('image_/image_.py', ('.py',))   # файл на входе — он же на выходе
```

```bash
PYTHONPATH=. python -m file_.file_walk --suffix .py --count   # что вообще обойдёт инструмент
PYTHONPATH=. python -m file_.file_walk docs --suffix .md      # список файлов
```

Возвращается **отсортированный** список `Path` — порядок устойчив между запусками, на нём
можно сравнивать выдачи двух прогонов.

## 3. Что пропускается

`FILE_WALK_SKIP`: `.venv`, `venv`, `__pycache__`, `.git`, `node_modules`, `.idea`,
`.mypy_cache`, `.pytest_cache`, `.ruff_cache`, `dist`, `build`, `.next`.

Список — часть контракта, а не настройка «на всякий случай»: инструмент, читающий
`node_modules`, сообщает о находках в чужом коде, и его перестают читать.

## Грабли

1. **Фильтр после обхода не экономит ничего** — `.venv` уже перебран. Экономит только
   `dirs[:] = [...]` внутри `os.walk`: ветка не открывается вовсе.
2. **Ветка режется по имени каталога на любом уровне, а не по пути** — `node_modules` не
   обойдётся ни в корне, ни внутри пакета. Обратная сторона: свой каталог с таким именем
   тоже не обойдётся. Назовите его иначе, а не расширяйте `skip` исключением.
3. **Симлинки на каталоги не разворачиваются** (`os.walk` без `followlinks`). Иначе
   `.claude/docs-common -> ../py_modules/docs` обошёлся бы дважды, и вычитка нашла бы
   каждую опечатку по два раза.
4. **Расширение сверяется с точкой** — `('py',)` не найдёт ничего, нужно `('.py',)`.
   Молчаливый пустой список тут честнее догадки: иначе `--suffix .tar.gz` работал бы
   через раз.
