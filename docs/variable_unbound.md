# Переменная, прочитанная раньше присваивания: `UnboundLocalError` до запуска

> `variable_unbound(дерево)` отвечает на вопрос, которого не задаёт ни один
> разбор: имя в функции связано — но связано ли оно **к тому моменту**, когда
> его читают. Такой код парсится, импортируется, проходит ревью и падает лишь
> тогда, когда исполнение дойдёт до строки. Инструмент —
> `py_modules/variable_/variable_unbound.py`, CLI:
> `python -m variable_.variable_unbound <путь>`; код возврата 1 — есть находки.

## 1. Почему этого не видит ничто другое

Питон решает судьбу имени по всей функции сразу: присвоил где угодно в теле —
имя локальное **везде**, включая строки выше присваивания.

```python
def collect(p):
    refs = pick(p, seed)          # UnboundLocalError: seed ещё не связан
    ...
    seed = p['seed'] or random()  # ...а связывается сотней строк ниже
```

- `ast.parse`, `python -m py_compile`, импорт модуля — молчат: синтаксис цел;
- сторож свободных имён молчит: `seed` в функции **связан**, просто ниже по
  тексту, а он ищет имена, не связанные нигде;
- тесты молчат, если функция ходит наружу (ферма, сеть, база) и в сюиту не
  входит.

Цена в PersonaAI — прогон №745: правка выглядела рабочей, слот занялся, ферма
постояла, работа упала с нулём кадров.

## 2. Чем платит точность: области видимости, а не номера строк

⚠ **Инструмент обязан молчать там, где ошибки нет.** Ложная тревога дороже
пропуска: её пролистывают вместе с настоящей находкой. Поэтому разобран не
текст, а области видимости:

| Случай | Почему не тревога |
|--------|-------------------|
| `{k: v for k, v in x.items()}` | у comprehension **своя область**; `k` снаружи не существует |
| `[max(t.height for t in r) for r in rows]` | цель **вложенной** comprehension — тоже своя; плоский отсев здесь уже соврал |
| `def inner(): return later` выше `later = 1` | вложенная функция исполнится **потом** |
| `f = lambda: later` | то же самое |
| `global counter` | локальность снята объявлением |
| параметры функции | связаны входом, до любой строки |
| `for i in items: total += i` после `total = 0` | первое связывание выше первого чтения |

Связывают имя не только `=`, и каждая форма перечислена явно: `for`,
`with ... as`, `except ... as`, `import`, `:=`, `def`, `class`, `match ... as`,
дополненное присваивание. Пропущенная форма — это ложная тревога на ровном
месте.

Тело класса — отдельный случай: оно исполняется **сразу**, поэтому чтения из
него считаются, а присваивания в нём внешнюю функцию не связывают.

## 3. Что инструмент НЕ ловит

- **условное связывание**: `if c: x = 1` … `print(x)`. Упадёт или нет, решают
  данные, а не текст; сказать статически нечего, и молчание честнее догадки;
- **`del x`** и повторное чтение после него — то же самое.

## Грабли

- **Чтение внутри comprehension — настоящее чтение.** Она исполняется той же
  строкой, поэтому `[x for x in items if x > limit]` выше `limit = 3` —
  находка, и верная. Своя область у comprehension только для её **целей**.
- **Цикл не исключение, а самый частый случай.** Чтение в начале тела и
  связывание в конце — `UnboundLocalError` на первой же итерации. Если имя
  заведено до цикла, находки нет: первое связывание выше.
