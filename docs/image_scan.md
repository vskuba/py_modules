# Сканирование снимка: полосы фона, строки текста, габарит глифов

> Одна колонка пикселей отвечают на три вопроса сборки: где начинаются и
> кончаются светлые области (`image_scan_runs`), с каким шагом идут строки
> (`image_scan_rows`) и какого размера сами глифы (`image_scan_glyph`).
> Инструмент — `py_modules/image_` (модуль `image_scan`), CLI:
> `python -m image_.image_scan`. Тон и доли кадра — `image_tooling.md`.

## 1. Полосы: `image_scan_runs`

`image_scan_runs(path, axis, pos, tone, tol, min_len, rect)` идёт вдоль разреза
(`y` — горизонтальная строка пикселей на высоте `pos`, `x` — вертикаль на
`pos`) и отдаёт отрезки, где пиксель совпадает с тоном (`white`, `black`,
`#rrggbb`) с допуском `tol`; короче `min_len` — мусор, отбрасывается. Границы
включительные, координаты — целого кадра.

Так измеряются границы белого листа на тонированном фоне, высота sheet-попапа,
положение разделителя (`tone '#ededed'` даёт полосу в 2–3 px). Без `--pos`
разрез по центру кадра — центр колонки контента почти всегда там же.

- **Разрез через текст рвёт белую область на куски** (глифы — не белый): либо
  вести разрез по чистой колонке (между текстом и краём), либо читать
  объединение полос с зазором ≤ пары пикселей.
- **Скруглённые углы телефона дают фальшивые края** на горизонтальных
  разрезах у верха/ низа кадра; `rect` отрезает рамку.

## 2. Строки: `image_scan_rows`

`image_scan_rows(path, rect, thresh, min_height)` — бинаризация по яркости и
профиль тёмных строк: отдаёт интервалы строк, их центры и **шаг** (медиана
разностей центров; зазоры ≤ 2 px — разорванная глифами строка, склеивается).
Шаг строкового меню — по нему проверяют, что хотспоты расставлены по рядам, а
не «на глаз»: измеренный pitch 154.75 px против раскиданных на 150±9 точек
виден сразу.

`rect` обязателен по смыслу: без него в профиль попадают тёмные подписи
панели вкладок и статус-бар, медиана шага съезжает.

## 3. Габарит глифов: `image_scan_glyph`

`image_scan_glyph(path, rect, thresh)` — рамка вокруг тёмных пикселей окна:
высота текстовой капс (`h` ≈ 38 px в ряду меню) против «высоты строки» из
`rows` — это разные величины, CSS задают по первой. Окно должно обнимать одну
строку: две строки в окне дают удвоенный `h`. Пустое окно — `ValueError` с
текстом про порог, а не молчаливый ноль.

## CLI

```bash
python -m image_.image_scan runs shot.png --axis y --pos 540 --tone white --min 40
python -m image_.image_scan runs shot.png --axis x --pos 900 --tone '#ededed'
python -m image_.image_scan rows shot.png --rect 242,1300,990,2010
python -m image_.image_scan glyph shot.png --rect 242,1330,900,1400
```

## Грабли

1. **Разрез через текст** — белая полоса рвётся на глифах; читать чистую
   колонку или склеивать зазоры.
2. **Скругления экрана** — фальшивые «не белые» пиксели по краям кадра;
   сужать `rect`.
3. **`rows` без `rect`** считает шаг по мусору (вкладки, статус-бар) —
   медиана вводит в ошибку уверенным числом.
4. **Снимок не «после перехода»** — полупрозрачный в анимации слой тоном 233
   не проходит в `white` с малым `tol`: источник — `web_shot` с бюджетом или
   `screencap` в покое.
