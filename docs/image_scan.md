# Сканирование снимка: полосы фона, строки текста, габарит глифов

> Одна колонка пикселей отвечают на три вопроса сборки: где начинаются и
> кончаются светлые области (`image_scan_runs`), с каким шагом идут строки
> (`image_scan_rows`) и какого размера сами глифы (`image_scan_glyph`). А
> габарит содержимого заданного тона по всему кадру — `image_scan_bbox`.
> Инструмент — `py_modules/image_` (модуль `image_scan`), CLI:
> `python -m image_.image_scan`. Тон и доли кадра — `image_tooling.md`.

## 1. Полосы: `image_scan_runs`

`image_scan_runs(path, axis, pos, tone, tol, min_len, rect)` идёт вдоль разреза
(`y` — горизонтальная строка пикселей на высоте `pos`, `x` — вертикаль на
`pos`) и отдаёт отрезки, где пиксель совпадает с тоном (`white`, `black`,
`chroma` — любой цветной, `#rrggbb`) с допуском `tol`; короче `min_len` —
мусор, отбрасывается. Границы включительные, координаты — целого кадра.

Так измеряются границы белого листа на тонированном фоне, высота sheet-попапа,
положение разделителя (`tone '#ededed'` даёт полосу в 2–3 px). Без `--pos`
разрез по центру кадра — центр колонки контента почти всегда там же.

- **Разрез через текст рвёт белую область на куски** (глифы — не белый): либо
  вести разрез по чистой колонке (между текстом и краём), либо читать
  объединение полос с зазором ≤ пары пикселей.
- **Скруглённые углы телефона дают фальшивые края** на горизонтальных
  разрезах у верха/ низа кадра; `rect` отрезает рамку.

## 2. Строки: `image_scan_rows`

`image_scan_rows(path, rect, thresh, min_height)` — бинаризация по яркости и
профиль тёмных строк: отдаёт интервалы строк, их центры и **шаг** (медиана
разностей центров; зазоры ≤ 2 px — разорванная глифами строка, склеивается).
Шаг строкового меню — по нему проверяют, что хотспоты расставлены по рядам, а
не «на глаз»: измеренный pitch 154.75 px против раскиданных на 150±9 точек
виден сразу.

`rect` обязателен по смыслу: без него в профиль попадают тёмные подписи
панели вкладок и статус-бар, медиана шага съезжает.

## 3. Габарит глифов: `image_scan_glyph`

`image_scan_glyph(path, rect, thresh)` — рамка вокруг тёмных пикселей окна:
высота текстовой капс (`h` ≈ 38 px в ряду меню) против «высоты строки» из
`rows` — это разные величины, CSS задают по первой. Окно должно обнимать одну
строку: две строки в окне дают удвоенный `h`. Пустое окно — `ValueError` с
текстом про порог, а не молчаливый ноль.

## 4. Батч окон: `image_scan_windows`

`image_scan_windows(path, windows)` — габарит инка сразу по списку
именованных окон (`{имя: (x0, y0, x1, y1)}`). Сверка свёрстанного всегда
идёт по контрольным точкам (заголовок, номер, строки), а `image_scan_glyph`
на пустом окне бросает: в батче пустое окно — `None` в ответе, «инка нет»
это результат проверки, а не исключение.

## 5. Сверка клона с оригиналом: `image_scan_windows_diff`

`image_scan_windows_diff(a, b, windows, offset='auto', tol=2)` отвечает на
вопрос «клон совпал с оригиналом или нет» одним вердиктом. Кадры одного
экрана лежат сдвинутыми (скриншот телефона со статус-баром против
headless-рендера — на замере 20–25 px), поэтому сравнивается не пиксель в
пиксель, а ink-рамка каждой точки после снятия **константного** смещения.
`offset='auto'` берёт медиану разностей левых верхних углов по окнам с
инком на обеих сторонах: один съехавший блок не сдвигает медиану, он
виден большим `resid` в отчёте. В окне `b` меряется сдвинутым на offset.

Вердикт по окну: остаток `resid = delta − offset` в допуске `tol` по обеим
осям; пустое окно с обеих сторон — `ok` (согласованное отсутствие), пустое
с одной — пропажа или лишнее содержимое, всегда `БОЛЬНО`.

Цикл проверки клона целиком:

```bash
# 1. кадр оригинала с телефона
python -m adb_.adb_ capture /tmp/zpass/card.png
# 2. тот же экран из свёрстанной страницы: seed шины через inject-js
python -m web_.web_shot www/documents.html --out /tmp/zpass/render.png \
    --size 1080x2276 --budget 4000 \
    --inject-js "localStorage.setItem('diaData', JSON.stringify({...}))"
# 3. сверка по контрольным точкам
python -m image_.image_scan diff /tmp/zpass/card.png /tmp/zpass/render.png \
    --window title=591,150,1000,210 --window name=560,1410,1050,1600
```

## 6. Габарит тона по всему кадру: `image_scan_bbox`

`image_scan_bbox(path, tone='chroma', tol=8, rect=None)` отвечает на «где в
кадре содержимое заданного тона», когда координаты неизвестны: возвращает
ограждающую рамку `(x0, y0, x1, y1)` всех попавших в тон пикселей и их число
(`box=None`, если таких нет). В отличие от `runs`/`glyph`, которым нужны
разрез и окно, `bbox` смотрит на весь кадр разом и окно не требует.

Тон по умолчанию — `chroma` («любой цветной»: размах каналов больше `tol`).
Фон карточек и страниц серый, у серого хроматика нулевая, — значит `chroma`
ловит именно содержимое, а не вариации подложки, и под конкретный hex
подвязываться не надо. Практика: залили слот тестовой картинкой — `bbox`
покажет, куда она легла на самом деле; стёрли запечённый объект — остатки
тона дадут рамку, и пустой ответ («чисто») есть вердикт «дотянуто до фона».
`rect` отсекает цветные оверлеи интерфейса (пилюли, баннеры), иначе их
пиксели раздуют рамку.

## CLI

```bash
python -m image_.image_scan runs shot.png --axis y --pos 540 --tone white --min 40
python -m image_.image_scan runs shot.png --axis x --pos 900 --tone '#ededed'
python -m image_.image_scan bbox shot.png [--tone chroma] [--tol 8] [--rect x0,y0,x1,y1]
python -m image_.image_scan rows shot.png --rect 242,1300,990,2010
python -m image_.image_scan glyph shot.png --rect 242,1330,900,1400
python -m image_.image_scan windows shot.png --window title=591,150,1000,210 \
    --window name=560,1410,1050,1600
python -m image_.image_scan diff orig.png render.png --window title=... \
    [--offset auto|none|dx,dy] [--tol 2]
```

## Грабли

1. **Разрез через текст** — белая полоса рвётся на глифах; читать чистую
   колонку или склеивать зазоры.
2. **Скругления экрана** — фальшивые «не белые» пиксели по краям кадра;
   сужать `rect`.
3. **`rows` без `rect`** считает шаг по мусору (вкладки, статус-бар) —
   медиана вводит в ошибку уверенным числом.
4. **Снимок не «после перехода»** — полупрозрачный в анимации слой тоном 233
   не проходит в `white` с малым `tol`: источник — `web_shot` с бюджетом или
   `screencap` в покое.
5. **`auto`-смещение по узким окнам** — сдвинутое содержимое обрезается краем
   несдвинутого окна и медиана мерит край окна (−20 вместо −25); функция
   пересчитывает по сдвинутым окнам до сходимости (3 прохода), но если окно
   впритык к контенту и смещение больше окна — сходится отказывается, окно
   надо расширить.
6. **Сверка не ловит изменение размера** — `resid` сравнивает левые верхние
   углы; блок, раздувшийся на 10 px вниз, остаётся «в норме», пока не
   поедет его верх. Для высот смотри `h` в габаритах `windows`.
