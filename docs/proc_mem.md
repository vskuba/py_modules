# Память машины — из `/proc` без разбора колонок `free`

> `free -h` и `ps aux` написаны для глаз: колонки под каждую версию procps
> — отдельная работа разбора, а спрашивается всегда одно: сколько свободно
> **сейчас** и **кто** держит. Ответ лежит в `/proc/meminfo` и
> `/proc/<pid>/statm` — в килобайтах, без колонок и без зависимости от
> версии утилит.

## 1. Сводка

```python
from proc_.proc_mem import proc_mem_stat

m = proc_mem_stat()
# {'mem_total': 33353359360, 'mem_available': 3880071168, 'mem_used': 29473288192,
#  'swap_total': ..., 'swap_free': ...}      # байты
```

`mem_used` — total минус **available**: то, что реально отнято у дела.
Пустой словарь — не Linux (на macOS `/proc` нет), и это ответ, а не ошибка.

## 2. Держатели: `proc_top_mem`

```python
from proc_.proc_top import proc_top_mem

top = proc_top_mem(10)
# [{'pid': 1339689, 'name': 'python', 'rss': 4832464896}, ...]  # по убыванию
```

Имя — `comm` (15 символов, ядро обрезает), вес — RSS в байтах. Между
списком pid и чтением `statm` процесс мог умереть — такая строка просто
пропускается, а не роняет обход.

```bash
PYTHONPATH=. python -m proc_.proc_mem             # сводка JSON
PYTHONPATH=. python -m proc_.proc_top -n 5        # тяжелейшие пять
```

## Грабли

1. **Свободное мерило — `MemAvailable`, а не `MemFree`**: кэш страниц
   отдаётся под дело, и «свободно» по `MemFree` пугает нулём там, где
   половина машины — готовая к отдаче кэшированная мелочь.
2. **RSS считает общие страницы каждому владельцу**: библиотечные мегабайты
   приплюсовываются всем, кто их маппит, и сумма топа больше памяти машины.
   Уникальный вес — `smaps_rollup`, а он дорог на каждом круге.
3. **`comm` — имя процесса, не командная строка**: uvicorn-воркеры все как
   один `python`/`uvicorn`; различать — только по pid и `cmdline`.
4. **Размер страницы спрашивается у ядра** (`sysconf`), а не помнится числом:
   на экзотических сборках она не обязана быть кратной мегабайту.
