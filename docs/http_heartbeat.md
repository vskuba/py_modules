# HTTP-heartbeat: чужая сессия живёт без браузера

Модуль `http_/http_heartbeat.py`. Держит веб-сессию на **чужом** сайте живой
периодическим HTTP-запросом: сайт видит активность и считает пользователя в сети,
а браузер при этом закрыт.

Задача узкая и повторяется от проекта к проекту: вошли один раз браузером, забрали
cookie, дальше поддерживаем присутствие сами. Модуль отвечает за второе.

## 1. Почему не браузером

Сайт считает человека «в сети», пока его открытая страница шлёт периодический
запрос. Держать ради этого вкладку — самый дорогой из возможных способов:

| Что держим | На одну сессию | Тысяча сессий |
|------------|----------------|---------------|
| вкладка Chromium | ~143 МБ | 143 ГБ — невозможно |
| свой HTTP-клиент на сессию | ~707 КБ | 690 МБ — дорого и незачем |
| **общий клиент, cookie на запрос** | **~4,7 КБ** | **4,5 МБ** |

⚠ **Отсюда главное правило: клиент один на все сессии, cookie передаются на каждый
запрос.** Клиент на сессию кажется естественным — у каждой свои cookie, — но каждый
несёт собственный пул соединений: тысяча клиентов это тысяча пулов и тысяча
рукопожатий TLS на круг. Общий клиент переиспользует соединения к тому же хосту, и
от сессии остаётся только словарь cookie.

Числа в таблице — замер, а не оценка: тысяча клиентов против тысячи словарей cookie
в одном процессе.

**Откуда берётся сама сессия.** Войти без браузера обычно нельзя: форма, капча,
код из письма. Вход делают один раз в `browser_` (`browser_control.md`), снимают
`storage_state` и сохраняют файлом (`browser_page.md`, раздел про вход) — дальше он
живёт здесь. ⚠ Отбор cookie для запроса есть в обоих местах, и он **разный**:
`http_heartbeat_cookies` мягче (домен второго уровня, без пути и срока, словарь для
клиента), `browser_cookie_header` строже (правила браузера, строка заголовка).
Известный дубль: мягкость здесь не случайна — сайт кладёт cookie то на `site.com`, то
на `www.site.com`, — поэтому сводить их нужно с проверкой на живом сайте.

## 2. ⚠ Потолок ставит чужой сайт, а не наша память

Памяти тысяча сессий стоит копейки, и на этом легко ошибиться в выводах. Считать
надо другое:

| Период удара | Тысяча сессий |
|--------------|---------------|
| 15 с | 67 запросов/с |
| 30 с | 33 запроса/с |
| 60 с | 17 запросов/с |

Всё это **с одного адреса и под тысячей разных учёток**. Сайт вправе счесть такое
нападением, и потерять можно не запрос, а учётки. Поэтому:

- период подбирается под сайт — по тому, как быстро он гасит присутствие;
- `HTTP_HEARTBEAT_PARALLEL` держит поток ровным: залпом тысяча запросов уходить не
  должна, даже если период позволяет;
- рост числа сессий — повод пересмотреть период, а не оставить как есть.

## 3. Настройка сайта

Модуль не знает ни одного сайта. Куда идти, говорит настройка — обычный словарь,
который проект хранит там, где ему удобно:

```json
{
  "base": "https://site.example",
  "headers": {"Referer": "https://site.example/lk"},
  "beat":   {"path": "/services/beat", "body": "mode=online"},
  "alive":  [{"path": "/services/state", "body": "mode=update", "auth_field": "auth"}],
  "unread": {"path": "/api/stats", "method": "GET", "field": "unreadMail"}
}
```

| Ключ | Зачем |
|------|-------|
| `base` | корень сайта; от него собираются все пути |
| `headers` | общие заголовки: часть сайтов проверяет `Referer` |
| `beat` | тот самый периодический запрос — «я здесь» |
| `alive` | по чему видно, что вход ещё жив |
| `unread` | необязательный счётчик, если сайт отдаёт его попутно |

Шаг описывается словарём `{path, method, body, headers}`. Обязателен только `path`;
метод выводится из тела — есть что послать, значит `POST`.

### ⚠ Примета живого входа обязательна

Сайт отвечает `200` и гостю: выкинутая сессия получает страницу входа тем же кодом,
что и работающая. Без приметы такой сайт выглядит живым всегда, и обнаружится это
в тот день, когда все сессии давно протухли, а панель показывает их в сети.

Примет три, по видам ответа:

| Примета | Когда |
|---------|-------|
| `auth_field` | ответ JSON, и в нём есть поле про пользователя |
| `ok_mark` | ответ не JSON вовсе — ищем подстроку |
| ничего не задано | сайт гостю отказывает кодом — «раз ответил, значит жив» |

Последняя — самая слабая, и выбирать её стоит последней.

`alive` может быть списком: у одного сайта разные кабинеты отвечают разными
модулями и в разных форматах. Подошла любая проверка — вход жив; отказ остальных
ничего не значит.

## 4. Как пользоваться

```python
from http_.http_heartbeat import (http_heartbeat_client, http_heartbeat_cookies,
                                  http_heartbeat_ready, http_heartbeat_send_many)

if not http_heartbeat_ready(config):
    return                                   # сайту ещё не объяснили, куда идти

client = http_heartbeat_client()             # один на все сессии
try:
    sessions = {key: http_heartbeat_cookies(state, config['base'])
                for key, state in states.items()}
    done = http_heartbeat_send_many(client, sessions, config)   # {ключ: дошло ли}
finally:
    await client.aclose()
```

| Функция | Что делает |
|---------|-----------|
| `http_heartbeat_ready(config)` | настроено ли — без этого не начинают |
| `http_heartbeat_client()` | общий клиент; закрывать вызывающему |
| `http_heartbeat_send(client, cookies, config)` | один удар |
| `http_heartbeat_send_many(client, sessions, config)` | удар по многим разом |
| `http_heartbeat_check(client, cookies, config)` | удар + проверка входа + счётчик |
| `http_heartbeat_cookies(storage_state, base)` | cookie нужного хоста из состояния браузера |

### Удар и проверка — разные вещи

`send` шлёт один запрос и отвечает «дошло / не дошло». `check` делает до трёх и
отвечает разбором. Разница в цене: тысяча сессий раз в полминуты — это 33 запроса в
секунду против сотни, поэтому в круге живёт `send`, а `check` зовут по случаю: при
входе, по кнопке, при разборе жалобы.

⚠ **`offline` и `error` у `check` — разные исходы.** Первый значит «сайт не признал
вход, нужен повторный логин», второй — «до сайта не достучались». Слив их в один,
проект гонял бы вход браузером из-за чужой сетевой аварии.

### ⚠ Cookie отбираются по домену

`http_heartbeat_cookies` берёт из `storage_state` только cookie нужного хоста.
Отправить их скопом нельзя: в состоянии лежат и чужие (аналитика, CDN), а вместе
они выдают клиент, который «слишком много знает» — у настоящей страницы этих имён в
запросе нет.

## 5. Границы модуля

**Не входит и не выходит.** Вход — дело браузера и сценариев, они у каждого проекта
свои. Сюда приходят готовые cookie, а откуда они взялись — не его забота.

**Не знает ни базы, ни расписаний, ни учёток.** Он про запрос и ответ. Кого держать
в сети и когда — решает проект: у него и таблицы, и смены, и журнал.

**Не хранит состояние между вызовами.** Клиент создаёт вызывающий и он же закрывает;
модульных синглтонов здесь нет намеренно — иначе два круга в одном процессе делили
бы один пул, не подозревая друг о друге.

## 6. ⚠ Почему папка называется `http_`, а не `http`

`http` — пакет стандартной библиотеки. В `PYTHONPATH` проекта лежит и корень
`py_modules`, поэтому папка `http` перекрыла бы стандартный пакет **во всех
проектах сразу**, а сломалось бы это не здесь, а в чужом коде, который импортирует
`http.client`. Ровно поэтому в общем слое уже есть `logging_`, `datetime_`, `json_`.

Хвостовое подчёркивание в префикс функций не входит: `http_/http_heartbeat.py` →
`http_heartbeat_send()`.
