# Правка кадров-скриншотов: стирание запечённого текста, заливка окна, штрих в альфу

> Скриншот, который становится подложкой клона, надо уметь чистить: тёмный
> текст стирается продолжением фона (`image_fix_erase`), окно с известным
> тоном заливается плоским цветом с дугой угла (`image_fix_fill`), рукописный
> штрих вырезается в PNG с альфой (`image_fix_strokes`). Альфа кадра проходит
> сквозь любую правку нетронутой. Инструмент — `py_modules/image_` (модуль
> `image_fix`), CLI: `python -m image_.image_fix`. Замеры до и после правки —
> `image_scan.md`.

## 1. Стирание: `image_fix_erase`

`image_fix_erase(path, out, boxes, edge=6, axis='h', quality=92)` затирает
прямоугольники (конвенция PIL: `x1`, `y1` исключая) содержимым «продолжённого
фона». Строка окна заполняется линейной интерполяцией между **медианами**
узких краёвых полос слева и справа, при `axis='v'` — сверху и снизу.

Почему так, а не «закрасить средним окна»:

- **плоская заплата видна** — фон страниц и карточек имеет медленный
  градиент, заплатка среднего тона темнеет к светлому краю окна;
- **медиана, а не среднее** — в краевую полосу может попасть опечатка
  соседнего текста (окно поставлено вплотную), среднее утянет в тёмное,
  медиана шестипиксельной полосы её переживёт;
- **якоря линии — середины полос**, а не границы окна: медиана отвечает за
  уровень в центре полосы, иначе значение на краю окна сдвинуто на `edge/2`
  px против фона и шов читается.

`axis` выбирают по направлению собственного градиента фона и форме окна:
строку текста в широкой карточке — `h`, высокое узкое поле (колонка таблицы,
правый край) — `v`. Окно у края кадра затирается плоским уровнем единственной
полосы-донора; окно без обеих полос (на весь кадр) — `ValueError`, продолжения
фона не существует.

Формат сохранения — по расширению `out`; для webp/jpeg действует `quality`
(92 — неотличим от исходника скриншота интерфейса).

**Альфа проходит насквозь.** Любой режим с прозрачностью — RGBA, LA, P с
`tRNS` — сохраняется: правка живёт в RGB, альфа возвращается нетронутой, на
выходе кадр становится RGBA. Раньше склейка альфы знала только RGBA, и LA/P
кадр выходил RGB с потерянной прозрачностью — почерневшая матовая подложка
там, где был просвет.

## 2. Плоская заливка: `image_fix_fill`

`image_fix_fill(path, out, boxes, color, radius=0, feather=2.0, quality=92)`
красит окна сплошным замеренным `color` (`'#rrggbb'` или тройка 0-255).
Среднее между `erase` и «закрасить на глаз»: когда тон окна известен точнее
краёвых доноров `erase`, интерполяция лишь добавит шума к правильному цвету.
Типовые случаи — слот фотографии цвета подложки, заглушка поля формы,
заливка освобождённого окна перед наложением живого элемента.

- **радиус — дуга, а не аргумент красоты**: окно на скруглённой карточке без
  `radius` даёт белый ореол по углам наружу и полосу цвета под низом; дуга,
  снятая с замера окна, совпадает с CSS `border-radius`;
- **маска — знаковое расстояние** до скруглённого прямоугольника
  (`image_layout.image_layout_alpha` — одна реализация SDF на пакет), край
  размыт на `feather` px: ровно чтобы спрятать ±1 px сдвига края
  lossy-сжатием, не порождая заметную растяжку;
- альфа источника проходит так же, как у `erase`.

После заливки окно контролируют тем же замером, что и нашли: `image_scan
windows` («пусто») или `image_scan bbox --tone '#rrggbb'` (габарит залитого
совпал с окном).

## 3. Штрих в альфу: `image_fix_strokes`

`image_fix_strokes(path, out, box, hi=150, span=120, color=(0,0,0))` — фото
подписи/штампа ручкой на светлой бумаге → RGBA, где

```
alpha = (hi − lum) · 255 / span, lum = (R+G+B)/3, клампы 0..255
```

Светлее `hi` — полностью прозрачно, `span` единиц яркости до чёрного — весь
диапазон альфы. Антиалиасинг края превращается в плавную альфу по той же
формуле — ручная ключевка не нужна. Пороги подобраны по реальной подписи:
штрих ручки lum 60–110 на бумаге lum 210+, при 150/120 бумага уходит в нуль,
штрих — в 85–255.

Полученный PNG CSS кладёт поверх чистой подложки: подпись больше не несёт
серую рамку вырезанного прямоугольника.

## 4. Пара с `image_scan`: цикл правки

Правку всегда проверяют тем же замером, которым нашли дефект:

```bash
python -m image_.image_fix erase card.png --out card_clean.webp \
    --box 591,150,1000,210 --box 560,1410,1050,1600
python -m image_.image_scan windows card_clean.webp \
    --window title=591,150,1000,210 --window name=560,1410,1050,1600
# оба окна «пусто» — текст стёрт, подложка цела
```

## CLI

```bash
python -m image_.image_fix erase shot.png --out clean.webp \
    --box 40,60,260,90 [--box ...] [--edge 6] [--axis h|v] [--quality 92]
python -m image_.image_fix fill shot.png --out slot.webp \
    --box 135,584,520,1104 --color '#f7f7f7' [--radius 36] [--feather 2]
python -m image_.image_fix strokes photo.png --out sign.png \
    --box 40,60,260,90 [--hi 150] [--span 120]
```

## Грабли

1. **Стирают по живому источнику** — правь копию: `erase` всегда пишет в
   `out`, но вызвавший с `out == path` теряет оригинал без возврата.
2. **Окно впритык к другому тексту** — краевая полоса захватывает соседние
   глифы: медиана держит, но при `edge` больше просвета тон заплатки уедет.
   Между окном и чужим текстом должен остаться зазор ≥ `edge`.
3. **`axis` против градиента** — при `h` поперёк вертикального градиента
   строки окна получают уровень только своей полосы: верх и низ высокого
   окна разъедутся тонами. Высокое окно — `v`.
4. **Тёмный фон** — формула штриха рассчитана на светлую подложку: на тёмном
   фото всё станет непрозрачным. Инвертированный случай (светлый штрих на
   тёмном) этой функцией не делается — там альфа растёт с яркостью.
5. **webp q92 после erase — уже lossy второго поколения** — если правок
   много, держите мастер в PNG и конвертируйте в webp один раз на финише.
6. **`fill` с цветом «на глаз» вместо замера** — плоский тон, взявший тон с
   соседнего пикселя, на градиентной подложке виден пятном; берите `color` из
   того же окна модальной медианой (`image_measure`), что и заливаете. Радиус
   вне формы угла (`radius` не с окна, а «на глаз») даёт либо срез, либо
   незаметную, но читаемую ступеньку.
