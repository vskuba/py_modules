# Cashier: разведка среды без рук

Namespace `cashier_/` — читалки платёжной платформы Cashier (dev/stage/prod): хосты и
базы среды, сессия дашборда, бренд, провайдер, вызовы внешнего API, возможности
процессоров. Всё в namespace **только читает**: ни одна функция не пишет в базу, не
дергает мутаций дашборда и не заводит транзакцию, кроме явного `cashier_api_process`.

Проектные детали (адреса, профили MySQL, агентская учётка) — в `AGENTS.md` проекта и
`docs/agent-access.md`; здесь — устройство слоя и порядок вызовов.

## Из чего собран

`cashier_env` — низ: по одному имени среды даёт хосты ролей, имена баз и заголовки.
Остальные модули не склеивают домены сами, а спрашивают их здесь, поэтому смена схемы
хостов или переименование базы — правка одного файла. Дальше два независимых корня:

- `cashier_dashboard` — GraphQL-сессия дашборда (`loginUser`, `switchAccount`, `call`);
- `cashier_processor` — файлы checkout-а payment-gateway, без сети.

Над ними — `cashier_brand` (uuid, креды, Bearer; ходит в дашборд и в базу) и
`cashier_provider` (регистрация провайдера по базам), а `cashier_api` — уже внешний API
бренда поверх токена бренда. Цепочка всегда однозначная: бренд → токен → вызов; хост →
база → строка провайдера.

## Порядок вызовов на типовой задаче

Проверка «провайдер подключён и возврат работает» идёт снизу вверх, по одному вызову
на слой — раньше это было двадцатью `curl` и `SELECT`:

1. `cashier_env map` — чем вообще пахнет среда (хосты, базы, роли).
2. `cashier_processor gaps <провайдер> --env stage` — что говорит база (зарегистрирован
   ли тип, под какими брендами) против того, что лежит в коде ветки (фабрики,
   `RefundPaymentProcessor`). Ответ — «куда идти чинить», а не «ошибки нет».
3. `cashier_provider refunds <провайдер> --brand <бренд>` — есть ли строка возврата и на
   какой депозитный экземпляр она смотрит.
4. `cashier_brand token <бренд>` → `cashier_api methods refund --account <бренд>` —
   живое подтверждение со стороны API. `payment-methods` и `schema` ничего не создают;
   `payment-process` создаёт **живую транзакцию** и без тестовой карты провайдера не
   зовётся вовсе.

## Грабли

1. **Cloudflare на dev/stage режет не-браузерные UA** — вместо ответа приходит 1010, и
   модуль выглядел бы сломанным. Браузерный набор заголовков собирает `cashier_env_headers`;
   любой свой `urllib`-вызов без него — будущая «ошибка сети».
2. **Тело OAuth-запроса — JSON**, та же пара логин/пароль формой отвергается
   `invalid_grant`. Токен живёт час и лежит в `~/.cache/cashier` файлом 0600; при
   смене кредов бренда нужен `--fresh`, иначе час будет ходиться старый Bearer.
3. **Сессия дашборда входит не в тот бренд.** После `loginUser` текущий аккаунт — первый
   из списка (на stage это Casino), поэтому любой запрос про бренд обязан предварительно
   `switchAccount`. `--account` в модулях это делает сам.
4. **`Clearers` без фильтра отдаёт 500 строк и падает** — на stage сотни клиреров
   автотестов, нужный в выборку не попадает. Фильтр `processorName` обязателен; в
   Query-ростере при этом нет `currentAccount`, есть только `Accounts`.
5. **Один SQL-запрос на задачу.** База доступна через userspace WireGuard-туннель, и
   каждый запрос стоит несколько секунд. Поэтому выборки собраны `UNION ALL` и
   `COALESCE`-подзапросами, а не циклом по базам; «уточнить отдельной запроской» здесь
   дороже, чем длинный SQL.
6. **`is_refund_supported` в aggregate-psp ничего не включает** — пережиток колонки.
   Возврат разрешён, когда в `cashier-withdrawal.payment_provider` есть строка
   `withdrawal_type='REFUND'`, привязанная к депозитному провайдеру; её и ищет
   `cashier_provider refunds`.
7. **Матрица процессоров зависит от ветки working tree.** `RefundProcessorFactory.php`
   есть не везде, и у Nuvei он появляется только в feature-ветке: `supports … refund`
   отвечает по файлам того checkout-а, который указан, а не того, что задеплоено.
8. **Ответы наружу уходят замазанными** (`data_mask_json`); полный токен и креды — только
   в файле 0600, никогда в выводе и в git.

## Как запускать

```bash
cd /var/www/cashier-service-payment-gateway
PYTHONPATH=/home/vasyl/PycharmProjects/py_modules /home/vasyl/PycharmProjects/py_modules/.venv/bin/python \
  -m cashier_.cashier_provider info nuvei --env stage
```

`--root` указывает, чей `.env.local` читать (по умолчанию checkout payment-gateway),
`--env` — среда (`dev` / `stage` / `prod`). Тесты сюиты — рядом с модулями,
`cashier_/*_test.py`; сеть и база в них подменены, прогон без VPN.
