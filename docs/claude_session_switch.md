# Сессии Claude Code таблицей и переключение кликом

Таблица запущенных на машине сессий Claude Code в статусной строке: радиокнопка, имя, состояние,
потраченные токены. Клик по радиокнопке или имени выводит сессию на экран — она должна жить в tmux.

## 1. Из чего собрано

| Модуль | Что делает |
|--------|-----------|
| `claude_/session/claude_session_live.py` | живые сессии из `~/.claude/sessions/<pid>.json`: имя, статус, вид, панель tmux |
| `claude_/session/claude_session_tokens.py` | сводка сессии по транскрипту, с дочитыванием: токены и заголовок |
| `claude_/session/claude_session_switch.py` | таблица со ссылками и сервер `GET /switch/<sessionId>` на `127.0.0.1:8797` |
| `tmux_/tmux_.py` | панели и клиенты tmux, панель процесса, вывести панель на экран, новое окно |
| `claude_/session/claude_session_host.py` | где видна сессия: PyCharm, PhpStorm, терминал — по предкам процесса |

```bash
PYTHONPATH=. python -m claude_.session.claude_session_live                 # список
PYTHONPATH=. python -m claude_.session.claude_session_switch table          # таблица
PYTHONPATH=. python -m claude_.session.claude_session_switch to <sessionId> # переключить
PYTHONPATH=. python -m claude_.session.claude_session_switch serve          # сервер
```

## 2. Статусы

Пишет сама сессия в свой файл: `busy` — модель отвечает («работает»), `shell` — ход
окончен, но идёт фоновая команда («фон»), `idle` — ждёт человека («ждёт»). Вид `bg` —
фоновая сессия. ⚠ Файл переживает убитую сессию: живость — по `/proc/<pid>`.

В таблицу попадают только **видимые** сессии (`visible`): фоновые (`bg`) терминала не
имеют вовсе, а сессия в tmux, к которому не подключён ни один клиент, жива, но на экране
её нет — переключиться на неё некуда. И не **вложенный запуск**: Agent SDK
(`entrypoint: sdk-*`, ревьюер заставы) или процесс-потомок другой живой сессии — его панель
находится по предкам (панель хозяина), и в таблице выходил двойник хозяина с его заголовком.

## 3. Токены

Токены — раздельно, в таблице `вход/выход` (голубой/оранжевый): **вход** = вход без кэша +
запись в кэш, **выход** — что написала модель. Чтение из кэша не входит: оно повторяет
контекст на каждом шаге и ничего не говорит о работе.

- ⚠ Один ответ пишется в транскрипт несколькими строками с одним `message.id` и
  одинаковым `usage` — без отбора по `id` счёт выходит в разы больше.
- ⚠ Транскрипты — десятки МБ, строку рисуют раз в секунду: файл дочитывается с прошлого
  места (`~/.cache/claude-session-tokens.json`), первый прогон медленнее.

## 4. Почему клик идёт через http-сервер

- ⚠⚠ **Терминал JetBrains отдаёт наружу только `http://`.** Своя схема
  (`claude-session://`, зарегистрированная через `xdg-mime`) из него молча не открывается —
  проверено кликом; `xdg-open` той же ссылки срабатывает. Поэтому клик → браузер →
  сервер на петле → tmux.
- Ответ на удачный клик — `204 No Content`; отказ — страница с причиной (сессия не в tmux,
  нет клиента tmux), иначе «клик ничего не сделал» молча. Ссылка есть у каждой строки —
  и у сессий не в tmux: по `sessionId` в ней статусная строка отмечает радиокнопку своего окна (`○` → `◉`)
  (таблица общая на все окна, собирается одна на машину).
- ⚠ Панель tmux знает только `pane_pid` (оболочку), а Claude — её потомок: панель
  ищется подъёмом по родителям в `/proc`.
- ⚠ Снаружи tmux `switch-client` обязан назвать клиента (`-c`): у внешнего процесса
  «текущего» нет. Берётся самый недавно активный.

## 5. Сессия не в tmux — вкладка JetBrains

Сессия не в tmux, но открыта отдельной вкладкой терминала JetBrains — переключение
выбирает эту вкладку. Нужен плагин **Claude Tab Switch** (`claude-shell/jetbrains/claude-tab`,
сборка и установка — `./build.sh`, затем перезапуск IDE):

| Модуль | Что делает |
|--------|-----------|
| `claude_/session/claude_session_transcript.py` | путь к транскрипту сессии |
| `jetbrains_/jetbrains_tab.py` | `GET /api/claude-tab?title=…` во все IDE на портах 63342… — выбрать вкладку |
| `gnome_/gnome_window.py` | вывести окно вперёд по заголовку — через расширение GNOME `claude-window@local` |

- Вкладка ищется **по заголовку**: Claude Code ставит его в шапку вкладки сам. Связь с
  процессом не ищется намеренно — внутренности терминала меняются от версии к версии
  IDE, а вкладки окон инструментов — стабильный интерфейс платформы.
- ⚠ Заголовок сравнивается без значков в начале (`✳`, крутилка); длинный — по началу,
  если вкладка хранит его с `…`. Две сессии с одним заголовком — выберется первая.
- Плагин вдобавок перехватывает открытие ссылок `127.0.0.1:8797/switch/…`: если терминал
  открывает их через платформу IDE, браузер не открывается вовсе.
- ⚠ Без плагина IDE отвечает на адрес 404 — это «вкладки нет», не ошибка.
- `python -m jetbrains_.jetbrains_tab list` — какие вкладки видит плагин в каждой IDE.
- Сессия в tmux, а tmux открыт во вкладке JetBrains: после переключения панели выбирается
  и сама вкладка — её шапка к тому времени уже носит заголовок новой панели
  (`set-titles-string "#T"` в `~/.tmux.conf`). Нет такой вкладки — не отказ.

## 6. Кнопка «+» — новая сессия

Под таблицей — `+ новая сессия`: ссылка `127.0.0.1:8797/new?cwd=<папка проекта окна>`.
Папку вшивает статусная строка каждого окна сама — таблица одна на машину, а проект у
окон разный. Сервер зовёт `jetbrains_tab_new`, плагин открывает вкладку терминала с
командой `bash -ic 'claude; exec bash -i'`: интерактивная оболочка подтягивает PATH
(claude под nvm), после выхода из Claude вкладка остаётся с оболочкой.

- Вкладка открывается в IDE, где открыт проект этой папки (все IDE спрашиваются строго,
  `strict=1`); ни одна не узнала папку — в первой живой IDE, в проекте последнем в фокусе.
- Окно, где нажали «+», само в tmux (статусная строка добавляет `&tmux=<сессия>`, имя —
  `tmux display -p '#S'`): новая сессия — **окно этой сессии tmux** (`tmux_window_new`),
  оно сразу на экране в той же вкладке; радиокнопка возвращает прежнее. Так одна вкладка
  терминала меняет содержимое, а не множит вкладки.
- ⚠ Окно в **фоновую** сессию (`claude --bg`) тоже в tmux, но его статусную строку рисует
  фоновый процесс вне tmux: `$TMUX` там пуст, и «+» открывал новую вкладку IDE. Такая строка
  шлёт `&sid=<сессия>`, а сервер находит сессию tmux по окну, которое на неё смотрит
  (`job` строки, видимое на экране — первым).
- ⚠ Уже запущенную сессию в tmux не перенести: процесс к другому терминалу не пересадить.
  Схема «одна вкладка» — для сессий, начатых через `claude-tmux`.

## 7. Заголовок в таблице и обычный клик

- В колонке имени — **заголовок сессии**, тот же, что в шапке вкладки (`custom-title`,
  иначе `ai-title`); пока модель его не дала — служебное имя (`rhapsodyai-07`). Заголовок
  собирает тот же дочитывающий проход, что и токены: перечитывать транскрипты целиком
  раз в 2 с дорого.
- **Клик без Ctrl** — только внутри tmux: `~/.tmux.conf` вешает на `MouseDown1Pane`
  проверку `#{mouse_hyperlink}`; ссылка сервера сессий — tmux зовёт её `curl`-ом сам, мимо
  браузера; любой другой клик — как по умолчанию. ⚠ Вне tmux Ctrl+клик требует сам
  терминал JetBrains, и ссылка идёт через браузер.

## 8. Колонка «где открыта»

PyCharm, PhpStorm, … — `claude_/session/claude_session_host.py`: предки процесса сессии
(`proc_ps_ancestors`), приложение — по пути исполняемого файла предка
(`/snap/phpstorm/733/bin/phpstorm` → PhpStorm). ⚠ Сессия в tmux — потомок сервера tmux,
не IDE: смотрятся предки **клиента** tmux её сессии (`tmux_clients`).

В таблице приложение — **значком** под логотип JetBrains: две буквы на плашке с переходом
двух фирменных цветов (PyCharm — `PC` зелёный→жёлтый, PhpStorm — `PS` фиолетовый→розовый);
картинок статусная строка не показывает. Не узнано — серое `··`.

## 9. Порядок: сначала своя IDE

Таблица одна на машину, а порядок у окна свой: сессии той же IDE, что и окно, — сверху,
из других IDE — внизу; внутри группы — как было (работает, фон, ждёт).

- Приложение строки спрятано в её ссылке параметрами OSC 8 `host=PyCharm:pid=123` — на
  экран не выходят. Статусная строка окна находит свою строку по `sessionId` **или по
  процессу** (`pid=` — ближайший предок-`claude` самой статусной строки), берёт её `host=`
  и переставляет строки `awk`-ом.
- ⚠⚠ Одного `sessionId` мало: после `/resume` внутри сессии Claude Code отдаёт статусной
  строке id **нового** разговора, а файл сессии `~/.claude/sessions/<pid>.json` хранит
  прежний. Своя строка не находилась — не было ни `◉`, ни перестановки. Процесс же тот же.
- ⚠ Обрезка до 13 строк — **после** перестановки, в статусной строке (таблица собирается
  целиком, `--rows 99`): иначе сессии своей IDE уходили бы в «… ещё».
- Зебра — там же, при выводе: фон всех строк 235 (как плашка имени), каждая вторая после
  своей — 236. ⚠ Цвет — из 256 цветов, не RGB: tmux подменял `48;2;…` ближайшим из палитры,
  и «еле заметный» фон выходил ярко-серым.

## 10. Доля окна подписки — жёлтым

Сколько процентов **5-часового окна** подписки обошлась сессия — тот же счёт, что у
экономии субагентов (`dsh_saving`): взвешенные токены сессии (веса прайса
`DSH_SAVING_WEIGHTS`, **с чтением кэша** ×0.1) / цена 1% окна (`dsh_saving_calibrate`).

- Калибровка — по аккаунту самой сессии (её снимок `rate_limits`): цена процента у
  разных аккаунтов своя.
- ⚠ Оценка, не счёт Anthropic — все оговорки `dsh_saving` в силе. Сессия длиннее окна
  может набрать больше 100%: это её цена в окнах, а не занятость текущего.
- Калибровки ещё нет (окно занято меньше 10%) — серый прочерк.

## 11. Субагенты сессии

Последняя колонка — субагенты DSH, работающие **сейчас** по заданиям этой сессии:
**значки их моторов** (`dsh_motor_badge`: цифра на плашке, у каждого мотора свой цвет).
Те же значки стоят в строке «DSH 4/4: …» перед подписью работы — цифра и цвет связывают
работу с сессией-хозяином; несколько моторов — несколько значков; нет — прочерк.

- Кто работает — `dsh_board_motors_busy` (тот же вызов, что рисует «DSH 4/4»); чья это
  работа — `dsh_wait_owner_of` (кто сейчас ждёт ответа: метку перезаписывает каждый `ask`
  в карточку), иначе `dsh_saving_owner_of` (кто завёл — метка ставится один раз).
- ⚠ Задание, отданное карточке мимо `dsh-board` (окно DeepSeek, прямой вызов хоста), следа
  не оставляет — таблица считает хозяином прежнего.
- ⚠⚠ Хост DSH медлит — опрос ждётся не дольше 3 с (`CLAUDE_SESSION_LIVE_AGENTS_WAIT`,
  фоновая нить), дальше — прошлый удачный ответ из `~/.cache/claude-session-agents.json`
  (до 2 мин). Без потолка запросы к хосту (по 10 с) не укладывались в `timeout 8`
  статусной строки: вставала **вся** таблица — и новое название `t …` в ней не появлялось.
- ⚠ Хост DSH лёг — колонка пустеет у всех, таблица не ломается. Карточка,
  заведённая не из Claude Code (без `CLAUDE_CODE_SESSION_ID`), хозяина не имеет и в
  таблицу не попадает.

## 12. Одна команда — claude-shell

Новая сессия запускается **обёрткой `claude-shell`**, а не голым `claude`: в ней ответы на
вопросы через Telegram. «+» из tmux — окно с `claude-shell`; плагин IDE — вкладка с ним.

`claude-shell`, запущенный человеком из обычного терминала, сам уходит в tmux
(`cli_tmux_enter` в claude-shell → `tmux_session_enter`): сессия `cc` свободна — окном в
ней; занята другим терминалом — своя `cc-2`, `cc-3`, … (иначе зеркало). Не уходит: уже в
tmux, `-p`, роли конвейера, без терминала, `CLAUDE_SHELL_TMUX=0`. `claude-tmux` — второе
имя той же команды.

- ⚠ Сессий tmux теперь бывает несколько (вкладка на сессию): `tmux_focus` берёт клиента,
  который **уже показывает** сессию цели. ⚠⚠ Без такого клиента чужой больше не
  переводится (`steal=False`): переведённая вкладка уносила с экрана свою сессию — та жила
  дальше без вкладки, «скрытой», и казалась закрытой. Вместо этого плагин IDE открывает
  **новую вкладку**, подключённую к сессии цели (`jetbrains_tab_attach`, адрес
  `/api/claude-tab/attach`, в ней `tmux attach -t =<сессия>`). Плагина с этим адресом нет
  (старый отвечает 404) — прежнее поведение, чужая вкладка.
- Клик **внутри tmux** знает свою вкладку: привязка мыши шлёт заголовок
  `X-Tmux-Client: #{client_name}`, и сессия открывается **в этой же вкладке**: её окно
  tmux **переезжает** в сессию tmux вкладки (`move-window`), как окно от «＋». ⚠⚠ Не
  `switch-client` всей вкладки: у неё бывает несколько окон-сессий, и все они оставались
  без экрана («скрыта»). Новая вкладка IDE — только для клика не из tmux.

## 13. «✕» — закрыть сессию

Перед радиокнопкой — тусклый жирный `✖` (`claude_/session/claude_session_close.py`, адрес
`/close/<sessionId>`). **Два клика:** первый взводит (крестик белый на красном), второй в
течение 10 с закрывает; нет второго — взвод гаснет. Крестик вплотную к радиокнопке —
одного промаха не должно хватать. **У своей строки крестика нет:** свою сессию отсюда не
закрыть, она в таблице есть всегда — статусная строка вырезает ссылку `/close/` из своей строки.

- Закрыть — завершить процесс, **не стереть**: транскрипт остаётся, `claude --resume`
  возвращает сессию. В tmux — `tmux_pane_kill` её панели; во вкладке IDE — SIGTERM
  процессу `claude`, claude-shell выходит следом, вкладка остаётся с оболочкой.
- Взвод виден через одну-две секунды — таблицу пересобирает фон статусной строки.
- У **скрытой** строки (§21) свой «✖» (`/close/<id>?hidden=1`, взвод `hidden:<id>`): закрываются
  **все скрытые** копии беседы, видимая копия той же беседы не трогается. ⚠ По одному
  `sessionId` двойник неотличим от видимой — без признака закрылась бы она.

## 14. Вопросы сессий

Сессия стоит и ждёт ввода — в колонке состояния мигающий оранжевый `?` и «вопрос»,
в конце строки причина; такие сессии — первыми. Признак — **статус в файле сессии**:
`status: waiting`, причина в `waitingFor` («input needed»). Claude Code переписывает его
мгновенно, как «работает»/«ждёт»; судя по `input needed` — и на вопрос, и на разрешение.

- ⚠⚠ **Не по транскрипту.** Строку с `AskUserQuestion` Claude Code дописывает в
  транскрипт **вместе с ответом**, а её метка времени — время вопроса. Прогон задним
  числом поэтому «находит» вопрос, а вживую его строки в файле ещё нет: замер — 30 опросов
  подряд `waiting` в файле сессии и ни одного вопроса в транскрипте.

## 15. Субагент ждёт ответа — мигающий «?»

Субагент DSH спросил человека (`ask_user_question`) и стоит — за цифрой его мотора `?` на
оранжевой плашке (`dsh_motor_badge_ask`): и в строке «DSH 4/4: …», и в колонке субагентов.
Признак — в хвосте журнала работающей карточки (`dsh_session_asking`): `tool/call`
`ask_user_question` без `tool/result` с тем же `callId`.

- Мигание делает статусная строка: на нечётных секундах плашка 208 гаснет до 238 (SGR 5
  терминал не умеет). Тем же знаком отмечена и сессия Claude в `waiting` — мигает и она.
- ⚠⚠ Не по проекции `userQuestions.active`: список карточек — кэш до 60 с, и на живой
  карточке, ждущей ответа, вопроса в нём не было. Журнал одной карточки — доли секунды,
  смотрятся только работающие (не больше числа моторов).
- Запросов разрешений у субагентов нет: режим доступа карточек — `danger-full-access`.

## 16. Окно в фоновую сессию

`/resume` фоновой сессии (`kind: bg`) изнутри обычной: Claude Code держит в окне свою
пустую сессию (её `sessionId` — в файле процесса), а работу ведёт фоновая; **статусную
строку окну рисует фоновый процесс** (`claude.exe`, не `claude`) и передаёт ей id фоновой.

- Строка окна берёт название, состояние, токены, долю окна и субагентов фоновой и несёт в
  ссылке `job=<id фоновой>` — по нему статусная строка окна узнаёт себя.
- ⚠ Связь окна с фоновой — **по заголовку** (шапка панели окна = заголовок фоновой, оба
  ставит Claude Code): окно подключено к управляющему процессу фоновых сессий
  (`/tmp/cc-daemon-*/control.sock`), а в какую именно оно смотрит, по сокету не видно.
- ⚠ Свой процесс статусная строка ищет по имени `claude*`: фоновый называется `claude.exe`.

## 17. Название: «Проект: заголовок»

Перед заголовком — проект сессии (имя её папки) своим цветом: «CyberAi: …»,
«RhapsodyAi: …». Свежая сессия без заголовка — «Новая сессия», а не служебное имя
(`cyberai-61`). Колонка названия — 80 знаков, проект — до 32.

## 18. Порядок: свой проект, своя IDE, чужая IDE

В каждом окне сверху — сессии **его проекта**, затем остальные сессии **той же IDE**,
затем — **другой IDE**; внутри группы — по алфавиту «проект: название». Алфавит задаёт
таблица, группы раскладывает статусная строка окна по параметрам ссылки своей строки
(`proj=` — имя папки проекта, `host=` — IDE), не трогая порядок внутри группы. Обрезка до
13 строк — после раскладки.

## 19. Какую вкладку IDE выбрать

- Вкладка ищется по **фактической шапке**: у сессии в tmux — по заголовку её панели сейчас
  (`tmux_pane_title`), иначе — по заголовку сессии; у сессии без заголовка шапка — «Claude
  Code», и среди одинаковых вкладок берётся вкладка **проекта сессии**.
- ⚠ Шапку вкладки сокращают и **посередине** («Площадки для…ажи IT-проектов»). Сопоставление
  — на стороне `jetbrains_tab_select` (по списку вкладок плагина, сравнение по началу и
  концу вокруг «…»), плагину уходит точное имя найденной: правка без пересборки и
  перезапуска IDE.

## 20. Окно другой IDE — вперёд (Wayland)

На Wayland программа не может поднять ни своё окно, ни чужое: `ProjectUtil.focusProjectWindow`
плагина выбирает вкладку, но окно другой IDE остаётся позади; окна IDE — родные Wayland,
`xdotool` их не видит. Поднимает оболочка: расширение GNOME Shell `claude-window@local`
(`claude-shell/gnome/`, D-Bus `Activate(заголовок, класс)`), вызов —
`gnome_/gnome_window.py`. После выбора вкладки сервер поднимает окно с классом `jetbrains`
и именем проекта в заголовке.

- ⚠ Новое расширение оболочка на Wayland видит только после выхода из сеанса и входа
  заново: `claude-shell/gnome/install.sh`, затем `gnome-extensions enable claude-window@local`.
- Нет расширения — вкладка выбирается, окно остаётся на месте; отказа нет.

## 21. Скрытые сессии и моторы без видимого хозяина

Сессия жива в tmux, но ни одна вкладка её не показывает (вкладку закрыли, IDE
перезапустили) — внизу строка «скрыта» (`hidden` в `claude_session_live_list`). Клик
выводит её своей вкладкой (`/switch/<id>?pid=<процесс>` — именно эту копию). Не строка:
скрытый двойник беседы, открытой в другой вкладке, и пустая сессия без заголовка; несколько
скрытых копий одной беседы — одна строка «скрыта ×N». ⚠ Без этих строк после перезапуска
IDE сессии не находили и открывали заново `/resume` — так плодились двойники.


Субагент работает, а его хозяина в таблице нет: сессия **закрыта** (процесса нет — его
субагенты дорабатывают) или **скрыта** (фоновая, в отсоединённом tmux). Такие моторы — внизу
таблицы тусклой строкой «проект: заголовок хозяина (закрыта|скрыта)» со значками
(`claude_session_live_orphans`). Строка **скрытой** — ссылка `/switch/<хозяин>`: клик выводит
сессию на экран своей вкладкой (§12); у закрытой ссылки нет. Название — то же, что было у
строки хозяина (своё `t …` сильнее заголовка транскрипта), иначе сессия внизу выходила под
другим именем и казалась новой. Проект и заголовок — хозяина: проект закрытой сессии —
по каталогу её транскрипта (`claude_session_transcript_cwd`: слаг сличается со слагами
настоящих папок). ⚠ Не папка карточки субагента — она его рабочая (`scratchpad/…/t4`,
копия репо).

## 22. Своё название: `t …`

Сообщение `t Ссылки в статусной строке` в сессии — её название (хук `UserPromptSubmit`
`claude_/hook/claude_hook_session_name.py`, хранилище `claude_session_name`). Хук **не
пускает сообщение к модели** (`decision: block`) — показывает «Название сессии: «…»».
Название сильнее заголовка Claude Code. Строчная `t` и пробел: заглавная «T» — обычное
начало фразы. Ключи — `session_id` из ввода хука и процесс `claude` (после `/resume`
id расходятся).

- Своё название видно и в **шапке вкладки терминала**. Шапку собирает tmux
  (`set-titles-string` в `~/.tmux.conf`) из опции панели `@claude_name`, которую ставит
  сборщик таблицы (`tmux_pane_label`). Значок работы Claude Code (✳/⠂) из его заголовка
  остаётся впереди. ⚠ Сам Claude Code название не узнаёт: заголовок панели (`#T`) остаётся
  его, и окна в фоновую сессию по-прежнему сводятся с ней по нему.

## 23. «Ready» — отработала без взгляда

Сессия работала (`busy`, `shell`, `waiting`), закончила, а на неё не смотрели — в
колонке состояния зелёное «Ready» с мигающей «R» (`claude_session_ready`; терминал JetBrains признак мигания SGR 5 не показывает, поэтому «R» раз в секунду перекрашивает сама статусная строка: ярко-зелёная ↔ тёмно-зелёная (28), чаще строка не перерисовывается). Взгляд — клик по ней в
таблице, промпт человека в ней (тот же хук), её панель tmux на экране (`shown`: активная
панель активного окна в сессии с клиентом). Своё окно «Ready» не пишет — статусная строка
меняет его на «ждёт».
- ⚠ Вкладку IDE не в tmux «на экране» не распознать: такая сессия остаётся «Ready», пока
  по ней не кликнут или не напишут в неё.

- Доля — только расход в **текущем** 5-часовом окне (корзины по 10 минут, `buckets`).

## 24. Токены: за сессию и в текущем окне

Две колонки `вход/выход`: первая — за всю жизнь сессии (терминала), вторая — в **текущем**
5-часовом окне подписки (корзины `buckets_in`/`buckets_out` с `resets_at` − 5 ч). За ними —
доля окна. Окно в сессии не работали — `0/0`.

## 25. Доли разных аккаунтов

На машине бывают сессии **разных аккаунтов** (`/login`), у каждого своё 5-часовое окно:
складывать их доли — как заряды двух батарей, сумма за 100% — не ошибка счёта. Внутри
аккаунта доли сходятся с его занятостью (замер: 29,4% + 4,8% при окне 36%).

Аккаунт строки — метка по сбросу недельного окна (`account`, допуск дрейфа 4 ч), в
ссылке — `acc=`. ⚠ Не сутки: суточный допуск склеил два аккаунта со сбросами в 9 ч
друг от друга (окна 48% и 96%). У калибровки (`DSH_SAVING_ACCOUNT_DRIFT`) он держался
дольше — аккаунт брал цену 1% соседа (×15), и доли в таблице падали до «<1%». Статусная строка окна красит долю
**чужого** аккаунта серым, своего — жёлтым.

## 26. Shift+Enter в tmux — перевод строки

Терминал JetBrains (движок libghostty) шлёт Shift+Enter отдельной клавишей
(`ESC[27;2;13~`), tmux её узнаёт (`S-Enter`), но **приложению в панели отдаёт простой
`\r`**, пока то само не попросит расширенные клавиши. Claude Code не просит — и
Shift+Enter в tmux отправлял сообщение вместо перевода строки. В `~/.tmux.conf`:

```tmux
set -s extended-keys always          # не ждать просьбы приложения
set -s extended-keys-format csi-u    # ESC[13;2u — этот вид Claude Code понимает
```

- ⚠ `always` действует только на **новые** панели: режим клавиатуры — состояние панели,
  заданное при её создании. Уже открытым его включает запрос приложения, и его можно
  подать снаружи — записать в tty панели, tmux прочтёт это как вывод программы:
  `for t in $(tmux list-panes -a -F '#{pane_tty}'); do printf '\033[>4;1m' > $t; done`.
- Что на самом деле приходит от терминала и что уходит в панель — журнал сервера tmux:
  `kill -USR2 <pid сервера>` включает и выключает его (`tmux-server-<pid>.log` в рабочей
  папке сервера); строки `complete key` и `input_key_vt10x`.
- Побочный эффект: в голом bash внутри tmux Shift+Enter печатает `[13;2u`.
- Не сработало — Ctrl+J: перевод строки, который проходит через tmux без настроек.

## 10. Переключатель бэкенда справа от «＋»

`○ Claude ● Qwen4` на строке кнопки — бэкенд этого окна; клик — `GET /backend?pid=<claude>&to=<имя>`.
Сервер передаёт просьбу обёртке claude-shell (`claude_/session/claude_session_backend.py`:
файл `~/.cache/claude-shell-backend/<pid обёртки>` + `SIGUSR1`), та перезапускает `claude`
на новом бэкенде с `--resume` той же беседы. Что значат имена бэкендов — знает только
claude-shell (`src/backend/backend_switch.py`, `.claude/docs/backend.md` там).

- Рисуется, только если в окружении строки есть `CLAUDE_SHELL_BACKEND` — её ставит
  claude-shell ручной сессии; у голого `claude` и у ролей конвейера переключателя нет.
- ⚠⚠ Сигнал — только обёртке, у чьего `claude` эта метка в окружении: обёртку без
  обработчика `SIGUSR1` по умолчанию убивает вместе с сессией.
- Ширина для выравнивания вправо — `stty size` терминала процесса `claude`: stdout
  статусной строки не терминал.
