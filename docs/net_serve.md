# Раздать каталог в фоне и убрать за собой

> «Подними сервер для проверки» в каждой сессии кончается одинаково: процесс
> висит в фоне, порт занят, следующая попытка падает `EADDRINUSE`, а кто его
> занял — уже никто не помнит. `net_serve` делает это одним вызовом и одним
> вызовом же убирает: состояние на диске, процесс — не чужой, а свой по порту.

## 1. Сейчас

```python
from net_.net_serve import net_serve_up, net_serve_down, net_serve_status

got = net_serve_up('data/uvicorn/public')      # {'url': 'http://127.0.0.1:41213/', …}
…                                              # curl, браузер, web_shot — что угодно
net_serve_down(port=got['port'])               # порт свободен, состояние удалено
```

Занятый тем же каталогом порт — не ошибка: второй `net_serve_up` вернёт тот же
`url` с `reused: True`. Каталог опознаётся по абсолютному пути, порт берётся
свободный сам (или свой `--port`), привязка — только 127.0.0.1.

```bash
PYTHONPATH=. python -m net_.net_serve up .claude/docs --port 8080
PYTHONPATH=. python -m net_.net_serve status
PYTHONPATH=. python -m net_.net_serve down --port 8080
```

## 2. Как узнаётся «свой» процесс

Состояние ложится в `tmp/net_serve-<sha1 каталога>.json`: pid, порт, url. Его
может не быть (убили -9, пережили перезагрузку) — тогда `down` идёт через
`proc_ps_kill(port=…)`: мишень — процесс, держащий этот порт, из которого
вычитаются свои предки; бьёт только по тем, в чьей командной строке светится
метка `net_.net_serve`. Чужой сервис на том же порту не пострадает — метки у
него нет.

## Грабли

1. **`down` без селектора ничего не трогает**: ни каталога, ни порта — вернётся
   `error`, а не «убьём всё подряд».
2. **состояние — подсказка, а не истина**: процесс переживает удаление json, а
   json не переживает `-9`; путь сверки — порт (`net_port_wait(up=False)`).
3. **`SimpleHTTPRequestHandler` — раздача, а не приложение**: ни PHP, ни
   шаблонов, ни CORS; для SSR-страниц есть `uvicorn_dev`, здесь задача — статика
   под `web_shot`/`curl`.
