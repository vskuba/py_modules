# Скролл-кадры и анимация: дельта, полотно, «шевелится ли кадр», монтаж

> Смещение между кадрами одного скролла ищется по high-pass профилям строк
> (`image_frames_delta`), полотно склеивается с кроссфейдом и выбором
> позднего кадра (`image_frames_stitch`), факт анимации — знаковым сдвигом по
> полосам (`image_frames_drift`), скорость бегущей строки — корреляцией
> колоночных профилей полосы (`image_frames_shift`), визуальная сверка десятка
> кропов — монтажом (`image_frames_grid`).
> Инструмент — `py_modules/image_` (модуль `image_frames`), CLI:
> `python -m image_.image_frames`. Управление самим телефоном —
> `mobile_control.md`, серия кадров с метками времени — `mobile_device.md`
> (`adb_burst`).

## 1. Дельта скролла: high-pass, потому что фон привязан к экрану

`image_frames_delta(a, b)` возвращает, на сколько строк контент кадра `b`
уехал относительно `a`. Сравниваются профили яркости строк минус их
скользящее среднее (окно 151): фон-градиент приклеен к экрану и между
кадрами разный, а содержимое на верной дельте совпадает — прямое сравнение
профилей сплывает на градиент.

- **Полоса сравнения — от 1/6 высоты.** Выше лежит прилипающий заголовок:
  он не ездит вместе с контентом и затягивает минимум на нулевую дельту.
- **Поиск в два такта:** грубо шагом 4, затем поштучно ±6 вокруг лучшего —
  на цельноэкранном кадре полный перебор по пикселю ничего не добавляет,
  а стоит в сотни раз дороже.

## 2. Полотно: доклеивать дельту, спорное — из позднего кадра

`image_frames_stitch(paths, out, crop, start_row, blend, prefer_last)` —
из серии снимков одного скролла одно полотно; у каждого кадра отрезается
окно `crop` (панели статуса/вкладок в полотно не входят), доклеиваются
только последние `dy` строк следующего кадра.

- **Стык — косая альфа на `blend` строк** (умолчание 12): строки содержимого
  на перекрытии и так совпадают, а ступенька градиента фона растягивается
  с одной строки на двенадцать и с экрана уходит.
- **`blend` не увеличивать «для гладкости», когда между кадрами контент
  перестроился.** Приложение может перетасовать свои промо-плитки между
  снимками — длинный кроссфейд на разных плитках даёт двоение текста;
  короткий шов попадает в зазор между рядами и остаётся едва заметной
  сменой оттенка обоев.
- **`prefer_last` — против тостов.** Системный тост («Помилка з'єднання»)
  висит поверх содержимого и прячет под собой строки; следующий снимок
  показывает те же строки чистыми — перекрытие берётся из позднего кадра.
  Но только ниже `start_row`: строки выше прилипающего заголовка в позднем
  кадре — это сам заголовок, а не уехавший контент.

## 3. Drift: анимируется ли кадр и куда плывёт

`image_frames_drift(a, b, bands)` по каждой полосе отдаёт **знаковое**
среднее смещение каналов (b − a), |Δ| в среднем и максимум. Это не вердикт
«тон совпал» (`image_diff_zones` из `image_tooling.md`) — это направление и
величина: «фон уходит в синий, карточка стоит».

- **Живой фон проверять двумя кадрами без перезагрузки.** Снимок через
  `adb_cdp capture` навитигирует на страницу и сбрасывает фазу CSS-анимации
  — два «разных» кадра окажутся одним состоянием. Дельту фазы ловят голым
  `screencap` с интервалом. Эталонная проверка: обои за 8 с — |Δ| ~30 при
  знаке по каналам, стекло карточки — ровно 0.0; любой ненулевой drift
  «статичного» слоя означает, что он сдвинулся вместе со страницей.
- **Полосы задавать по смыслу разметки**, не брать кадр целиком: среднее по
  всему кадру усредняет «светлеет верх» и «синеет низ» почти в ноль.

## 4. Shift: на сколько пикселей уехало содержимое полосы

`image_frames_shift(a, b, band, search, dt)` — сдвиг содержимого полосы
(бегущая строка, карусель) по колонкам: `dx`/`dy` в пикселях, корреляция и,
при переданном `dt`, скорость px/s. Считается по **профилям** (сумма яркости
колонок/строк полосы), не по пикселям: текст едет на субпиксель и каждый
кадр дорисовывается с новым AA — пиксельная корреляция тонкого текста поверх
цветного градиента на живом тикере не различала сдвиги (корреляция ~0.37 при
верных 175 px), профильный пик острый и не врёт (0.91–1.00).

- **Полоса — по разметке, не треть кадра**: статичный контент вокруг
  разбавляет профиль.
- **`dt` — из меток кадров, не из «интервал × номер»**: `screencap` сам стоит
  до секунды, серийные метки пишет `adb_burst_capture`.
- **Скорость — цепочкой пар и `сумма(dx)/сумма(Δt)`**: короткая пара
  попадает в зависший `screencap` (тот же байт-буфер → честные `dx=0`,
  корреляция 1.00 при стоящем контенте — не путать с покоем), одиночная пара
  на длинном шаге даёт алиасинг. На живом тикере 11 пар по ~1.9 с сошлись в
  средние 83.7 px/s; первая же пара «на глаз» по зависшей серии наврала втрое.
- **Корреляция < 0.7** — сдвиг не влез в `--search` или пик алиасинга.

## 5. Монтаж: десять кропов одним взглядом

`image_frames_grid(items, out, cols, scale)` — плитки (кадр или его box)
в одну картинку с тёмной подложкой между ними: шов между разными кадрами
не должен выглядеть продолжением картинки. Так читаются строки точек со
всех страниц, низы слайдов, ряды карточек — глазами десять отдельных файлов
не сверить, а одному взгляду на montage — можно.

## 6. Цикл: за какой период кадр возвращается к первому

`image_frames_cycle(paths, interval=None, tol=2.0, rect=None)` — серия кадров,
снятых с равным шагом; период — первый кадр после нулевого, чей средний по
каналам совпал с нулевым в допуске `tol`: «дыхание» обоев, webp-луп, возврат
экрана после тоста. Возвращает `period_frames` (и `period_s`, если задан
шаг `interval`) плюс ряд средних по кадрам — его видно глазами.

Среднее по всему окну вместо попиксельного сравнения — осознанный компромисс:
вернувшийся к началу кадр совпадает и в среднем, а среднее не сходит с ума от
шума сжатия живых скриншотов. Отсюда два честных крайних случая:

- `period_frames == 1` — соседние кадры уже равны: экран стоит или шаг
  выборки мельче хода анимации (между двумя снимками шевеление не видно —
  период неотличим от шага);
- `period_frames is None` — за эту серию повтор не наступил, период длиннее
  серии; это не «цикла нет». Увеличьте серию или уменьшите `tol`.

`rect` вырезает движущиеся оверлеи (часы в статус-баре, счётчик, бегунок
загрузки) — они портят среднее и прячут фактический возврат фона; окно берут
по неподвижной зоне контента.

## CLI

```bash
python -m image_.image_frames delta shot1.png shot2.png
python -m image_.image_frames stitch a.jpg b.jpg c.jpg --out tall.jpg \
    --crop 91,2077 --start-row 180 --prefer-last
python -m image_.image_frames drift t0.png t8.png \
    --band 'wallpaper:0,100,1080,330' --band 'стекло:100,420,980,1620'
python -m image_.image_frames shift tick0.png tick3.png \
    --band 86,1297,992,1362 --dt 2.9          # скорость: dx / dt
python -m image_.image_frames grid doc.jpg@0,2077,1080,2400 doc2.jpg@0,2077,1080,2400 \
    --out bottoms.png --cols 3 --scale 0.4
python -m image_.image_frames cycle f0.png f1.png f2.png f3.png f4.png \
    --interval 3.57 --rect 0,420,1080,1620     # период цикла по серии, секунды
```
